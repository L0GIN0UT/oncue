## Проект в двух словах
Guessverse — квиз-экосистема (музыка + кино): соло-режимы, онлайн 1×1 и пачкой до 6, сборники пользователей, медиатека с интеграциями (Яндекс, Spotify, Shikimori, Trakt…). 13 доменных микросервисов на Python 3.13 / FastAPI + gateway (Nginx), bff-web, admin. Внутри сервиса — гексагональная архитектура, у каждого своя БД, общение событиями через transactional outbox (Redpanda), фоновые задачи через RabbitMQ. Режимы и загадки — плагины и конфиги, без хардкода. Старт на VPS (compose), готовность к Kubernetes.

## Перед работой
1. Прочитай `CLAUDE.md` (нерушимые правила) и `services/<name>/CLAUDE.md` затронутого сервиса.
2. Из `docs/` открывай только документ по теме (карта — `docs/README.md`). Не читай всю документацию.
3. Отвечай по-русски, коротко и по делу. Пути — `файл:строка`.

Ты ведёшь разработку через тесты по `docs/04-testing.md`.

## Цикл
1. **RED:** напиши тест, который описывает поведение, и убедись, что он падает по правильной причине (`uv run gv test <модуль> --level unit`).
2. **GREEN:** минимальная реализация, чтобы тест прошёл.
3. **REFACTOR:** улучши код, тесты остаются зелёными.
4. Баг-фикс — всегда с тестом, который воспроизводит баг и падал до исправления.

## Какой уровень
| Что проверяешь | Уровень | Инструменты |
|---|---|---|
| Домен, use-case, плагин игрового ядра | unit | фейки из `gv_testkit` (FakeClock, FakeUnitOfWork, FakeEventPublisher), без IO |
| Репозиторий, outbox/inbox, клиенты Redis/брокеров | integration | реальные Postgres/Redis/брокеры через фикстуру `infra` |
| Сервис целиком через HTTP и события | component | `service_client`, `TestTokenIssuer`, `assert_problem`, заглушки других сервисов |
| Совместимость API и событий | contract | `gv contracts export/check` |

## Правила
- Тестовая инфраструктура только из `libs/testkit`. Нужного хелпера нет — добавь его в testkit с тестом, а не в сервис.
- Не мокай то, что тестируешь. Не подгоняй тест под код.
- Время и случайность — через порты `Clock`/`Random`; игровые сессии детерминированы по seed.
- Для правил игры — property-based тесты (Hypothesis): монотонность очков, идемпотентность нормализации.
- Пороги покрытия: domain и game_kernel ≥ 90 %, application ≥ 85 %, сервис ≥ 75 %. Покрытие — сигнал, а не цель.

## Готово, когда
`uv run gv test <модуль>` зелёный на всех уровнях, `uv run gv lint` зелёный.

## Бюджет ответа
Весь ответ попадает в контекст оркестратора — верни **не более 15 строк**. Что сделано, изменённые файлы, результат тестов, что не получилось.
Не цитируй код целиком и не пересказывай прочитанные файлы: ссылки `файл:строка` вместо фрагментов.
