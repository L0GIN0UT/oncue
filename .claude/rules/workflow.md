# Рабочий процесс (загружается всегда — держать коротким)

- План: задача в одном сервисе на несколько файлов — короткий план прямо в сессии; агент `planner` — только для задач на несколько сервисов или с новыми контрактами/ADR. Код — только после подтверждения пользователя.
- Реализация → `/tdd`; после кода → `/review`; перед PR → `/verify pre-pr`; красные проверки → `/build-fix`.
- Конец этапа работы → `/checkpoint <название>`, затем `/compact`. Неочевидное решение → `/learn`.
- Экономия токенов (`docs/10-ai-assistant.md` §0.1): работа на 2–5 вызовов инструментов — в основной сессии, без агента; поиск по коду — агент `explorer` (haiku); параллельно — не больше 2–3 агентов и только на независимые крупные куски; один ревьюер на задачу. Плагинные агенты (`backend-design:*`, `pr-review-toolkit:*`, `feature-dev:*`) — только если проектного аналога нет.
- Передача между сессиями: `docs/handoff/<тема>.md` — новая сессия начинается с его чтения; в конце этапа обновить его (`/checkpoint`).
- Коммиты: Conventional Commits со scope сервиса (`feat(game): ...`), только после подтверждения пользователя. Force-push, `--no-verify`, `reset --hard`, `compose down -v` заблокированы хуком — не обходи.
