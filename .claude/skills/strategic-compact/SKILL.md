# Осознанное сжатие контекста

Автосжатие срабатывает в случайный момент — часто посреди задачи — и теряет детали. Сжимаем сами на границах этапов.

## Когда сжимать
- **После планирования**, когда план утверждён: исследование больше не нужно, план — нужен.
- **После отладки**, когда причина найдена и исправлена.
- **После завершения этапа** работы (фича, сервис, ревью) — перед следующим.
- Хук `gv hook compact` подсказывает после 50 вызовов Edit/Write и затем каждые 25 — это сигнал «проверь», а не команда.

## Когда НЕ сжимать
Посреди реализации, когда в контексте связанные изменения нескольких файлов, ещё не закоммиченные и не проверенные.

## Как
1. `/checkpoint <этап>` — проверка + заметка сессии («Сделано / В процессе / Для следующей сессии»).
2. `/compact` с подсказкой, что сохранить: `/compact сохрани: план из N шагов, сделаны 1–3, дальше шаг 4 в services/game; решение — ...`.
3. После сжатия опорные точки: корневой `CLAUDE.md`, `services/<name>/CLAUDE.md`, заметка в `.claude/sessions/` (её же хук покажет в начале новой сессии).

## Экономия токенов в целом
- Читать только документ по теме (`docs/README.md` — карта), а не весь `docs/`.
- Широкий поиск по коду — через агента-исследователя, который возвращает вывод, а не дамп файлов.
- Правила в `.claude/rules/` подгружаются только для затронутых путей — не копировать их в промпты.
