# Guessverse: conventions

Always start by reading the repo root `CLAUDE.md`, then `services/<name>/CLAUDE.md` for the service you touch. Open only the doc for the current topic (map: `docs/README.md`). Never read all of `docs/`. Path-scoped rules in `.claude/rules/` load automatically for matching files.

## Architecture invariants (never break)
- 13 domain services (identity, catalog, media-pipeline, game, match, rating, collections, library, integrations, progression, payments, social, notifications) + gateway (Nginx), bff-web, admin (Django from stage 1).
- Service composition lives in `infra/services.toml`. Derived files (compose, nginx `infra/nginx/generated/*`, prometheus, `.importlinter`, `.env.example`, DB init script) are generated by `gv gen` and never edited by hand (a hook blocks it); CI runs `gv gen --check`.
- Database per service. Never read or write another service's DB. Only admin reads read-replicas, and mutates via `/admin/v1` APIs.
- Cross-service: domain events via Redpanda with transactional outbox; consumers idempotent via inbox (`event_id`). Background jobs via RabbitMQ. No sync chains A->B->C; keep local projections instead.
- Event envelope: event_id (uuid7), event_type `<service>.<Event>`, event_version, occurred_at, producer, aggregate_type, aggregate_id (partition key), correlation_id, causation_id, payload. Schemas in `contracts/events/<service>/<Event>.v<N>.json` (hand-written); envelope in `contracts/events/envelope.v1.json` (generated). Breaking change = new major version published in parallel.
- API: `/v1` public, `/internal/v1`, `/admin/v1`; RFC 9457 Problem Details with machine `code`; cursor pagination; `Idempotency-Key` on mutations; money as integer minor units.
- OpenAPI snapshot `contracts/openapi/*.json` is generated: after changing routes run `gv contracts export`; `gv contracts check --base origin/main` blocks breaking changes.

## Service layout (hexagonal)
```
services/<name>/src/<name>_service/
  domain/          # pure Python: entities, value objects, domain events, DomainError
  application/     # commands/, queries/ (one use-case per class), ports/, dto.py
  infrastructure/  # db/ (SQLAlchemy tables, alembic migrations), messaging/ (event handlers), clients/
  api/public|internal|admin/   # thin FastAPI routers
  main.py          # composition root: ServiceDefinition (routers, tables, handlers, topics)
  settings.py      # pydantic-settings, env only (GV_ prefix)
tests/unit|integration|component|contract
```
- Processes (api, relay, consumer, worker, all, migrate), health, metrics, graceful shutdown come from `libs/service` (`gv_service.main(DEFINITION)`). No DI framework (ADR 0011): build dependencies explicitly in router/handler factories that receive `Infrastructure`.
- Dependency direction: api/infrastructure/main -> application -> domain. Enforced by import-linter. Time and randomness via `Clock`/`Random` ports.
- New service: `gv new-service <name> --description ... [--public PREFIX] [--no-database]` (see guessverse-new-service).

## Shared libs (use, don't reimplement)
`gv_core` (errors, uuid7, clock, context, pagination, AggregateRoot), `gv_db` (engine with hide_parameters, ServiceTables with outbox/inbox, SqlAlchemyUnitOfWork, migrations), `gv_messaging` (EventEnvelope, OutboxWriter/OutboxRelay, Inbox, EventProcessor, RetryPolicy, Kafka and Rabbit adapters), `gv_auth` (JwtVerifier, Principal, require_perm), `gv_observability` (logging with recursive secret masking, metrics, tracing), `gv_service`, `gv_flags`, `gv_testkit`.

## Game engine
- Rules live once in `libs/game_kernel` (stage 2), used by game (solo) and match (online).
- Mode = versioned `ModeConfig` (domain, source, clue, answer, scoring, session, rewards). New mode = config, not code.
- New clue type = new `ClueType` plugin + registry entry + asset handler in media-pipeline. Never add `if type == ...` branches to the core.
- Server is the source of truth; assets are served per level via one-time signed URLs.

## Code rules
- Python 3.13, FastAPI, SQLAlchemy 2 async, Pydantic v2, uv workspace. ruff + mypy --strict (`gv lint` runs everything CI runs). A PostToolUse hook runs ruff fix+format after every edit.
- Docstrings (Google style, Russian) on public domain/application classes, ports, plugins, libs; they feed the mkdocs reference (`mkdocs build --strict` in CI). Comments explain *why* only; link ADRs.
- Shared code only in `libs/*`. Never share domain or ORM models between services.
- Migrations backward compatible (expand -> migrate -> contract).
- Config via env only; stateless; health/live, health/ready, metrics; graceful SIGTERM. Settings default to production (safe default); local/test set GV_ENVIRONMENT explicitly.
- Never log secrets or PII; logging masks sensitive keys recursively, but don't format secrets into message strings.

## Tests
- Use `libs/testkit` (fakes, TestTokenIssuer, service_client, assert_problem, events helpers, InfraProvider); never hand-roll test infrastructure in a service.
- Levels: unit (no IO) / integration (real Postgres/Redis/brokers via GV_TEST_* env or testcontainers) / component (service + stubs) / contract.
- Locally missing infra skips integration tests; with CI=true it fails them.
- Every change has tests; every bug fix has a reproducing test. Run `gv test <service|libs/x> [--level L]`, `gv test --changed`.

## Workflow (project commands and agents in `.claude/`)
`/plan` (planner) → `/tdd` (tdd-guide) → `/review` (code-reviewer + security-reviewer for sensitive zones) → `/verify pre-pr` → `/checkpoint` → `/compact`. Red checks → `/build-fix`. See `docs/10-ai-assistant.md`.

## Security gates (see docs/10-ai-assistant.md section 3)
- Every diff: backend-design:security-discipline.
- Endpoints or permissions: auth-and-authorization + security-reviewer agent.
- identity, payments, progression ledger, entitlements: additionally finecomb and idempotency-and-side-effects; flag for human review.
- Gateway blocks /internal, /admin, /health, /metrics, /docs, /openapi.json (also under /v1/); keep internal/admin routes under their own prefixes anyway.
- Billing stays disabled (`billing.enabled=false`, plan `free_all`) unless the owner explicitly decides otherwise.

## Language
Docs, docstrings, comments in Russian; identifiers in English; Conventional Commits with service scope.
