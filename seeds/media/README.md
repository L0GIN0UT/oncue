# Синтетические исходники ассетов

Тоны для треков и абстрактные кадры для фильмов из `seeds/catalog` — для local и e2e
(план этапа 2, §5 «Сиды»). Прав третьих лиц нет (ADR 0014): звук и картинка генерируются
из ключа единицы каталога, поэтому бинарные файлы в git не хранятся.

```bash
uv run python seeds/media/generate.py          # → seeds/media/out/
```

Генератор читает все `seeds/catalog/*.jsonl`. Получится (имя — ключ строки каталога с `-`
вместо `:`):

| Файл | Единица | Вид исходника (`kind`) | Загадки |
|---|---|---|---|
| `track-<slug>.m4a` (50 с, AAC) | трек | `audio` | `audio_intro`, `audio_reverse` (`start_s` 30) |
| `film-<slug>.jpg` (1280×720) | фильм | `frame` | `frame_progressive`, ревил `audio_blackout` |
| `film-<slug>-{1..6}.jpg` | фильм | `frame`, `position` = номер | `frame_sequence` (1 — самый сложный) |
| `soundtrack-<slug>.m4a` (50 с) | фильм | `soundtrack` | `soundtrack` |
| `clip-<slug>.m4a` (50 с) | фильм | `audio_clip` | `audio_blackout` |

Тексты `description`/`emoji` — не файлы: они приходят из catalog (`clue_texts` строки
импорта, одобряются сразу при `GV_CATALOG__SEED_TEXTS_APPROVED=true`, только local/ci).

## Засев одной командой (local/ci)

```bash
gv dev up infra && gv dev up services          # стек с dev-оверлеем (порты 127.0.0.1:81xx)
export GV_BOOTSTRAP_ADMIN__LOGIN=... GV_BOOTSTRAP_ADMIN__PASSWORD=... GV_SERVICE_SECRET_ADMIN=...  # из infra/compose/.env
uv run gv dev seed [--date YYYY-MM-DD]
```

`gv dev seed` (`tools/gv/src/gv_cli/seed.py`) импортирует все файлы каталога, генерирует
исходники и загружает на фильм шесть кадров (`position` 1..6), саундтрек и звук фильма, на
трек — тон (`origin=seed`); ждёт готовности всех наборов единицы и статических профилей,
играбельного пула каждого режима в проекции game и перегенерирует наборы всех плановых
режимов на текущий период: дейлики — на день, `film.bracket.weekly` — на неделю (с
понедельника), с проверкой пригодности (у сетки — тема и 32 единицы). Повторный запуск
безопасен (стабильные `Idempotency-Key`). Основной кадр `film-<slug>.jpg` сидер не грузит:
`frame_progressive` берёт самый свежий кадр вида `frame`.

## Порядок загрузки вручную (local)

1. `gv dev up infra`, `gv dev up services`.
2. Импорт каталога через admin: `POST /admin/v1/imports {"source": "file", "file_id": "tracks.jsonl", "reason": "сиды"}`
   и то же для `films.jsonl` (см. `seeds/catalog/README.md`). catalog публикует `MediaItemCreated`.
3. Для каждой единицы найти `media_item_id` в админке (карточка единицы) и загрузить файлы:
   `POST /admin/v1/sources` (media-pipeline, multipart: `media_item_id`, `kind` из таблицы
   выше, `position` для кадров последовательности, `reason`, `file`; заголовок
   `Idempotency-Key`). `origin`, `source_url`, `license_note` необязательны (ADR 0072).
4. media-pipeline генерирует наборы по профилям `default` и публикует `AssetsReady`;
   game заполняет проекцию `clue_assets`.
5. game публикует сиды режимов (`seeds/game/modes`, только local/ci, `GV_GAME__BOOTSTRAP_MODES_DIR`)
   и создаёт наборы дня периодической задачей `game.daily.schedule`. Если пул ещё пуст,
   наборы получают статус `failed` и пересоздаются на следующем запуске задачи
   (`GV_GAME__SCHEDULE_INTERVAL_S`) или при первом старте дейлика.

Минимум пула для публикации конфига — `source.params.pool.min_playable` в сидах режимов
(10 для дейликов, 20 для случайных): загрузите исходники хотя бы для такого числа единиц.

## Реальные медиа (только local)

Дополнение к синтетике, ничего не удаляет. Файлы лежат **вне репозитория** (ADR 0014), по
умолчанию в `C:/gv-media`. Выгрузки возобновляемые: повторный запуск не качает готовое заново.

```bash
uv run python seeds/media/fetch_tmdb_popular.py --total 10000   # кино TMDB → tmdb/ (ключ TMDB_KEY в .keys.env)
uv run python seeds/media/fetch_deezer.py --count 10000         # треки Deezer: клипы 30 с + обложки → deezer/
uv run gv dev seed-real --real-dir C:/gv-media --import-dir <каталог seeds/catalog стенда> \
    --ffmpeg <путь к ffmpeg>                   # переменные админа - как у `gv dev seed`
```

Источник треков для стенда — Deezer.

### Параметры `gv dev seed-real`

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--real-dir` | `C:/gv-media` (`GV_REAL_MEDIA_DIR`) | Где лежат `tmdb/` и `deezer/` |
| `--import-dir` | каталог по умолчанию | Куда писать `real-films.jsonl` и `real-tracks.jsonl` (видит catalog) |
| `--ffmpeg` | `GV_FFMPEG` или PATH | Путь к ffmpeg |
| `--ffmpeg-jobs` | `min(8, ядер)` | Потоков перекодирования клипов |
| `--package-units` | 100 | Единиц в одном пакете (при 20 000 единиц - около 200 пакетов) |
| `--collection-size` | 50 | Размер сборника (самые популярные) |
| `--min-collection-size` | 20 | Минимум единиц для сборника жанра, категории или десятилетия |
| `--stall-timeout-min` | 30 | Минут без единого нового готового набора ассетов, после которых засев останавливается |
| `--tracks-limit` | нет | Ограничить число треков (отладка) |
| `--without-synthetic` | выкл | Чистый стенд только на реальных данных (см. ниже) |
| `--date` | сегодня | День плановых наборов |

Пример на 10 000 треков и 10 000 тайтлов кино:

```bash
uv run gv dev seed-real --without-synthetic --real-dir C:/gv-media --import-dir <каталог seeds/catalog стенда> \
    --ffmpeg <путь к ffmpeg> --ffmpeg-jobs 8 --package-units 100 --collection-size 50 --stall-timeout-min 30
```

### Что делает `gv dev seed-real` (`tools/gv/src/gv_cli/seed_real.py`)

- **Источники** в `<real-dir>`:
  - `tmdb/catalog-films.jsonl` - кино всех категорий (**Фильмы, Сериалы, Мультфильмы, Аниме**).
    Файлы тайтла лежат по полю `folder` (`Аниме/movie-129/`, `Сериалы/tv-1399/`): `poster.jpg`
    и `frame-1..6.jpg`. Ключ сериала - `film:tmdb-tv-<id>`. Тайтл без постера или без шести кадров
    отбрасывается.
  - `deezer/catalog-tracks.jsonl` + `deezer/clips/<id>.mp3` + `deezer/covers/<album_id>.jpg`.
    Трек без клипа отбрасывается, без файла обложки идёт без неё (`artwork` ревила `null`).
    Нет папки - источник пропускается.
- **Каталог.** Пишет `real-films.jsonl` и `real-tracks.jsonl` в `--import-dir` (в git не попадают) и
  импортирует их. `overview` уходит в `clue_texts.plot_raw` (загадка «описание»), `listens` трека
  (популярность из `rank` Deezer) - в `metrics.popularity`. Контракт каталога не менялся, поэтому
  клиент приводит данные к нему: роль `creator` (создатель сериала) → `director`; kind у сериалов и
  аниме - `film`; внешний id сериала передаётся как `tmdb: "tv-<id>"`, чтобы не совпасть с id
  фильма (catalog объединяет единицы по внешнему id); `tmdb_type`, `seasons`, `category`,
  `folder`, `poster`, `frames`, `audio`, `cover`, `album`, `origin` в импорт не попадают.
- **Аудио.** Клипы перекодируются в `<real-dir>/seedpack/audio/*.m4a` в `--ffmpeg-jobs` потоков:
  ffmpeg зацикливает 30 секунд до 50 с (профили читают `start_s` 30 у реверса и до 15 с уровня), как
  у синтетики. Кэш - готовый файл: кодирование идёт во временный `*.part.m4a` и переименовывается
  по завершении, прерванный запуск не оставляет битых файлов. Клип, который не перекодировался,
  пропускается и попадает в сводку.
- **Пакеты.** Недостающие файлы собираются в zip с `manifest.json` (`ZIP_STORED`: медиа уже
  сжато), уходят `POST /admin/v1/packages`; клиент ждёт статус `GET /admin/v1/packages/{id}`. В
  логе прогресс «пакет 12/150». На трек: `audio` и `cover`; на кино: шесть `frame` (`position`
  1..6) и `poster`. Уже загруженное пропускается. Происхождение трека: `origin=upload`, страница
  трека - `source_url`; лицензия у Deezer пустая, и `license_note` не передаётся (ADR 0072). Приём
  файлов и проверки - на стороне media-pipeline (`services/media_pipeline/CLAUDE.md`).
- **Ожидание наборов ассетов.** Без жёсткого таймаута на всё сразу: клиент проходит по
  ожидающим единицам, пишет «наборы готовы N/M, проваленных K» и останавливается, только если
  `--stall-timeout-min` минут не появилось ни одного нового готового (или проваленного) набора.
- **Битые единицы не роняют засев.** Набор в статусе `failed` (например `source.undecodable`),
  пакет, отвергнутый media-pipeline, и клип, не прошедший ffmpeg, пропускаются: единица не
  попадает в сборники и пулы, ключи печатаются в сводке (первые 50) и пишутся целиком в
  `<real-dir>/seedpack/broken-units.txt`. Проваленные наборы единиц, которых нет в текущем списке
  засева (прошлые запуски), игнорируются. Если подряд отвергнуто три пакета - засев останавливается
  (похоже на сбой стенда, а не на битые файлы).
- **Повторный запуск** безопасен и возобновляем: ключи идемпотентности стабильны, уже загруженные
  исходники пропускаются, остальное достраивается; битые единицы пробуются снова.
- **Сборники** (размер `--collection-size`, внутри - по популярности: прослушивания у треков,
  `popularity` TMDB у кино, при равенстве - по рейтингу):
  - музыка: «Топ треков» (`real-music-top`) и по сборнику на каждый жанр треков, в котором не
    меньше `--min-collection-size` треков (`real-music-<жанр>`; названия на русском из
    `GENRE_TITLES`);
  - кино: «Топ по популярности» (`real-film-top`) по всему кино; для каждой категории топ
    (`real-film-<категория>-top`) и сборники по жанрам внутри категории
    (`real-film-<категория>-<жанр>`); сборники по десятилетиям (`real-film-1990s`). Ключи - ASCII
    (транслитерация: `real-film-serialy-top`).
  Сборник меньше минимума не создаётся. Режимы кино одинаковы для всех категорий: у сериалов и
  аниме тот же набор кадров и афиша; режим, которому не хватает данных, не получает набор и
  попадает в сводку, а не падает.
- Обновляет наборы периода (дейлики строятся из загруженных реальных единиц).

### Чистый стенд только на реальных данных (`--without-synthetic`)

```bash
uv run gv dev seed-real --without-synthetic --real-dir C:/gv-media --import-dir <каталог seeds/catalog стенда> \
    --ffmpeg <путь к ffmpeg>                   # без предварительного `gv dev seed`
```

По умолчанию флаг выключен: `seed-real` дополняет `gv dev seed`, как описано выше. С флагом
команда самодостаточна:

- **Пропускается:** синтетические файлы каталога и их исходники (генератор не запускается),
  кураторские сборники `seeds/collections/*.yaml` (в том числе featured) и синтетические дейлики.
- **Остаётся:** конфиги режимов, уровни и рейтинг (их публикуют сервисы при старте), реальные
  единицы и сборники `real-*`, а также базовые шаги `gv dev seed`: ожидание онлайн-шаблонов,
  предметы, паки и товар «своя аватарка», события и конфиг social. Промокоды и аккаунты засев
  не создаёт (игроков регистрируют сами).
- **Рекомендуемое:** `featured` получают «Топ по популярности» (кино, порядок 1), «Топ треков»
  (музыка, порядок 2) и топ каждой категории кино (порядки с 3).
- **Порядок:** загрузка исходников → ожидание профилей → пулы режимов → сборники → лобби-сборники →
  **наборы периода** (дейлики строятся из уже загруженных реальных единиц) → progression, события, social.
- **Режим без материала** (нет единиц домена, мало играбельных, не опубликован, непригодный набор
  периода, недоступный сборник) не роняет засев: набор для него не создаётся, а режим с причиной
  попадает в итоговую сводку `seed-real: пропущено <ключ>: <причина>`.

**Картинка ответа (`artwork`, ADR 0073).** Обложка и постер дают набор `artwork` (600×600 у
трека из `cover`, 600×900 у фильма из `poster`, а без постера из кадра), его ждёт тот же шаг
«наборы ассетов готовы». Если файла обложки у трека нет, `Reveal.artwork` остаётся `null`
(заглушку рисует фронтенд).

## Правка профиля ассетов на уже засеянном стенде

Параметры профилей лежат в `services/media_pipeline/src/media_pipeline_service/config/asset_profiles.yaml`
(кадры - `frame_progressive/default`: размытие 25, 20, 15, 10, 5, 0 px). Правка меняет
`params_hash`, поэтому у уже загруженных единиц нужны новые наборы:

```bash
uv run gv dev replan-assets --clue-type frame_progressive   # переменные админа - как у `gv dev seed`
```

Одна команда: порциями досоздаёт недостающие наборы (`POST /admin/v1/asset-sets/replan`), ждёт их
готовности и новых версий режимов game (`game.modes.bootstrap` публикует правку сида, когда под
новый хэш готов пул; в dev-оверлее проверка раз в минуту). Старые наборы и версии режимов остаются:
начатые сессии и наборы дня доигрываются по ним. Повтор безопасен. Сначала должны быть выкачены
новые образы media-pipeline и game.

У реальных фильмов нет `soundtrack` и `audio_clip`, поэтому режимы «саундтрек» и «затемнение»
по-прежнему играют на синтетике. Повторный запуск безопасен (стабильные `Idempotency-Key`).

## Скрипты выгрузки (`fetch_tmdb_popular.py`, `fetch_deezer.py`)

Запускаются вручную, пишут в `<root>/tmdb/` и `<root>/deezer/` (`GV_REAL_MEDIA_DIR`, по умолчанию
`C:/gv-media`), в git результат не попадает. Подробности и параметры - в docstring скриптов.

- **`fetch_tmdb_popular.py`** - популярное кино TMDB: четыре категории (Аниме, Мультфильмы,
  Сериалы, Фильмы; в каждой не меньше `--min-per-category`, по умолчанию 150, всего не меньше
  `--total`, 10 000). Ключ - `TMDB_KEY` в `<root>/.keys.env`, нигде не печатается. Раскладка:
  `tmdb/<Категория>/<movie|tv>-<id>/{poster,frame-1..6}.jpg`, `tmdb/<Категория>/catalog.jsonl` и
  общий `tmdb/catalog-films.jsonl` (его читает `seed-real`). Оставляются только тайтлы с афишей
  и полным набором кадров.
- **`fetch_deezer.py`** - популярные треки Deezer через публичное API (ключ не нужен; лимит
  около 8 запросов в секунду держит сам скрипт). Набирает пул артистов (жанры, чарты, имена из
  `seed-artists.txt`, «похожие артисты»), берёт топ-треки, убирает дубли одной песни (ремастеры,
  «feat.»), оставляя ремиксы и лайвы отдельными треками, и скачивает превью 30 с и обложки.
  Результат: `deezer/clips/<id>.mp3`, `deezer/covers/<album_id>.jpg`,
  `deezer/catalog-tracks.jsonl` (`key` `track:deezer-<id>`, `genres`, `metrics.listens` из
  `rank`, `source_url`, `audio`, `cover`).

**Условия Deezer.** Условия API Deezer разрешают только личное некоммерческое использование.
Выгрузка нужна исключительно для локального стенда и нигде не публикуется; лицензия в строках
каталога пуста (ADR 0072: `license_note` необязательна). Для публичного релиза источник музыки
должен быть другим - это решает владелец.
