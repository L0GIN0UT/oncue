# 0068. Сигналы win-trading для модератора

- **Статус:** черновик
- **Дата:** 2026-10-25
- **Уточняет:** [0038](0038-matchmaking-queues.md) (раздел «Win-trading»), [0052](0052-sanctions-and-enforcement.md) (шкалы порядочности без автосанкций)

## Контекст
ADR 0038 отказался от лимита повторных пар (временные ограничения исключены решением владельца) и отложил детектор аномалий. В 5c social считает только счётчики порядочности. Онлайн-опыт без потолка делает выгодным договорные матчи и фарм вторым аккаунтом. Решение владельца: **автосанкций нет** — детектор лишь показывает сигналы модератору.

## Решение
1. **Источник.** `match.MatchFinished` в social (уже слушается). Учитываются только рейтинговые дуэли 1×1: `ranked = true` (нет поля — `ladder` не `null`), `aborted = false`, ровно два разных игрока. Победитель — `outcome = win`, сдавшийся — `finish = forfeit` (оба сдались — никто). `PlayerRated` для сигналов не нужен. Новых полей в контрактах событий нет.
2. **Сигналы.**
   - `pair_repeat` — пара сыграла ≥ `min_matches` рейтинговых матчей за окно `window_s` (в обе стороны, окно от самого свежего матча пары). `streak` — подряд побед одного игрока над другим; ≥ `strong_streak` — серьёзность `high`, иначе `medium`.
   - `forfeit_series` — игрок сдался ≥ `streak_min` раз подряд против одного соперника в окне `window_s`; любой матч пары без его сдачи обрывает серию.
   - `forfeit_window` — игрок сдался ≥ `window_min` раз за окно `window_s` (любые соперники).
3. **Конфиг.** Необязательная секция `win_trading` тела `social_config.v1` (`pair_repeat`, `forfeit_series`; все числа 1..1 000 000), версиями в БД (ADR 0053). Секции нет — действуют умолчания домена (окно 7 суток, 5 матчей, серия 3, 3 сдачи подряд, 5 за окно); схема остаётся `v1` (добавлено необязательное поле). Сид `seeds/social/config.yaml` задаёт значения явно.
4. **Хранение.** Миграция `0007` (expand, только новые таблицы): `win_trading_matches` (факт матча, PK `match_id` — повтор события не меняет данные) и `win_trading_signals` (готовые сигналы). Сигналы пересчитываются в транзакции потребителя при каждом новом факте по окнам *текущего* конфига (сигнал, переставший выполняться, удаляется), чтение идёт без пересборки. `identity.UserDeleted` удаляет факты и сигналы игрока.
5. **Показ.** Admin-API social, право `social.moderate`: блок `win_trading` в `GET /admin/v1/users/{id}/moderation` и очередь `GET /admin/v1/win-trading/signals` (фильтры `kind`, `severity`, `user_id`, курсор; свежие первыми). Раздел «Модерация» admin показывает то же. Просмотр очереди аудируется (`social.view_win_trading`). Игроку данные не показываются.

## Ограничения
- **Ложные срабатывания.** Друзья и родные играют друг с другом часто; сигнал — повод посмотреть, не вердикт. Социальной связи детектор не учитывает.
- **Нет автоматики:** ни санкций, ни уведомлений игроку, ни блокировки очереди. Санкцию модератор выдаёт вручную (`RANKED`).
- **Не обратное:** матчи до выката не восстанавливаются; изменение конфига действует с ближайшего матча пары.
- Не ловит сговор через много аккаунтов (кольца из трёх и более) и «сдачу без forfeit» (нарочно проигранный матч). Пересмотреть по данным.

## Последствия
- Рост `win_trading_matches` — одна короткая строка на рейтинговую дуэль; при нагрузке добавить ретенцию (старше максимального окна) — отдельной задачей.
- Пороги правятся без деплоя (черновик → публикация конфига social).
