# 0012. Подписанные ссылки на ассеты: короткий TTL, проверка на Nginx

- **Статус:** принято (уточняет `architecture/security.md` §5 в части «одноразовых» ссылок)
- **Дата:** 2026-10-09

## Контекст
Ассеты загадок (отрывки, кадры, постеры по уровням) нельзя отдавать заранее: иначе клиент получит ответ до ревила. В документации заявлены «одноразовые подписанные ссылки». На VPS нет CDN с token-auth, а отдача файлов через сервис со счётчиком в Redis нагружает бэкенд.

## Решение
media-pipeline выдаёт HMAC-ссылку (`secure_link_md5` Nginx) на конкретный уровень с TTL 60 с. Nginx проверяет подпись и срок и отдаёт объект из приватного MinIO во внутренней сети (`proxy_cache`). Одноразовость заменяют: короткий TTL, случайные ключи объектов без id контента, журнал выдачи (`link_issuance`) и rate-limit выдачи на субъекта и уровень. Порт `UrlSigner` позволяет позже подключить CDN с token-auth без изменения логики.

## Альтернативы
- Строго одноразовые ссылки через сервис со счётчиком в Redis — нагрузка на бэкенд отдачей файлов, сложнее кэширование.
- Presigned URL S3 — нельзя ограничить кэширование и раздачу через gateway, MinIO пришлось бы публиковать наружу.

## Последствия
- (+) Простая и быстрая раздача на VPS, MinIO не торчит наружу.
- (−) В течение 60 с ссылку можно открыть повторно. Риск ограничен: ссылка даёт только уже открытый уровень.
- Настоящая одноразовость — этап 7 вместе с CDN.
