# 0045. Магазин и инвентарь: покупка в одной транзакции с ledger

- **Статус:** предложен (черновик; решения владельца — 2026-10-23). Зона повышенной безопасности
- **Дата:** 2026-10-23

## Контекст
В 5b Версы тратятся на косметику. Ошибка здесь — потеря или дублирование валюты: двойное списание,
покупка без проводки, предмет без оплаты, отрицательный баланс. Слоты, редкости и условия открытия
должны меняться без релиза.

## Решение
- **Предмет (`items`):** `slot` (аватар, рамка, титул, фон — значения из конфига), `rarity` (конфиг),
  `media_kind` = `static | animated`, `asset_key` (S3, формат — [0046](0046-animated-cosmetics-format.md)),
  `level_required?`, `price?` (целые Версы). `CHECK`: задано хотя бы одно из `level_required` и `price`.
  Если заданы оба — предмет доступен по уровню или за Версы раньше уровня. Условий в коде нет.
- **Инвентарь (`inventory`):** PK `(user_id, item_id)`, `source` (`purchase | level | wheel | promo | pack | admin`),
  `acquired_at`, `expires_at?`, `convert_condition?` (поля для 5d, в 5b всегда `NULL`).
  Чтение скрывает просроченные.
- **Оформление (`equipped`):** PK `(user_id, slot)` → `item_id`; предмет должен быть в инвентаре и
  соответствовать слоту. Снятие — удаление строки.
- **Покупка** `POST /v1/shop/items/{id}/purchase`, `Idempotency-Key`. Одна транзакция под `FOR UPDATE`
  баланса `earned`: проводка `CurrencyDebited` (`op_id = shop:{user}:{item}`), строка инвентаря,
  outbox `ItemPurchased` (+ `CurrencyDebited`). Повтор возвращает ту же выдачу; нехватка Версов —
  409 `progression.insufficient_funds`; предмет уже есть — 409 `progression.already_owned`;
  цена и условия берутся только из БД, клиент передаёт лишь id.
- **Открытие по уровню** — без проводки: выдача при первом чтении инвентаря или по `ProgressionLevelChanged`
  (`op`-отметка `level:{user}:{item}`, `source = level`).
- **Колесо:** приз-косметика выдаётся в инвентарь тем же путём; дубль заменяется Версами по редкости предмета
  (сетка `wheel.duplicate_verses` по редкостям в конфиге, `op_id = wheel:{user}:{day}:dup`).
- **Сторно покупки** — вне 5b; дебеты не сторнируются через admin-API 5a (`progression.not_reversible`).
- **Сверка** журнала и баланса учитывает дебеты; без неё траты не включаются (ADR 0043).

## Рассмотренные альтернативы
- Покупка как две операции (списание, затем выдача) с компенсацией — окно, где деньги списаны, а предмета нет.
- Асинхронная выдача по событию `CurrencyDebited` — отставание, видимое игроку, и ещё один источник гонок.
- Условия открытия в виде кода (`if level >= n`) — нарушает правило «ничего не хардкодить».
