# 0003. Два брокера: Redpanda для событий, RabbitMQ для задач

- **Статус:** принято
- **Дата:** 2026-10-07

## Контекст
Две разные потребности: доменные события с многими потребителями и replay (новые сервисы, восстановление проекций) и фоновые задачи с ретраями, DLQ и приоритетами.

## Решение
Redpanda (Kafka API) — лог доменных событий. RabbitMQ (quorum queues) — очереди задач. Доступ через абстракции `libs/messaging` (`EventPublisher`, `TaskQueue`).

## Альтернативы
- Только RabbitMQ (+ Streams): replay ограничен, экосистема Kafka-инструментов недоступна.
- Только Kafka: ретраи с задержкой, DLQ и приоритеты для задач — самописные.
- Kafka вместо Redpanda: JVM, больше памяти на VPS. API совместим, переход возможен без изменения кода.

## Последствия
- (+) Каждая модель используется по назначению.
- (−) Два компонента в эксплуатации и мониторинге.
