# 0044. Ежедневное колесо и бусты опыта

- **Статус:** предложен (черновик; решения владельца — 2026-10-23)
- **Дата:** 2026-10-23

## Контекст
Раз в сутки игрок крутит колесо: бусты опыта, Версы, редко косметика. Нужно, чтобы результат нельзя
было выбрать, повторить или подменить, а бусты не влияли на рейтинг.

## Решение
- **Колесо:** число секторов (12 по умолчанию), призы и веса — в версионируемом конфиге.
  Один спин в сутки; сутки обновляются вместе с дейликом (`progression.timezone`).
- **`wheel_spins`, PK `(user_id, day)`.** Сектор выбирает сервер через порт `Random`
  (криптостойкий источник) по весам версии конфига; результат пишется до ответа; повторный запрос
  возвращает ту же запись; `Idempotency-Key` не нужен — естественный ключ `(user_id, день)`. Тело запроса `POST /v1/wheel/spin` пустое, лишние поля отклоняются.
- **Приз выдаётся в той же транзакции**: Версы — проводка `wheel:{user}:{day}`, буст — запись в
  `boosts`, косметика — вызов порта инвентаря (в 5a заглушка: запись в журнал выдач, реальная выдача
  в 5b).
- **Буст:** `boosts(user_id, multiplier, matches_left)`, множитель только к **опыту**, никогда к
  рейтингу и Версам. Тратится завершённым онлайн-матчем с опытом больше нуля, идемпотентно по
  `match_id`. Бусты не складываются: новый встаёт в очередь. Порядок: буст, затем потолок (для соло
  буст не применяется).
- **Веса публикуются** в профиле колеса (`GET /v1/wheel`), чтобы шансы были видны игроку.
- **Колесо никогда не продаётся** — иначе это лутбокс. Запрет зафиксирован здесь.

## Рассмотренные альтернативы
- **Выбор сектора на клиенте** — подмена результата.
- **Спин без привязки к дню** — повтор запроса даёт лишний приз.
- **Буст по времени** — сгорает, пока игрок офлайн; буст «на N матчей» понятнее.

## Уточнения реализации P2
- **Полная очередь бустов.** Лимит: 1 активный + `wheel.max_boost_queue` в очереди. Если сектор с
  бустом выпал при полной очереди, приз заменяется на `none` (в ответе, в `wheel_spins` и в событии);
  `sector_key` остаётся настоящим.
- **`item` в `WheelSpun`.** Схема события не знает приз `item`: в событии он идёт как `none`, в API
  и `wheel_spins` — `item`; выдача — запись `grants_log` (заглушка до 5b).
- **`season_tier`** (метрика бейджа «звание сезона») = число полос сетки наград сезона ниже полосы
  игрока + 1; вне сетки — 0. Это упрощение 5a: цель бейджа выбирает порог (1 — любое место таблицы).
- **`GET /v1/me/quests` пишет назначение**: первое обращение за период назначает набор и сохраняет
  снимок (под блокировкой игрока), то есть это не чистое чтение.
- **Размер пула.** `quests.daily_count` / `weekly_count` больше числа включённых заданий пула — не
  ошибка конфига: игроку выдаётся весь пул.
- **Ретро-назначения.** Событие с `finished_at` из прошлого периода засчитывается в тот период;
  если набор того периода ещё не назначен, он назначается задним числом по конфигу на `finished_at`.
- **Хук буста** вызывается только при положительном базовом опыте матча (участие и раунды, либо
  бонус первой победы дня больше нуля); трата — в транзакции матча, идемпотентно по `(user, match)`.

## Последствия
- Тесты: 20 параллельных спинов дают одну проводку и одинаковый ответ; распределение по весам
  проверяется на фиксированном `Random`.
- Заглушка выдачи косметики заменяется реализацией в 5b без смены контракта.
