# 0029. Ассеты сборников — наборы со `scope`

- **Статус:** предложено (план этапа 3b, утверждён владельцем)
- **Дата:** 2026-10-16
- **Уточняет:** [0020](0020-mode-config-assets-by-params-hash.md), [0024](0024-clue-texts-as-media-assets.md)

## Контекст
Автор сборника хочет свои загадки к единицам. Свои картинки требуют очереди модерации
(этап 5), свободный текст — тоже. Эмодзи без текста почти не требуют модерации. Отдавать
эмодзи из проекции game значит завести вторую модель играбельности и выдачи уровней, от
которой отказались в ADR 0024.

## Решение
- В 3b свои ассеты — **только эмодзи** (D5): строго RGI (`gv_text.emoji.is_strict_emoji`,
  таблица Unicode Emoji 16.0), не больше 12 графем, без текста. Проверка — и в
  collections при публикации, и в media-pipeline (защита в глубину).
- Путь тот же, что у текстов catalog: `CollectionPublished.items[].custom.emoji` →
  media-pipeline заводит исходник `text` со `scope = collection:<id>` и строит наборы
  только профилей `emoji` → `AssetsReady|AssetsFailed.scope = {kind: "collection", id}`.
- game хранит `scope_id` у ассета. Для сессии по сборнику берётся сначала набор со
  `scope` сборника, затем каталожный (`PlayableFor.scope`).
- Удаление эмодзи, `CollectionDeleted` или скрытие сборника удаляет наборы со `scope`;
  объекты S3 чистит существующая очистка.

## Последствия
- Античит и выдача уровней те же, что у каталожных загадок; scoped-ассет выдаётся только
  в сессиях этого сборника и только для открытого уровня.
- Уникальность ассета в game становится `(media_item_id, clue_type, params_hash,
  scope_id)`; индекс меняется в два шага (новый `CONCURRENTLY`, старый — следующим
  релизом).
- Свои кадры и описания — этап 5, неверные варианты — вместе с `lite` (этап 4).
