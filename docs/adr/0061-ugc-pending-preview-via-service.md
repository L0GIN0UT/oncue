# 0061. Предпросмотр непромодерированных UGC-изображений через сервисы

- **Статус:** предложен (черновик; решение владельца — 2026-10-25). Уточняет [0048](0048-promo-codes-custom-avatar.md) и [0012](0012-signed-asset-links-nginx.md). Зона повышенной безопасности (загрузка пользовательских файлов)
- **Дата:** 2026-10-25

## Контекст
По 0048 pending-изображения лежат в бакете ассетов под `p/<hex>.webp`, а политика бакета разрешала
анонимный `s3:GetObject` на `p/*`: модератору их отдавал gateway по подписанной ссылке `/media/p/…`.
Любой, кто достучался до S3 во внутренней сети и знает ключ, читал файл до модерации (в бэклоге —
«принятый риск»). Ключ — 128 бит из CSPRNG, но сам факт анонимного чтения непромодерированного
содержимого лишний.

## Решение
- Из `assets_read_policy` убран `p/*`; анонимно читаются только `a/*` (через gateway по подписи, 0012)
  и `u/*` (одобренные, публично через `/ugc/`). Политику перезаписывает `put_bucket_policy` в job `migrate`
  (`prepare_storage`), прежняя не остаётся.
- media-pipeline: `GET /admin/v1/ugc-images/{asset_id}/preview` (право `media.ugc.moderate`) отдаёт
  байты только `pending`-заявки (`image/webp`), читая объект из S3 по ключам сервиса. Заголовки
  `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Content-Disposition: inline`.
  Не `pending` — 409 `ugc.not_pending`, нет заявки или объекта — 404 `ugc.not_found`. Выдача аудируется
  (`ugc.preview`). Ключ объекта и адрес S3 в ответ не попадают. Ответ-ссылка (`url`, `expires_at`) удалён.
- admin: `GET /ugc/<id>/preview/` — прокси за `require_perm`: зовёт ручку с токеном модератора и
  стримит байты браузеру с теми же заголовками; токен в браузер не уходит; просмотр аудируется
  (`ugc.view_preview`). Карточка вставляет `<img src="/ugc/<id>/preview/">` только для `pending`.
- gateway: location `/media/p/…` удалён (путь отвечает 404), `NginxSecureLinkSigner` подписывает только `a/`;
  настройки `GV_MEDIA__UGC_PREVIEW_TTL_S` и `GV_MEDIA__UGC_PUBLIC_BASE_URL` убраны как ненужные.
- Ломающее изменение API для admin; admin обновлён в том же PR (media-pipeline вызывает только admin).

## Альтернативы
- **SigV4 на nginx** (gateway сам подписывает запросы к S3): нативной поддержки в nginx нет, нужен
  сторонний модуль/скрипт и хранение S3-ключей на gateway — рост поверхности атаки.
- **Presigned S3-ссылки:** требуют, чтобы S3 был доступен браузеру модератора, а это ломает 0012
  (хранилище не публикуется наружу).
- **Оставить как есть (принятый риск):** отвергнуто — стоимость исправления мала.

## Последствия
- Нагрузка на media-pipeline — только от модераторов (одна картинка ≤ лимита назначения на открытие карточки).
- Одобренные и отклонённые изображения предпросмотра не имеют: одобренное публично на `/ugc/`,
  отклонённое удалено. Карточка одобренного в admin показывает метаданные без картинки.
- Выкат: сначала media-pipeline (+ migrate с новой политикой), затем admin; между ними превью в старом
  admin не работает (кратковременно, только для модераторов).
- Требуется ручная проверка владельцем (зона загрузки файлов).
