# 0022. Скан образов (trivy) — отчётный, не блокирующий пайплайн

- **Статус:** принято
- **Дата:** 2026-10-12

## Контекст
Job `build` в CI собирает образ каждого сервиса и сканирует его trivy. Скан стоял
с `exit-code: 1` по `severity: CRITICAL,HIGH` (с `ignore-unfixed`), то есть любая
исправимая CRITICAL/HIGH-уязвимость валила сборку.

Пока падали тесты (этап S3/MinIO), job `build` вообще не запускался — гейт был
скрыт. После починки тестов все 15 сборок покраснели на trivy: в пакетах базового
образа `python:3.13-slim` (Debian) почти всегда есть свежие исправимые CRITICAL/HIGH
CVE. Это вне нашего контроля (фикс приезжает с обновлением базового образа), а
жёсткий гейт красит весь пайплайн на каждую новую CVE — даже когда правка к ней
отношения не имеет, — и блокирует несвязанные мерджи.

## Решение
- **Скан образа — отчётный, не блокирующий** (`exit-code: 0`). Таблица уязвимостей
  остаётся в логах job, видимость не теряется.
- **Зависимости, которые мы контролируем, по-прежнему строго гейтятся** `pip-audit`
  (`--strict`) в job `lint`: их мы чиним бампом версий в `uv.lock`. CVE пакетов
  базового образа — зона ответственности базового образа, а не нашего кода.
- `ignore-unfixed` оставлен: шум по CVE без доступного фикса не нужен и в отчёте.

## Последствия
- CI не краснеет на внешней CVE-текучке базового образа; гейт остаётся там, где он
  действенен (наши зависимости — pip-audit).
- Уязвимости образа видны в логе скана, но не отслеживаются централизованно.
  До прода: выгружать SARIF trivy в GitHub Security (code scanning) и вернуть
  блокировку по CRITICAL после включения регулярного обновления базового образа
  (digest-пиннинг + Dependabot на базовый образ). Пункт в roadmap, этап 7.
- Политика применяется и в `nightly`, если там появится сборка образов.

## Альтернативы
- **Оставить `exit-code: 1`** — пайплайн красный на неустранимые нами CVE,
  несвязанные мерджи заблокированы. Отклонено.
- **Гейтить только CRITICAL** — всё ещё красит CI на свежую исправимую CRITICAL в
  базе вне нашего контроля; полумера.
- **Выгрузка SARIF в Security tab сейчас** — требует включённого code scanning в
  настройках репозитория; отложено, чтобы не вносить в пайплайн шаг, падающий без
  этой настройки. Запланировано на этап 7.
