# 0023. Состав раунда, форматы ответа и правила завершения — плагины ядра

- **Статус:** предложено (план этапа 3a, утверждён владельцем)
- **Дата:** 2026-10-16

## Контекст
На этапе 2 раунд — одна загаданная единица, ответ — ввод названия, сессия идёт все
`session.rounds` раундов. Режимы этапа 3a ломают все три допущения: «больше/меньше»
показывает две единицы и спрашивает выбор, марафон и пара заканчиваются по промахам,
сетка строит следующие раунды из выборов прошлых. Ветвление по ключу режима в game или
во фронтенде нарушает правило «режимы — конфиги и плагины» (ADR 0008).

## Решение
- **Состав раунда — `RoundDraw(target, shown, options)`.** Источник отдаёт цель, открыто
  показанные единицы и варианты ответа. Классические источники дают только `target`.
- **Формат ответа — плагин `AnswerFormat`** (`classic`, `pick`). `answer.format` в
  контракте — ключ плагина, а не перечисление. Ответ `pick` — непрозрачный `option_id`
  варианта раунда; какая единица за ним, знает только сервер.
- **Досрочное завершение — плагин `EndRule`** в `session.end` (`all_rounds` по
  умолчанию, `lives`). `session.rounds` с правилом — максимум раундов (≤ 200).
- **Ленивая материализация:** раунды, зависящие от прошлых, источник отдаёт через
  `ProgressiveSource.followups(history)`; план сессии скрыт от клиента.
- **Подача итога** — `Scorer.presentation` (`score`, `streak`, `bracket`): клиент
  выбирает экран итога по данным, а не по ключу режима.

## Последствия
- Новые механики добавляются плагинами без правок ядра и game.
- Состояние сессии в `state jsonb` получает версию схемы: снимки этапа 2 читаются как v1.
- Контракт конфига расширяется совместимо: старые конфиги валидны без правок.
