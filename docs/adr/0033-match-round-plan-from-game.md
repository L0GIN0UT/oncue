# 0033. Источник раундов матча — план от game по internal API

- **Статус:** предложено (план этапа 4, решение владельца 2)
- **Дата:** 2026-10-22

## Контекст
Матчу нужны единицы раундов, ключи ответа (алиасы, частичные), наборы ассетов по уровням и
варианты `pick`. Всё это уже умеет game: проекции каталога и ассетов, сборники, проверка
играбельности, `ModeEngine.draw_rounds`. Повторить проекции в match — вторая модель
играбельности и второй набор потребителей событий.

## Решение
- При старте матча match **один раз** вызывает `POST /internal/v1/round-plans` game
  (сервисный токен, scope `rounds.plan`): `{mode_key, version?, seed, rounds,
  collection_ids[], exclude_ids[]}` → версия и тело конфига, раунды с ключами ответа,
  `asset_set_id` по уровням, варианты. Тело опубликованного конфига для проверки шаблона
  лобби — отдельная internal-ручка game.
- План хранится только в снимке комнаты ([0034](0034-rooms-process-lease-snapshots.md)) и
  клиенту не уходит. Ссылки уровней выдаёт media-pipeline по запросу match в момент открытия
  уровня (одна ссылка на комнату, раунд и уровень).
- Своих проекций каталога, ассетов и сборников в match нет.
- Ошибка плана (`pool_too_small`, недоступный контент, таймаут) — матч не стартует, комната
  возвращается в лобби или прерывается с причиной, без висящего состояния. Вызов — с
  таймаутом и circuit breaker.

## Последствия
- Таблица деградации (`scalability-resilience.md` §4.2): при недоступности game **идущие
  матчи доигрываются, новые не стартуют** («онлайн временно недоступен»).
- Синхронный вызов не на горячем пути: один хоп при старте, без цепочек A→B→C.
- Клиент сервисного токена `match` получает scope `rounds.plan` у game и `assets.link` у
  media-pipeline (`GV_SERVICE_CLIENTS`, ADR [0016](0016-service-tokens-client-credentials.md)).
