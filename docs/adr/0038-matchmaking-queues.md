# 0038. Матчмейкинг: очереди Redis, батчевый матчер, окно рейтинга

- **Статус:** принято (решения владельца 4b, 2026-10-23); реализуется в 4b (поток Q)
- **Дата:** 2026-10-23
- **Заменяет в плане этапа 4:** D16 в части party-очередей и штрафов `dodge_cooldown_s`

## Контекст
Подбор нужен только для рейтинговой дуэли 1×1. Рейтинг общий на домен, очередь отдельная на
формат: игрок выбирает формат и состоит ровно в одной очереди. Штрафов по времени и запрета
очереди нет.

## Решение
- **Очередь = `(ladder, format)`**, хранится в Redis (ZSET по рейтингу + хэш записи с
  `entered_at`, `last_seen`). API: `POST /v1/queue/enter | tick | leave`, `GET /v1/queue/pool`.
  `tick` — heartbeat раз в `GV_MATCH__TICK_S` и источник состояния (`searching | matched`,
  `room_code`); запись без heartbeat исчезает.
- **Рейтинг для подбора** — проекция `RatingChanged` в match (по `version`), новичок —
  `elo.start`. Применение `SeasonStarted.soft_reset` к проекции делает сам match тем же
  правилом (`target + ratio × (old − target)`), отдельных событий на сброс нет.
- **Окно** `±window.base`, каждые `window.step_every_s` секунд + `window.step`, потолок
  `window.max`; после `slow_hint_after_s` клиент видит «ищем дольше обычного», игрок остаётся
  в очереди. Всё из `LadderPublished.matchmaking` (по умолчанию ±100, +50 каждые 10 с).
- **Матчер** — батч раз в `matchmaking.interval_s` в процессе `rooms` под lease очереди
  (fencing-эпоха, как у комнат, ADR 0034): жадно по близости рейтинга, пара обязана попасть в
  окно обоих. Комната создаётся сразу в `countdown` из рейтингового шаблона домена
  (`answer.format` = `classic` для `classic`, `pick` для `lite`).
- **Допуск:** любой аккаунт; `Sanction.RANKED` в claim → 403 `match.ranked_forbidden`. Один
  игрок — одна активная комната или очередь (409 `match.active_room_conflict`).
- **Срыв отсчёта** — без штрафа, соперник возвращается в очередь с прежним `entered_at`.
  Принятый риск: срыв без последствий допускает сталкинг очереди; пересмотреть по данным.
- **Win-trading:** лимита повторных пар нет (временные ограничения исключены решением
  владельца); детектор аномалий — этап 5.

## Последствия
- Очередей четыре (`music`/`film` × `classic`/`lite`); пустая очередь — нормальное состояние.
- Падение rating не мешает подбору: проекция рейтинга устаревает, но не блокирует.
