# 0019. Соло-сессии в Postgres

- **Статус:** принято (уточняет карточку game в [services.md](../architecture/services.md#4-game))
- **Дата:** 2026-10-11

## Контекст
Карточка game в v1 архитектуры предполагала «горячие сессии в Redis с TTL» и Postgres только для результатов. Для соло-игры этапа 2 важны три свойства: событие `GameFinished`/`DailyCompleted` не теряется (outbox в одной транзакции с изменением), одна попытка дейлика на субъекта и день гарантирована, ход не применяется дважды. Решение D12 [плана этапа 2](../plans/stage-2.md#1-сквозные-решения-утверждены).

## Решение
- **Источник истины соло-сессии — Postgres** (таблица `game_sessions`, раунды и ответы — в строке сессии).
- Ход (ответ, пропуск, сдача) — одна транзакция:
  1. строка сессии под `SELECT … FOR UPDATE`;
  2. проверка `expected_version` (иначе 409 `game.desync` с актуальным снимком);
  3. `Idempotency-Key` через `gv_db.idempotency` в той же транзакции;
  4. переход по правилам `ModeEngine`, `version + 1`;
  5. событие в outbox, если сессия завершилась.
- Уникальность попытки дня — ограничение БД по `(mode_key, day, player_kind, player_id)`.
- Вызов media-pipeline за ссылкой на ассет — **вне** транзакции хода.
- Брошенные сессии (`session.abandon_after_min`) переводит в `abandoned` периодическая задача `game.sessions.abandon`.
- **Redis** — только вспомогательное: лимиты частоты (fail-open), поколение кэша конфигов (`game:modes:gen`). Его потеря не теряет состояние игры.

## Альтернативы
- **Redis + сброс в Postgres по завершении.** При потере Redis теряются незавершённые дейлики; для outbox нужен второй путь записи; уникальность попытки дня пришлось бы держать двумя механизмами.
- **Redis как основное хранилище с AOF.** Не даёт транзакции вместе с outbox.

## Последствия
- (+) Один путь записи, outbox и уникальность на уровне БД; нет расхождения Redis ↔ Postgres.
- (+) game по-прежнему stateless: любой под обрабатывает любой ход.
- (−) Каждый ход — запись в Postgres. Для нагрузки этапа (одна строка, optimistic `version`) это укладывается в p95 < 150 мс; при росте — PgBouncer и партиционирование `game_sessions` по времени.
- Онлайн-матчи (match, [ADR 0010](0010-match-room-single-writer.md)) это решение не затрагивает: там состояние комнаты живёт в памяти single-writer.
