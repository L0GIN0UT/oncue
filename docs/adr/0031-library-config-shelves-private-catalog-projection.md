# 0031. Медиатека: системные полки из конфига, приватность, проекция каталога

- **Статус:** предложено (план этапа 3b, утверждён владельцем)
- **Дата:** 2026-10-16

## Контекст
Игрок сохраняет единицу из ревила, итога и карточек: «смотреть позже», «просмотрено»,
«любимое» и свои полки. Набор системных полок и правила между ними («просмотрено» убирает
из «смотреть позже») не должны быть зашиты в код. Публичные полки — это UGC-текст для всех
и вопросы модерации. Обогащать каждую страницу полки через bff → catalog дорого.

## Решение
- **Системные полки — конфиг (D11):** `GV_LIBRARY__SHELVES_CONFIG` (по умолчанию
  `config/shelves.yaml` сервиса): ключ, домены, `title_key`, `exclusive_with`. Создаются
  лениво при первом обращении. Свои полки — до `GV_LIBRARY__LIMITS__CUSTOM_SHELVES_MAX`,
  название проходит `gv_text.ugc` (ADR 0030).
- **Приватность:** вся медиатека видна только владельцу (чужая полка — 404), гость
  медиатеки не ведёт. Публичные полки — этап 5.
- **Проекция каталога:** library проецирует `catalog.MediaItem*` (домен, статус,
  название, год, персоны) и строит карточки полки без вызова catalog. Заблокированная
  единица остаётся на полке с отметкой `unavailable`.
- **Ручки (D12):** `PUT/DELETE /v1/shelves/{shelf_ref}/items/{media_item_id}`
  (`shelf_ref` — `system:<key>` или uuid), естественная идемпотентность +
  `Idempotency-Key`, CSRF/Origin для cookie, поле `source` (`reveal`, `results`, `card`,
  `collection`, `library`). События `library.ItemSaved|ItemRemoved` (топик
  `library.shelf.v1`) — только при фактическом изменении.

## Последствия
- До ревила `media_item_id` клиенту неизвестен, поэтому кнопка «сохранить» античит не
  ослабляет.
- `identity.UserDeleted` удаляет все полки пользователя порциями.
- Экспорт и синхронизация полок (`ShelfExportRequested`) — этап 6, постеры — после
  публичного профиля постеров.
