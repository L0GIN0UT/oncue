# 0054. Сезонные события: определение и запуски в БД progression

- **Статус:** предложен (черновик; решение владельца — 2026-10-24)
- **Дата:** 2026-10-24

## Контекст
Сезонное событие (Новый год, Хеллоуин) — цепочка находок с периодом и темой оформления. Владелец
создаёт и запускает события из админки в любое время, без релиза и без файлового конфига. Событие
можно остановить досрочно и повторить с новым периодом.

## Решение
- **Определение** (`events`): `key`, тело JSON по `contracts/progression/event_definition.v1.json`
  (название, описание, `theme_key`, находки с координатами и дневником, награда), ключ картинки карты
  в S3 (бакет и публичный префикс предметов, ADR 0046). Правится, пока нет запусков не в `draft`.
- **Запуск** (`event_runs`): период `[starts_at, ends_at)`, статус `draft | published | active |
  finished | stopped`, на публикации — неизменяемый снимок определения и `body_sha256`. Прогресс и
  награды привязаны к запуску; архив читает снимок. Перезапуск — новая запись запуска.
- **Один активный запуск.** Публикация берёт advisory-lock и отказывает при пересечении периодов
  (409 `progression.event_period_overlap`). Периодом управляет время: задача relay
  `progression.events.tick` переводит `published → active → finished` и публикует `EventRunStarted` и
  `EventRunFinished`; чтение статуса не зависит от задачи (считается по времени).
- **Тема** — только ключ (ADR 0049): bff отдаёт `theme.key` активного запуска всем; пустой `theme_key`
  — тема не меняется. Отключить тему себе нельзя.
- **Права:** `progression.events.manage` (определение, запуски, статистика), `progression.events.publish`
  (публикация, остановка; только admin). Действия пишутся в `admin_actions`.

## Рассмотренные альтернативы
- Событие в файловом конфиге пакета — релиз на каждое событие.
- Находки в версионированном конфиге progression (ADR 0042) — событие не про лимиты, а про данные
  с собственным жизненным циклом и архивом.

## Последствия
- Снимок защищает архив и идущий запуск от правок определения.
- Часы сервера — источник истины для `active`; расхождение с задачей tick допустимо до её следующего прогона.
