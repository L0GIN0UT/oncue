# 0013. Админка в этапе 1 читает и пишет через admin-API сервисов

- **Статус:** принято (уточняет [ADR 0006](0006-django-admin-panel.md))
- **Дата:** 2026-10-09

## Контекст
ADR 0006 предполагал чтение админкой read-only реплик БД сервисов (unmanaged-модели Django) и запись через admin-API. В этапе 1 админка и сервисы разрабатываются параллельно; чтение реплик связало бы админку со схемой БД catalog, которая ещё меняется.

## Решение
В этапе 1 разделы админки и читают, и пишут через `/admin/v1` API сервисов (собственные view на Django). Каркас `ServiceModelAdmin` и роутеров реплик создаётся, но применяется с этапа 5 — для тяжёлых списков модерации, где чтение реплик оправдано производительностью.

## Последствия
- (+) Админка не зависит от схемы БД сервисов; поток admin не ждёт catalog.
- (−) Списки и фильтры админки ограничены возможностями admin-API (пагинация, фильтры приходится реализовать в сервисе).
