# 0004. Transactional outbox и идемпотентные потребители

- **Статус:** принято
- **Дата:** 2026-10-07

## Контекст
Без распределённых транзакций изменение данных и публикация события могут разойтись (запись есть, события нет, или наоборот).

## Решение
Событие пишется в таблицу outbox в той же транзакции, relay публикует его в брокер (at-least-once). Потребители дедуплицируют по `event_id` через inbox. Клиентские мутации принимают `Idempotency-Key`. Многошаговые процессы — оркестрируемые саги.

## Альтернативы
- Публикация после commit: теряет события при падении.
- 2PC/XA: не поддерживается брокерами, хрупко.
- Event sourcing: избыточен для большинства доменов.

## Последствия
- (+) Нет потерянных и задвоенных эффектов.
- (−) Eventual consistency между сервисами: UI должен это учитывать (награды приходят через секунды).
