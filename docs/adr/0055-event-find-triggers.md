# 0055. Триггеры находок: метрики заданий и спрятанные элементы

- **Статус:** предложен (черновик; решение владельца — 2026-10-24)
- **Дата:** 2026-10-24

## Контекст
Находка открывается действием игрока. Часть действий видят сервисы (матч, дейлик, сборник), часть —
только интерфейс (найти спрятанный элемент на странице).

## Решение
- **`server`.** Триггер — метрика из реестра заданий (ADR 0042) с `target` и периодом `day | event`.
  Реестр расширен: `duel_win`, `weekly_top_place` (счёт при месте ≤ `params.place_max`),
  `wheel_spin_streak`, `item_equipped` (`params.slot` или `params.item_key`), `collection_played`
  (`params.tag`). Находка засчитывается только событиями сервисов; предмет события — как у заданий
  (`metric_marks`), поэтому повтор с новым `event_id` не двоит прогресс.
- **`ui_spot`.** Белый список `page_key`: `home, leaderboards, profile, collections, match_summary,
  shop, wheel`. Клик шлёт `POST /v1/events/{key}/finds/{find}/claim`; сервер проверяет активный запуск,
  тип находки и порядок, повтор идемпотентен (200 с прежним результатом). Защиты от подделки клика нет
  (решение владельца): награда — косметика, нужен лимит запросов на игрока (Redis, fail-closed).
- **Порядок свободный, финал закрыт** до остальных находок (409 `progression.event_find_locked`).
- События до начала запуска и после его окончания находки не двигают; время — `finished_at` события.

## Последствия
- Новый тип триггера — строка в реестре и источник в application, без `if` в ядре.
- Подделка клика даёт игроку находку без действия — принятый риск, ограничен лимитом и ценой награды.
