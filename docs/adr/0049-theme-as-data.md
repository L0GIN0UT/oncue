# 0049. Тема оформления: наборы токенов во фронтенде, ключ — данные

- **Статус:** предложен (черновик; решение владельца — 2026-10-23)
- **Дата:** 2026-10-23

## Контекст
Будущие сезонные события (5d) должны менять вид интерфейса. Если цвета, радиусы и шрифты зашиты в
компоненты, тему не подменить. При этом значения оформления не должны приходить с бэкенда: это
исключает CSS-инъекции и рассинхрон версий фронтенда и данных.

## Решение
- **Дизайн-токены** — CSS-переменные: цвета, фоны, радиусы, шрифты, иконки. Компоненты используют только
  токены; захардкоженные цвета и шрифты запрещены (проверка lint-правилом или тестом по исходникам).
- **Наборы токенов лежат во фронтенде** — по одному на тему, ключ темы (`default`, позже `halloween`, …) →
  файл `frontend/src/styles/themes/<key>.css` (или объект токенов). Новый набор — релиз фронтенда,
  выпускаемый заранее до начала события.
- **Бэкенд отдаёт только ключ активной темы.** bff добавляет в `/pages/*` блок `theme: { key }`.
  В 5b ключ берётся из настройки bff (`default_theme_key`, по умолчанию `default`); в 5d — от активного
  сезонного события. Значений токенов в API, конфигах и БД нет.
- Фронт применяет набор по ключу на корневом элементе (атрибут `data-theme`, без мигания: ключ известен
  при серверном рендере). Неизвестный ключ — откат на `default`.
- Контраст каждого набора проверяется тестом (WCAG AA для основных пар токенов).

## Рассмотренные альтернативы
- Значения токенов в БД или конфиге с редактированием в админке — риск CSS-инъекции, нужна валидация,
  и тема может разойтись с версией компонентов.
- Отдельная сборка CSS на тему — релиз на каждую смену.
- Свободный CSS из админки — риск инъекции.

## Последствия
- Миграция существующих компонентов на токены идёт в S5 поэтапно; новые — только с токенами.
- Смена темы в рантайме — смена ключа в настройке bff (в 5d — по расписанию события), без релиза.
- Связано с 5d: у события будет `theme_key` ([план](../plans/stage-5.md) §12).
