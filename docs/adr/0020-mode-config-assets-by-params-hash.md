# 0020. ModeConfig ↔ ассеты по `params_hash`, очки в Scorer

- **Статус:** принято (уточняет [02-game-engine.md §4](../02-game-engine.md#4-уровни))
- **Дата:** 2026-10-11

## Контекст
Ассеты уровней заранее генерирует media-pipeline по профилям (`asset_profiles.yaml`) и сообщает о них событием `AssetsReady` с `params_hash` параметров профиля. game должен по конфигу режима найти готовый набор ассетов единицы и знать параметры уровней (длительности, размытие) для интерфейса. В v1 движка очки лежали внутри уровней (`levels[].points`): тогда любая правка очков меняла бы параметры загадки, а с ними и хэш. Решение D7 [плана этапа 2](../plans/stage-2.md#1-сквозные-решения-утверждены).

## Решение
- **`clue.params` в конфиге режима совпадают с параметрами профиля media-pipeline.** game хранит проекцию `clue_assets` из `AssetsReady` и ищет набор по `(media_item_id, clue_type, params_hash(clue.params))`.
- `params_hash` — `sha256` канонического JSON; алгоритм реализован дважды (`gv_game_kernel.params`, `media_pipeline_service.domain.params`) и закреплён golden-векторами `contracts/clues/params_hash.golden.json`, их проверяют тесты обеих сторон.
- **Очки уровней — в `scoring.params.points`** (Scorer `by_level`), а не в `clue.params.levels[]`. Длина `points` сверяется с числом уровней загадки перекрёстной проверкой валидатора (`config.*`). Максимум очков считает Scorer (`max_score`), клиент его не вычисляет.
- **Публикация** конфига проверяет, что играбельных единиц (единица активна в проекции каталога и у неё есть готовый набор ассетов под этот `params_hash`) не меньше `source.params.pool.min_playable`; иначе — ошибка валидации.
- Генерация ассетов под новый, ещё не известный media-pipeline набор параметров (`ClueAssetsRequested`) — этап 3. До этого конфиг с новыми `clue.params` не опубликуется: пул окажется пустым.

## Альтернативы
- **Ссылка по `profile_key`.** Проще, но game не знает параметров уровней для интерфейса и не замечает, что профиль с тем же ключом изменился.
- **Очки внутри уровней + хэш только по «визуальным» полям.** Требует, чтобы обе стороны одинаково знали, какие поля исключать, — хрупко без выигрыша.

## Последствия
- (+) Правка очков, раундов, пула и matcher не трогает ассеты; смена параметров уровней автоматически означает другой набор ассетов.
- (+) Расхождение конфига и профиля видно при публикации, а не во время игры.
- (−) Любая правка `clue.params` (даже порядка уровней) требует соответствующего профиля в media-pipeline.
- (−) Две реализации `params_hash`: изменение алгоритма — только с новыми golden-векторами в `contracts/`.
