# 0006. Админ-панель на Django, мутации через admin-API сервисов

- **Статус:** принято
- **Дата:** 2026-10-07

## Контекст
Нужна админка для модерации, контента и конфигов с ролями суперпользователь / модератор / пользователь. Данные распределены по БД сервисов.

## Решение
Отдельный сервис `admin` на Django. Чтение — unmanaged-модели поверх read-only реплик БД сервисов. Изменения — только через `/admin/v1` API сервисов. Вход через identity, права синхронизируются из identity. Свой аудит-лог.

## Альтернативы
- Django с прямой записью в БД сервисов: ломает инварианты и outbox, события не публикуются.
- Самописная админка на React: недели работы на списки, фильтры и формы.
- Готовые low-code (Retool, Appsmith): зависимость от внешнего инструмента, слабее контроль прав и аудита.

## Последствия
- (+) Быстрый и мощный UI, корректность доменов сохраняется.
- (−) У каждого сервиса появляется admin-API. Read-only доступ к репликам — исключение из правила «не читать чужую БД», разрешённое только для admin и только на чтение.
