# 0039. Сезоны, топ недели и лидерборды

- **Статус:** принято (решения владельца 4b, 2026-10-23); реализуется в 4b (поток G)
- **Дата:** 2026-10-23
- **Уточняет в плане этапа 4:** D18

## Решение
- **Сезон** — запись rating `(season_id, ladder, number, starts_at, ends_at)`. Длина —
  `season.length_days` конфига ladder-а (по умолчанию 56 = 8 недель). Закрытие — периодическая
  задача по `ends_at` (advisory lock, идемпотентно) или админ; следующий сезон открывается
  автоматически. События `SeasonFinished` (без списка мест — `standings_ref` на выборку API) и
  `SeasonStarted {soft_reset}`.
- **Мягкий сброс:** `new = target + ratio × (old − target)` (по умолчанию 1000 и 0,5), число
  матчей калибровки не обнуляется. Параметры — конфиг. Проекции читают формулу из
  `SeasonStarted.soft_reset`.
- **Топ недели** — прирост рейтинга с понедельника в зоне `weekly.timezone`, размер —
  `weekly.top_size`; закрывается в понедельник, `WeeklyTopFinalized` идемпотентно по периоду
  (`aggregate_id` = `{ladder}:{week_start}`).
- **Лидерборды** — Redis ZSET `{lb:ladder:season}` как хранилище чтения; источник истины —
  Postgres, пересборка задачей `rating.leaderboards.rebuild` и админ-ручкой. В лидерборд
  попадают игроки с `matches_played ≥ leaderboard.min_matches`; удалённые аккаунты скрыты.
  Публичные ответы кэшируются на bff на 10 с.
- Награды за сезон и топ недели, косметика — этап 5 (progression потребляет события);
  в 4b не реализуются.

## Последствия
- Потеря Redis не теряет лидерборды (пересборка).
- Смена `length_days` касается только новых сезонов.
