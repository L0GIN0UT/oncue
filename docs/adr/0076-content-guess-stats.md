# 0076. Статистика угадываний по контенту

- **Статус:** принято (решение владельца, 2026-11-03)
- **Дата:** 2026-11-03
- **Уточняет:** ADR 0074 (популярность в источнике единиц)

## Контекст
Сложность контента сейчас оценивается рангом Deezer (`metrics.listens`) и `metrics.popularity`.
Это текущая популярность, а не то, насколько трек или фильм реально угадывают. Нужны накопленные
по партиям данные на единицу и режим: сколько раз показан, угадан, угадан частично, не угадан,
на каком уровне и за какое время. Применение в подборе — отдельная задача, здесь только учёт и
отчёт.

## Решение
1. **Где живёт: сервис `catalog`.** Сложность — свойство контента, им владеет catalog; game и
   match владеют сессиями и матчами, а не контентом. catalog не читает чужие БД: данные приходят
   событиями.
2. **Источники — существующие события, контракты не меняются.**
   `game.GameFinished` (топик `game.session.v1`, соло, включая гостей) и `match.MatchFinished`
   (топик `match.match.v1`, онлайн) уже содержат по раундам `media_item_id`, исход, уровень и
   `elapsed_ms`. Обработчики подписаны на оба топика; потребитель идемпотентен через inbox
   (`EventProcessor`: запись inbox и инкремент счётчиков — в одной транзакции). Сами события
   публикуются один раз (`GameFinished` — при завершении сессии, `MatchFinished` — `UNIQUE match_id`),
   поэтому второго уровня дедупликации не нужно.
3. **Что считается.**
   - «Показан» — раунд с исходом `exact`/`partial`/`miss`/`gave_up`; `void` не считается.
   - Онлайн: результат игрока → `partial` при `partial=true`, `exact` при заданном `level`,
     иначе `miss`. Считаются только игроки с `finish` из `GV_STATS__MATCH_COUNTED_FINISHES`
     (по умолчанию `completed`: у вышедшего и сдавшегося нет ответов в начатых раундах).
     Прерванные матчи пропускаются (`GV_STATS__COUNT_ABORTED_MATCHES`).
   - Уровень и время учитываются только у точного ответа.
4. **Схема (миграция `0005`, только расширение).**
   - `content_mode_stats (media_item_id, mode_key)` — `shown`, `exact`, `partial`, `miss`,
     `gave_up`, `time_sum_ms`, `time_count`; CHECK: исходы в сумме дают `shown`, `time_count ≤ exact`.
   - `content_mode_buckets (media_item_id, mode_key, kind, bucket)` — `n`; `kind` = `level`
     (точные ответы по уровню) или `time` (гистограмма, ширина корзины `GV_STATS__TIME_BUCKET_MS`,
     всё дольше `TIME_BUCKET_MAX` копится в последней корзине). Размер таблицы ограничен
     числом единиц × режимов × (уровни + корзины), он не растёт с числом ответов.
   - Инкремент: `INSERT … ON CONFLICT DO UPDATE SET n = n + EXCLUDED.n`, ключи сортируются
     (одинаковый порядок блокировок у параллельных потребителей). Без FK на `media_items`:
     гонка импорта не должна ломать обработку события.
5. **Медиана** — приближённая, по гистограмме (нижняя медиана, середина корзины); точной
   медианы из счётчиков не получить, точность — полширины корзины.
6. **Отчёт.** `GET /admin/v1/stats/easiest-content?mode_key=&domain=&min_shown=&limit=` под
   `admin.access`: единицы по убыванию доли точных ответов при показах не меньше порога
   (`GV_STATS__REPORT_MIN_SHOWN`, по умолчанию 30; потолок выдачи `REPORT_LIMIT_MAX`). Публично
   не открыт.
7. **Неизменяемость корзин.** Корзина хранится номером, ширина (`TIME_BUCKET_MS`) и число
   (`TIME_BUCKET_MAX`) в данных не записаны: после накопления статистики менять их нельзя без
   очистки таблиц `content_mode_buckets` (иначе медиана искажается).
8. **Не делается:** статистика не участвует в подборе (отдельная задача); бэкфилла по прошлым
   играм нет — счёт идёт с момента выкладки.

## Последствия
- (+) Реальная сложность накапливается без новых событий и без изменения контрактов.
- (+) Объём данных ограничен; повторная доставка и параллельные потребители не искажают счётчики.
- (−) Дедупликация только по `event_id`: если game или match когда-нибудь начнут переиздавать
  итог той же сессии/матча с новым `event_id`, раунды посчитаются повторно — тогда нужна
  дедупликация по `session_id`/`match_id`.
- (−) Данные до выкладки не учтены; для редких единиц нужен большой порог показов.
- (−) Партии с разной аудиторией (соло и онлайн) различаются по `mode_key`, но смешиваются
  внутри одного режима.
- Тесты: `services/catalog/tests/unit/test_content_stats.py`, `.../integration/test_content_stats.py`,
  `.../component/test_api.py::test_stats_report_is_admin_only_and_bounded`.
