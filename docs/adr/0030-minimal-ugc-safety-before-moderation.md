# 0030. Минимальная безопасность UGC до модерации этапа 5

- **Статус:** предложено (план этапа 3b, утверждён владельцем)
- **Дата:** 2026-10-16

## Контекст
Сборники — первый пользовательский контент для всех: названия, описания, теги, свои
эмодзи, лайки. Очереди модерации и жалоб нет до этапа 5, а премодерация каждого сборника
вручную ляжет на владельца.

## Решение
- **Гости (D7)** играют публичные и unlisted сборники (если в режиме `allow_guest`), но не
  создают сборники, не лайкают, не ведут избранное и медиатеку (`require_user`, 403
  `auth.guest_forbidden`). Гостевые результаты не дают «пройден» и не входят в сложность.
- **Текст (D8)** — `gv_text.ugc`: NFKC, удаление управляющих, bidi- и zero-width-символов
  (ZWJ остаётся только внутри эмодзи), схлопывание пробелов; длина считается после
  нормализации. Denylist — файл (`GV_UGC__DENYLIST_PATH`, по умолчанию встроенный ru/en),
  сверка по «скелету» слова: похожие символы, регистр, диакритика, повторы и знаки внутри
  слова. В названии нельзя ссылок, доменов, `@` и e-mail. Ошибки — коды `ugc.*` в
  `details.reason` доменной ошибки сервиса.
- **Лимиты (D8)** — `GV_COLLECTIONS__LIMITS__*`: черновиков ≤ 20, публикаций в сутки ≤ 5
  (fail-closed), единиц 5..200, тегов ≤ 5 (из словаря). Лайки, избранное и сохранение в
  медиатеку — Redis fail-open с метрикой.
- **Модерация постфактум:** админ скрывает сборник и ограничивает автора (права identity
  `collections.view|curate|unpublish|restrict_author`, миграция `0007`), учитывается
  санкция `Sanction.CUSTOM_CONTENT` из claim. Черновики приватны (чужой — 404).
- **Лайки и избранное (D13):** `PUT/DELETE`, счётчик в той же транзакции,
  `CollectionLiked` только при новом лайке, свой сборник лайкнуть нельзя.
- **Кураторские сборники (D14):** YAML-редактор в админке → admin-API collections,
  `kind = curated`, автор «Guessverse»; «рекомендуемое» — для любых сборников.

## Последствия
- Denylist ловит обходы через похожие символы и невидимые символы, но не слова через
  пробел и «ссылки словами» — это остаётся модерации постфактум.
- Горячая строка `likes_count` приемлема для масштаба этапа; позже — счётчики в Redis.
- Очередь модерации, жалобы, свои кадры и описания — этап 5.
