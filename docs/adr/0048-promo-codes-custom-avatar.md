# 0048. Промокоды и своя аватарка

- **Статус:** предложен (черновик; решения владельца — 2026-10-23). Зона повышенной безопасности (промокоды дают валюту)
- **Дата:** 2026-10-23

## Контекст
Админ раздаёт награды кодами; игрок может купить право на свою аватарку. Код — секрет, перебор —
угроза, UGC-изображение — вектор атаки (файл, контент).

## Решение
### Промокоды
- Админ генерирует коды: награда — предмет или Версы, `max_uses`, `expires_at`, `per_user_once`.
  Код показывается один раз при создании; в БД — `code_hash` = HMAC-SHA256 серверным ключом
  (не голый sha256: коды короткие), сравнение за постоянное время.
- `promo_redemptions` PK `(code_hash, user_id)`. Погашение идемпотентно: повтор возвращает ту же награду.
  Счётчик активаций — под блокировкой строки кода; награда Версами — проводка с
  `op_id = promo:{code_id}:{user}`, предмет — инвентарь с `source = promo`; всё в одной транзакции,
  outbox `PromoRedeemed`.
- Лимит попыток ввода — по пользователю и по IP (Redis, fail-closed, `Retry-After`); ответ на неверный,
  просроченный и исчерпанный код одинаковый (404 `progression.promo_invalid`), чтобы не раскрывать состояние.
- Лимиты и сроки — конфиг; гостевые сессии не могут гасить коды.

### Своя аватарка
- Товар `custom_avatar` — покупается один раз (`UNIQUE(user_id)`), после покупки — право на заявки.
- Заявка `POST /v1/me/avatar` с файлом: progression передаёт файл media-pipeline (internal, scope `ugc.image`,
  один вызов, не цепочка), тот проверяет сигнатуру, размер и габариты (лимиты — конфиг), пересжимает,
  убирает EXIF, кладёт в S3 и создаёт **UGC-ассет со статусом `pending | approved | rejected`**.
  Progression хранит `avatar_requests(user_id, asset_id)`.
- **Модерация — в media-pipeline** (решение владельца): модератор одобряет или отклоняет в существующем
  разделе «UGC-изображения» админки (право `media.ugc.moderate`, у `moderator` и `admin`; код причины из
  списка в конфиге, аудит). Media-pipeline публикует `AssetModerated` (`asset_id`, `owner_user_id`, `purpose`,
  `status`, `reason_code`, монотонная версия), событие в outbox в одной транзакции с решением.
- Progression слушает `AssetModerated` (`purpose = avatar`): `approved` — аватар обновляется (идемпотентно
  по версии), `rejected` — прежний аватар остаётся. Notifications слушают то же событие и шлют уведомление
  с причиной (текст по `reason_code` — шаблон конфига). События `Avatar*` у progression не нужны.
- До одобрения виден прежний аватар; новая заявка отменяет предыдущую `pending`. Ассет `pending` и
  `rejected` недоступен по публичному префиксу; ссылка выдаётся только владельцу и модератору.

## Уточнения шага 0a (ревью)
- **Создание партии кодов и идемпотентность.** Коды показываются один раз; повтор с тем же `Idempotency-Key` не создаёт вторую партию и не раскрывает коды заново (409 `progression.codes_already_shown`). Потерянный ответ — отзыв партии и новая; это осознанный компромисс «коды не хранятся в открытом виде».
- **Потолок эмиссии.** Партия ограничена `promo.max_batch_verses` конфига: `count × max_uses × verses_amount` не больше потолка (иначе 422 `progression.promo_batch_too_large`).
- **Версия `AssetModerated`.** Решение может быть пересмотрено: админ снимает одобренное изображение (`approved → rejected`, «снятие UGC-изображения»), поэтому `version` растёт; `moderator_id` в событие не попадает (он только в аудите media-pipeline).
- **Приём изображений.** Конфиг media-pipeline задаёт для каждого назначения (`purpose`) лимиты и список сервисов-клиентов (progression — только `avatar`); владелец (`owner_user_id`) приходит от доверенного сервиса. Лимит размера multipart — на gateway и в приложении, превышение — 413.
- **Отписка от рассылки** — единственная ручка без входа: HMAC-токен, одинаковый ответ на чужой и неверный, лимит по IP.

## Рассмотренные альтернативы
- Хеш кода без ключа — перебор коротких кодов по утёкшей БД.
- Очередь аватарок в progression или в `social` — размазывает UGC-модерацию по сервисам; она принадлежит владельцу ассета (media-pipeline), `social` (5c) сможет её подтянуть через admin-API.
- Автомодерация изображений — вне объёма 5b.
