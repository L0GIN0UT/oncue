# 0027. Плановые наборы с периодом, режимы предпочтения, рекорды

- **Статус:** предложено (план этапа 3a, утверждён владельцем)
- **Дата:** 2026-10-16

## Контекст
Топ-32 — недельная сетка, одна на всех, как дейлик, но с периодом «неделя» и без
правильного ответа. «Больше/меньше» и марафон показывают личный рекорд и процентиль.

## Решение
- Наборы дня обобщаются до **наборов периода**: `ScheduledSource` с `period: day|week`,
  `day` набора — начало периода в зоне режима. Курация и календарь общие с дейликом.
- Сетка — источник `bracket` и matcher `preference` (любой выбор верен), очков нет
  (`scorer: none`). Статистика «согласны N %» хранится по паре `(winner, loser)` и
  считается только для пользователей; итог — событие `game.BracketCompleted`.
- Рекорды и гистограмма очков включаются флагом `features.records`, обновляются в
  транзакции завершения сессии, только для пользователей.

## Последствия
- Горячая строка статистики у популярной сетки приемлема в масштабе этапа; при росте —
  счётчики в Redis со сбросом в БД.
- Гости играют все режимы, но без рекордов и без влияния на статистику.
