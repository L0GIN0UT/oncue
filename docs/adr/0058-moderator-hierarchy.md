# 0058. Иерархия модераторов: санкция только в пределах своих прав

- **Статус:** черновик
- **Дата:** 2026-10-25
- **Уточняет:** [0052](0052-sanctions-and-enforcement.md)

## Контекст
ADR 0052 оставил модератору с `social.sanctions.manage` возможность санкционировать любого, включая admin («иерархии нет» — решение владельца, пункт бэклога). Теперь решение пересмотрено.

## Решение
- Санкция допустима, только если эффективные права цели ⊆ прав актёра (`target_perms <= actor_perms`, как `RoleMatrix.can_grant` в identity). Admin (все права) санкционирует любого, модератор — обычных игроков и равных себе, но не admin.
- Нарушение: 403 `social.sanction_target_outranks`. Проверка в `SanctionService._grant`, поэтому действует и для выдачи из admin-API, и для решения кейса (`SanctionGranter`). Снятие санкций правилом не затронуто.
- Права цели — локальная проекция `staff_perms_proj(user_id, perms[], version)` (миграция social `0006`) из `identity.UserRolesChanged` (полный снимок, запись только при большем `version`); `identity.UserDeleted` удаляет строку. Нет записи = пустой набор прав (обычный игрок).
- Права актёра берутся из его JWT (`actor_perms`).

## Последствия и ограничения
- Проекция отстаёт на время доставки события: повышенному пользователю модератор может успеть выдать санкцию до применения события; понижение действует с задержкой.
- Bootstrap-админ (команда `migrate` identity, `EnsureBootstrapAdmin`) получает роль через `User.change_roles`, то есть событие `UserRolesChanged` публикуется. Пока social не доставил его, админа в проекции нет и модератор может его санкционировать; потерянные до введения проекции события не воспроизводятся — для существующих staff-пользователей нужен повторный анонс прав (`announce_perms`) или ручной бэкфилл.
- Права цели сравниваются как множества: новое право у admin автоматически делает его «выше» модератора.

## Бэкфилл проекции при выкладке
Сотрудники, получившие роли до появления проекции, в неё не попадают (события не воспроизводятся). Перед включением правила на живой системе: выкатить identity с `GV_REANNOUNCE_STAFF_PERMS=true` — `migrate` публикует `UserRolesChanged` всем активным сотрудникам (`ReannounceStaffPerms`, потребители идемпотентны по `version`), затем флаг снять. Без бэкфилла модератор может санкционировать такого администратора.
