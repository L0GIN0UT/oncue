# 0043. Валюта «Версы»: append-only журнал, баланс в той же транзакции

- **Статус:** предложен (черновик; решения владельца — 2026-10-23). Зона повышенной безопасности
- **Дата:** 2026-10-23

## Контекст
Progression ведёт внутриигровую валюту. В 5a — только начисление (соло-раунд, дейлик, дуэль, party,
топ недели, итог сезона, задания, колесо, ручная выдача), траты появятся в 5b (магазин, паки,
промокоды). Ошибка здесь — деньги игроков: двойное начисление, отрицательный баланс, обход потолка.

## Решение
- **`currency_ledger` — append-only**, `UNIQUE(op_id)`, суммы целые (Версы, не дроби), знак
  по типу проводки. UPDATE и DELETE журнала запрещены (отсутствие прав у роли сервиса + триггер).
- **`op_id` вычисляется из предмета операции**, не из `event_id`:
  `game.session:{id}:verse`, `match:{id}:{user}:verse`, `wheel:{user}:{day}`,
  `season:{season}:{user}`, `admin:{Idempotency-Key}`. Повтор события с новым `event_id`
  не создаёт вторую проводку.
- **Баланс `balances(user_id, bucket)`** обновляется в той же транзакции через
  `SELECT … FOR UPDATE`, `CHECK (amount >= 0)`; там же пишется outbox
  (`CurrencyCredited`/`CurrencyDebited`). Асинхронной проекции баланса нет.
- **`bucket`** (`earned`/`paid`) есть с 5a; `paid` появится в 5b. За уровни Версы не даются.
- **Потолок с соло** (50/сутки) — дневной счётчик под блокировкой строки в той же транзакции;
  день по `finished_at`.
- **Сторно** — проводка с `reversal_of`; только админ с правом `progression.ledger.reverse` и
  причиной. Если баланс ушёл бы ниже нуля — 409 (решение за владельцем).
- **Ручная выдача** — право `progression.ledger.grant`, обязательная причина, лимит суммы на
  операцию и в сутки (конфиг), `Idempotency-Key`, `actor_id` в событии и аудите.
- **Сверка:** периодическая задача «сумма журнала = баланс», метрика и алерт.
- Награды топа недели и сезона — по сетке мест 1, 2, 3, 4–10, 11–100, 101–1000, суммы в конфиге
  ladder-а. Для сезона нужны места игроков: см. событие `rating.SeasonStandingsFinalized`
  ([план](../plans/stage-5.md), шаг 0a); топ недели — топ-100 (решение владельца), разряд 101–1000 только у сезона.
- Покупка Версов за деньги: паки только в 5b, продажа включается вместе с `billing.enabled`
  (сейчас `false`, паки скрыты).

## Уточнения реализации P1 (2026-10-23)
- **Защита журнала:** триггеры `BEFORE UPDATE OR DELETE` и `BEFORE TRUNCATE` в миграции `0002`. Остаточный риск: роль сервиса владеет таблицами и может отключить триггер. Разделение ролей (владелец миграций и рабочая роль с `SELECT, INSERT`) требует правки `infra/compose/postgres/10-service-databases.sh` и окружений — решение владельца, до него риск принят и отмечен в отчёте этапа.
- **Откат `0002`** прерывается ошибкой, если в журналах есть проводки.
- **Ключ награды сезона** — `season:{season_id}:{user}`: `season_id` уникален между ladder-ами. Недели — `weekly_top:{ladder}:{week_start}:{user}`.
- **Сверка** журнала с балансом — периодическая задача `progression.ledger.reconcile` (read-only транзакция, `statement_timeout`); инкрементальная версия — при росте журнала (вместе с партиционированием, этап 7).

## Уточнения реализации P3 (admin-API)
- **Бакет ручной выдачи** — только `earned`; `paid` — с 5b вместе с billing.
- **Суточный лимит выдач** (`admin.grant_max_per_user_day`, сутки в `config.timezone`) считает и **сторнированные** выдачи — защита от цикла «выдача → сторно → выдача».
- **Сторно** — только кредитов журнала Версов; дебеты (покупки 5b), сторно и журнал опыта → 409 `progression.not_reversible`.
- **`source_ref`** проводок админа — id записи `admin_actions`; причина (свободный текст) живёт только в аудите и не попадает в журнал и события. Аудит append-only (триггеры).
- **Публикация конфига** привязана к `body_sha256` черновика (иначе 409 `progression.draft_changed`).

## Рассмотренные альтернативы
- **Баланс как асинхронная проекция** — ответ спина показал бы старый баланс; в 5b — гонка списаний.
- **Event sourcing без таблицы баланса** — дорогое чтение на каждый запрос профиля.
- **Дробные суммы** — накопление ошибок округления, лишняя сложность.

## Последствия
- Сверка и алерт на расхождение обязательны до включения трат (5b).
- Отставание допустимо только у начислений от события (SLO лага consumer ≤ 30 с, метрика
  `gv_progression_consumer_lag`); баланс внутри операции согласован всегда.
- Миграции — через `review-migration`; в отчёте этапа: «требуется ручная проверка владельцем».
