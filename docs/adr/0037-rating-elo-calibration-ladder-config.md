# 0037. Рейтинг: Эло дуэли, калибровка, ladder-ы и звания — конфиг rating

- **Статус:** принято (решения владельца 4b, 2026-10-23); реализуется в 4b (поток G)
- **Дата:** 2026-10-23
- **Заменяет в плане этапа 4:** D15 в части попарного Эло для party (рейтинг только у дуэли)

## Контекст
План этапа 4 (D15) предполагал попарный Эло и для party. Владелец 2026-10-23 решил: рейтинг
есть только у дуэли 1×1, party — режим без рейтинга. Ladder-ов два — `music` и `film`
(ladder = домен). Формат ответа («классика» — ввод названия, «лайт» — 4 варианта) входит в
рейтинг, но не создаёт отдельный ladder.

## Решение
- **Ladder = домен.** Рейтинг общий на домен и сезон: `Rating(user, ladder, season)`. Формат
  очереди (`classic | lite`) влияет только на множитель дельты `elo.format_multiplier`
  (по умолчанию `classic` 1,0, `lite` 0,8).
- **Эло дуэли** (стандартный): `E = 1 / (1 + 10^((R_соперника − R) / scale))`,
  `delta = round(K × format_multiplier × (S − E))`, `S` = 1 / 0,5 / 0. Победа над сильным даёт
  больше, поражение от сильного снимает меньше. У каждого игрока свой `K`: `k_calibrating`
  в первых `calibration.matches` матчах (по умолчанию 10), затем `k`; сумма дельт пары поэтому
  не обязана быть нулевой. Старт — `elo.start` (1000).
- **Выход и сдача:** поражение по Эло плюс `elo.leaver_penalty` (по умолчанию −10) тому, кто
  вышел или сдался; сопернику — обычная победа. Срыв отсчёта штрафа не даёт. Матч,
  прерванный по вине сервера (`aborted`), рейтинг не меняет.
- **Калибровка:** пока `matches_played < calibration.matches`, звание скрыто
  (`hide_tier`), клиент видит «осталось N матчей»; рейтинг считается и используется
  подбором. API rating в калибровке отдаёт `rating = null`, `tier = null`.
- **Звания:** упорядоченный список `tiers[{key, family, step, title_key, below}]`, `below` —
  строгая верхняя граница, у высшего — `null`. Дефолт сидов: все звания, кроме высшего, по 3
  ступени с шагом 100: Железо (<400, <500, <600), Медь (<700…<900), Бронза (<1000…<1200),
  Серебро (до 1500), Золото (до 1800), Платина (до 2100); Алмаз ≥ 2100 без градации.
- **Конфиг ladder-а** — версионируемый документ по `contracts/rating/ladder.v1.json`: Эло,
  калибровка, звания, подбор, сезон, топ недели, лидерборд. Источник — YAML-сиды
  `seeds/rating/ladders` и admin-API rating (черновик → публикация → откат новой версией).
  Значений параметров в коде нет.
- **События:** `rating.rating.v1` — `RatingChanged`, `LadderPublished`, `SeasonStarted`,
  `SeasonFinished`, `WeeklyTopFinalized`. `RatingChanged.aggregate_id` = `user_id`, `version`
  монотонна по `(user_id, ladder)`. game проверяет `session.ladder` по проекции ключей из
  `LadderPublished`; match берёт окна подбора из `LadderPublished.matchmaking` и рейтинг из
  `RatingChanged` — синхронных вызовов rating нет.
- **Формат матча** доезжает до rating необязательным полем `queue_format` в
  `MatchStarted`/`MatchFinished` (`null` вне очереди).
- Рейтинговый матч — только дуэль из очереди; `POST /rooms` отвечает 403
  `match.ranked_forbidden` для `ranked`-шаблонов.

## Последствия
- Правка баланса — публикация новой версии конфига, без релиза кода.
- Рейтинг не ограничен снизу: пол не задан решением владельца (при необходимости — новое
  поле конфига).
- Идемпотентность: `processed_matches` по `match_id` поверх inbox; один матч — одна запись
  истории на игрока.
