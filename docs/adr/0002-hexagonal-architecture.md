# 0002. Гексагональная архитектура внутри сервиса

- **Статус:** принято
- **Дата:** 2026-10-07

## Контекст
Нужны тестируемость без инфраструктуры, замена адаптеров (провайдеры, платёжки, брокеры) без правки логики и единообразие 16 сервисов.

## Решение
Слои domain → application (use-cases + порты) → infrastructure/api. Зависимости только внутрь, проверяются `import-linter` в CI. DI через `container.py`.

## Альтернативы
- «Толстые» FastAPI-роутеры с ORM: быстро, но логика смешана с IO и плохо тестируется.
- Полный DDD с CQRS/Event Sourcing везде: избыточно. Event sourcing не нужен — достаточно outbox.

## Последствия
- (+) Unit-тесты домена без БД; SOLID обеспечивается структурой, а не дисциплиной.
- (−) Больше файлов и маппинга DTO. Компенсируется шаблоном сервиса.
