# 0057. Цепочка поставки образов: digest-пиннинг и блокировка trivy по CRITICAL

- **Статус:** черновик
- **Дата:** 2026-10-25
- **Уточняет:** [0022](0022-image-scan-reporting-not-gating.md)

## Контекст
ADR 0022 сделал скан образов отчётным: на плавающем теге `python:3.13-slim` любая новая исправимая CVE базового образа красила весь пайплайн. Условие возврата блокировки — закрепить базовые образы и включить Dependabot на них.

## Решение
- Базовые образы Dockerfile (`python`, `node`, `uv`) закреплены `tag@sha256:digest`; Dependabot (`docker`, `/infra/docker`) обновляет digest. Образы compose (`/infra/compose`) — Dependabot `docker-compose`. Centrifugo закреплён точной версией `v6.9.7` вместо плавающего `v6`.
- trivy в CI: отчётный проход `CRITICAL,HIGH` (`exit-code: 0`, как в 0022) и блокирующий проход `CRITICAL` (`exit-code: 1`, `ignore-unfixed`). HIGH остаётся отчётным.
- SARIF сохраняется артефактом job (`trivy-<service>`), а не выгружается в Code Scanning: не требует включённого GitHub Advanced Security. Выгрузка в Security — отдельное решение при включении.

## Последствия
- Новая исправимая CRITICAL в закреплённой базе красит сборку, пока не придёт PR Dependabot с новым digest. Это сознательный обмен: CRITICAL редки, а обновление базы — один merge.
- Образы стали воспроизводимыми; обновление базы — явное изменение в git.
- Зеркало образов под своим контролем не делаем: нужен внешний registry, остаётся на выкладку (этап 7).
