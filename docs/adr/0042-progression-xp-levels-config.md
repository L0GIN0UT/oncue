# 0042. Опыт и уровни: журнал проводок, уровень по версионируемому конфигу

- **Статус:** предложен (черновик; решения владельца по формулам — 2026-10-23)
- **Дата:** 2026-10-23

## Контекст
Опыт начисляется из четырёх источников (соло-раунд, дейлик, дуэль, party) событиями
`GameFinished`, `DailyCompleted`, `MatchFinished`. События приходят повторно и вне порядка;
формулы, потолки и пороги уровней меняет админ. Нужно, чтобы одно событие всегда давало один и
тот же опыт, а смена конфига не пересчитывала прошлое.

## Решение
- **Опыт — сумма проводок `xp_ledger`** (append-only, `UNIQUE(op_id)`). Накопленный опыт и
  `max_level` лежат в `progress(user_id)` (один уровень и один опыт на игрока, без деления по доменам; серия дейлика — отдельно, по доменам), обновляются в той же транзакции, что и проводка.
- **Опыт за участие, не за результат**: рейтинг на опыт не влияет, ranked и кастом равны. Суммы
  (соло-раунд, дейлик, дуэль, party по месту, первая победа дня), потолок с соло и множители —
  в конфиге `progression` (схема `contracts/progression/progression_config.v1.json`).
- **Уровни:** 100, порог уровня `n` = `base + step·n` (по умолчанию 500 + 20·n), параметры — в
  конфиге. Уровень вычисляется по порогам версии конфига и **не понижается** (`max_level`).
- **Сумма начисления — чистая функция** `(событие, версия конфига на finished_at, дневные счётчики)`.
  Версия конфига фиксируется в проводке (`config_version`), пересчёта задним числом нет.
- **Сутки** — по `progression.timezone` (как у дейлика), день берётся из `finished_at` события, а не
  из времени обработки: повтор даёт тот же результат.
- **Идемпотентность:** `op_id` вычисляется из предмета (`game.session:{id}:xp`,
  `match:{id}:{user}:xp`), поверх inbox по `(event_id, user_id)`.
- **Дейлик** награждается только по `DailyCompleted`; `GameFinished` с `day != null` опыт за раунды
  не даёт. Серию дейлика progression ведёт сам по `day` (в событии серии нет).
- **Антиабьюз:** бонус за победу и первую победу дня — при сыгранных ≥ `min_rounds_ratio` раундов
  (конфиг); досрочный выход и `aborted` — 0; `tech_win` — участие без бонуса за победу.
- **Гости** (`user_id = null`) пропускаются, после регистрации задним числом не начисляются.

## Уточнения реализации P1 (2026-10-23)
- **Версия конфига — по времени события:** опубликованная версия с наибольшим `published_at <= finished_at` (у дейлика и недели/сезона времени в payload нет — берётся `occurred_at` конверта); раньше первой публикации — самая ранняя. Повторная или запоздалая обработка не пересчитывает суммы по новым значениям.
- **Антиабьюз (R5, расширение):** `forfeit`, `left`, `aborted` и `tech_loss` дают 0 опыта и 0 Версов; `tech_win` — участие без бонуса за победу. Бонусы за результат (победа, первая победа дня, бонус и Версы за место в party) выдаются при `сыграно ≥ min_rounds_ratio`; матч без раундов их не получает. Раунд `void` не считается сыгранным; раунд выигран при очках строго больше всех остальных и больше 0.
- **Дейлик вне потолка:** `solo_daily_cap` ограничивает только соло-раунды; награда дейлика (`DailyCompleted`) в потолок не входит. Онлайн-опыт (дуэль, party) потолка не имеет - решение владельца: опыт за матч - следствие участия, бонусы режет `min_rounds_ratio`. Онлайн-Версы - потолок `verses.online_daily_cap` (необязательное поле; нет поля - нет потолка; значение владельца 500): суточный счётчик `daily_counters.online_verses` суммирует Версы за дуэли и party (без наград недели/сезона, дейлика, колеса, заданий), обновляется под той же блокировкой `FOR UPDATE`, сутки - по `finished_at` в `timezone` конфига. Фарм вторым аккаунтом закрывает детектор win-trading (хвост [ADR 0038](0038-matchmaking-queues.md)), не потолок.
- **Нулевая отметка предмета (решение владельца):** если после потолка (соло или онлайн-Версов) сумма равна 0 и проводка не пишется, предмет (`op_id`) фиксируется строкой `accrual_marks` в той же транзакции. Повтор по тому же предмету (в т.ч. с новым `event_id` и после повышения потолка) проверяет «`op_id` в журнале или в `accrual_marks`» до расчёта и не начисляет задним числом. Отметки не удаляются кодом.
- **Поздний `DailyCompleted`** (день раньше последнего в серии): серия не меняется, награда — как за серию 1.
- **Буст:** множитель применяется к опыту матча и к бонусу первой победы, `max(base, floor(base·mult))`, сверху ограничен границей схемы.
- Ничья и `tech_win` в дуэли получают Версы как проигравший (`duel.loss`); в party `tech_win` Версов не получает.

## Рассмотренные альтернативы
- **Опыт за результат** (очки, рейтинг) — отвергнуто решением владельца: награда за участие.
- **Пересчёт при смене конфига** — уровни прыгают назад и вперёд, награды выдаются повторно.
- **Счётчик без журнала** — нет аудита, повторная обработка неотличима от новой.

## Последствия
- Таблица версий конфига с `effective_from`; валидатор требует монотонные пороги.
- Поздний `MatchFinished` после смены сезона начисляется как обычно: опыт с сезоном не связан.
- Смена формулы действует только на новые события.
