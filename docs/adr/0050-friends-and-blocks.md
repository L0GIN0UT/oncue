# 0050. Друзья, блокировки, presence и приглашения

- **Статус:** предложен (черновик; решения владельца — 2026-10-24)
- **Дата:** 2026-10-24

## Контекст
5c добавляет друзей: заявки по нику и коду, блокировки, онлайн-статус и приглашение в комнату. Список друзей
виден только владельцу. Общего presence в системе нет (в Centrifugo он выключен).

## Решение
- **Дружба** — пара `(a, b)` с `a < b`, одна строка на пару; заявка — отдельная таблица, один pending на пару.
  Встречные заявки сливаются в одну дружбу. Лимиты (исходящих заявок в сутки, друзей всего) — конфиг social.
- **Код добавления** — 8 символов алфавита кодов комнат, хранится в `friend_codes`, регенерируется (старый код
  даёт 404). Перебор кодов и ников ограничен лимитом по пользователю и IP, fail-closed.
- **Блокировка** рвёт дружбу и заявки, скрывает профиль и запрещает заявки и приглашения в обе стороны.
  Ответы для заблокированного и скрытого профиля одинаковы (нет перечисления).
- **Приватность:** `profile_public`, `stats_public`, `friend_requests = all|none` («кто может звать в друзья»); история матчей всегда только владельцу.
- **Presence живёт в social:** heartbeat фронта пишет ключ с TTL в Redis, статус «в матче» — проекция из
  `MatchStarted`/`MatchFinished`. Статусы видят только друзья. Centrifugo presence не включаем.
- **Приглашение в комнату** — событие `RoomInviteSent` (код комнаты) → notifications (`room_invite`, in-app и
  realtime). Код не проверяется синхронно: проверка при входе в match. На приглашения — лимит.

## Рассмотренные альтернативы
- Presence Centrifugo — раскрывает наблюдателей и не знает про «в матче» (хвост 4b).
- Заявки как две строки на пару — гонки встречных заявок.

## Принятый риск

Различие по времени ответа: неизвестный игрок и скрытый/заблокировавший отвечают за разное время. Перебор ограничен лимитом `code_attempts_per_hour` (по игроку и IP, fail-closed). Ник отправителя проверяется до поиска цели, чтобы 503 `profile_not_ready` не раскрывал существование адресата; лимит перебора тратится только на выполняемом запросе (повтор с тем же `Idempotency-Key` бюджет не уменьшает).

## Последствия
social получает зависимость Redis (`infra/services.toml` → `gv gen`). Новые события: `FriendRequested`,
`FriendAdded`, `FriendRemoved`, `UserBlocked`, `RoomInviteSent`.
