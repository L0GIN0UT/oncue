# 0021. S3-хранилище на VPS: SeaweedFS вместо MinIO

- **Статус:** принято
- **Дата:** 2026-10-12

## Контекст
Исходники медиа и ассеты загадок лежат в S3-совместимом хранилище; на VPS это был MinIO (`infra/compose/compose.infra.yml`). В сентябре 2026 MinIO удалил образы `minio/minio` и `minio/mc` с Docker Hub, community-сборки прекращены, репозиторий архивирован; из `quay.io` образ без авторизации тоже не отдаётся. Следствия: в CI падали тесты media-pipeline (testcontainers не мог скачать образ) и e2e-смоук (compose не поднимал стек), а на VPS стек не поднялся бы на чистой машине.

Разбор при замене выявил два дефекта, которые e2e до этого не мог показать:
- бакеты в compose никто не создавал (`ensure_buckets()` нигде не вызывался);
- анонимное чтение префикса `a/` для gateway (ADR 0012) нигде не настраивалось;
- у media-pipeline в compose не было настроек `GV_S3__*`.

## Решение
- **Хранилище на VPS — SeaweedFS** (`chrislusf/seaweedfs`, Apache-2.0, активно развивается, один контейнер, S3 API). Версия закреплена тегом; параметры запуска — в `compose.infra.yml` с комментариями. Ключи доступа — из `.env` (`S3_ACCESS_KEY`, `S3_SECRET_KEY`, генерирует `gv dev secrets`) через `configs.content`; официальный entrypoint понижает права до пользователя `seaweed`.
- **Доступ gateway к ассетам — стандартная политика бакета S3** (`PutBucketPolicy`): анонимно разрешён только `s3:GetObject` на `arn:aws:s3:::<bucket ассетов>/a/*`. Запись, удаление, листинг и любые объекты вне `a/` — только по ключам. Политика переносима: AWS S3, SeaweedFS, MinIO понимают её одинаково. Встроенный STS-IAM SeaweedFS выключен (`-s3.iam=false`), идентичности — из конфига.
- **Бакеты и политику создаёт job `media-pipeline-migrate`**: в `ServiceDefinition` появился общий хук `prepare_resources`, его выполняет команда `migrate` после миграций БД (идемпотентно). Процессы сервиса ресурсы хранилища не создают.
- **Флаг `s3` в реестре сервисов** (`infra/services.toml`): сервис получает `GV_S3__*` и зависимость от `s3` в сгенерированном compose — без ветвлений по имени сервиса в шаблоне.
- **Наружу открыт только S3-порт.** SeaweedFS в одном контейнере поднимает master, filer, volume и S3; HTTP/gRPC master, filer и volume аутентификации не требуют и в обход ключей S3 дали бы доступ к сырым данным. Поэтому `-ip.bind=127.0.0.1` держит их на loopback внутри контейнера, а по сети `backend` доступен только S3 (`-s3.ip.bind=0.0.0.0`). REST-каталоги Iceberg и Lance выключены (`-s3.port.iceberg=0 -s3.port.lance=0`). Остаётся слушать на всех интерфейсах служебный gRPC-порт S3 (`s3.port+10000`, кэш IAM/политик) — он не публикуется на хост и доступен только другим контейнерам `backend`; на проде это закрывается сетевой политикой. Проверено на SeaweedFS 4.48: с хоста отвечает только S3 (403 без ключей), порты master/filer/volume — refused.
- **Тесты**: `gv_testkit` без `GV_TEST_S3_ENDPOINT` поднимает `moto_server` процессом (Docker не нужен). Совместимость кода с SeaweedFS проверена прогоном всех тестов media-pipeline против SeaweedFS 4.48 (227 тестов), политика — проверкой анонимных GET/PUT/DELETE/листинга.

## Последствия
- Код сервисов не изменился: работа идёт через S3 API, хранилище заменяемо (облачный S3, Garage) правкой compose.
- Каждый бакет SeaweedFS — отдельная коллекция томов; при множестве бакетов (как в тестах) нужен небольшой `-master.volumeSizeLimitMB`. На VPS бакетов два, тома — 256 МБ.
- Зависимость от внешнего реестра остаётся риском: на проде стоит держать зеркало образов под своим контролем (этап 7).
- Формат данных на диске у SeaweedFS свой: старый том `s3data` с данными MinIO SeaweedFS не прочитает и стартует с пустым хранилищем. Прод ещё не развёрнут, переносить нечего; при будущей миграции данные переливаются через S3 API (copy), а не подменой тома.

## Альтернативы
- **MinIO из quay.io** — образ без авторизации не отдаётся, обновлений безопасности нет.
- **Garage** — AGPL, требует отдельной инициализации раскладки кластера даже для одного узла.
- **RustFS** — до версии 1.0, недавние уязвимости.
- **Собирать MinIO из исходников** — поддержка чужого заброшенного форка своими силами.
