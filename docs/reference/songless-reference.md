## 1. Продукт

### 1.1. Суть
Сонглесс — русскоязычная веб-игра (музыкальный квиз): нужно угадать трек по первым секундам. Режимы бывают одиночные и соревновательные в реальном времени. Есть пользовательские плейлисты, прогрессия профиля, внутренняя валюта и косметика. Слоган: «Угадай трек по первым секундам».

### 1.2. Аудитория и позиционирование
- Только 18+: подтверждается при входе и при оплате [UI].
- Основной язык и каталог русскоязычные, зарубежная музыка тоже есть. Источник музыки — Яндекс Музыка.
- Каналы: веб, PWA и Telegram Mini App (официальный бот). Отдельный сценарий сделан для стримеров Twitch.
- Проект делает один разработчик (`exbn`, профиль id 1). Сервера оплачиваются донатами и продажей согл.

### 1.3. Глоссарий

| Термин | Значение |
|---|---|
| Дейлик | Ежедневный режим: 5 одинаковых для всех треков в сутки |
| Соглы | Внутренняя валюта, тратится только на косметику и «возможности» |
| Опыт / уровень | Прогрессия профиля, открывает функции |
| Формат | Способ угадывания: Классика, Лайт, Реверс, Эмодзи, Картинки |
| Уровень (трека) | Попытка с отрывком определённой длины |
| Битва | Матч на 3 и более игроков |
| Дуэль | Матч 1 на 1 |
| Лобби / комната | Кастомная комната с кодом из 8 символов |
| Звание / тир | Ранг по Эло: от Железа до Алмаза |
| Порядочность / Вежливость | Скрытые шкалы поведения, от 0 до 12 000 |
| Плашка | Декоративный фон под ником в списках |
| Эмоции (throws) | Предметы, которые кидают в игроков в матче: помидор, роза, поцелуй, хлопушка |
| Серия (streak) | Сколько дней подряд пройден дейлик |
| Мастерство артиста | Бейдж за 50 и более угаданных треков одного артиста |

## 2. Архитектура и технологии

| Компонент | Реализация |
|---|---|
| Фронтенд | Next.js (App Router, React Server Components, Turbopack), React, Tailwind CSS, Framer Motion. Тема только тёмная, шрифт Inter |
| Рендеринг | Публичные страницы (главная, каталоги, артисты, плейлисты, FAQ, юридические) рендерятся на сервере ради SEO. Игровые страницы являются клиентскими |
| Бэкенд | Монолитный REST API на том же домене, `/api/*`, JSON. Сессия хранится в cookie (без Bearer-токенов в клиенте) [вывод] |
| Realtime | Centrifugo: websocket с запасным транспортом `/connection/http_stream`. Токен выдаёт `/api/centrifugo/token` |
| Медиахранилище | `media.songless.ru` (аватары, шапки, фоны, обложки) |
| Внешние данные | Яндекс Музыка (метаданные, обложки, слушатели, похожие артисты), Shikimori (аниме), IGDB (игры) |
| Платежи | Внешний платёжный сервис: редирект с формой POST, карта или СБП, чек на e-mail |
| Мониторинг | Sentry-подобный SDK (`captureConsoleIntegration`, `/api/monitoring` как tunnel) и свои события `/api/stats/*` |
| Аналитика | Внешняя аналитика (вероятно, Яндекс Метрика: `reportYmOpen`) включается только с согласия на cookie |
| PWA | `manifest.webmanifest`: standalone, portrait, иконки 192 и 512 (есть maskable). Запуск из PWA отслеживается |
| Деплой | Версия сборки передаётся в `data-dpl-id` и `/api/system/status.version`. Клиент сверяет версию и предлагает обновиться [вывод] |

**Принцип «сервер — источник истины»:** клиент не знает правильных ответов. Он получает аудио по токенам и отправляет ответы на сервер. Состояние игры можно восстановить по `matchToken`.

## 4. Авторизация и аккаунты

### 4.1. Способы входа

| Способ | Детали |
|---|---|
| Яндекс ID | Основной способ. `GET /api/auth/yandex_ya?redirect=…` (OAuth) |
| Twitch | `GET /api/auth/twitch?redirect=…`. **Работает до конца октября 2026**, дальше пользователей просят привязать Яндекс ID (закреплённое уведомление `link_yandex`) |
| Telegram | Внутри Mini App: `POST /api/auth/telegram {initData}`, проверка `POST /api/tg/verify`. В Telegram нельзя пополнять баланс. Если приложение открыто не через официального бота, показывается предупреждение |

Вход всегда сопровождается чекбоксом: «Принимаю условия Пользовательского соглашения, ознакомлен с Политикой конфиденциальности; подтверждаю, что мне исполнилось 18 лет». Если сервер возвращает `needsTerms`, клиент шлёт `POST /api/user/consent {terms:true}`.

### 4.2. Онбординг
- `GET /api/user/onboarding` возвращает `needsOnboarding`, `suggestedNick`, `currentAvatarPreset`, `defaults`.
- `POST /api/user/onboarding {nick, avatarPreset}` сохраняет выбор.
- Затем запускается тур по сайту (событие `SITE_TOUR_EVENT`): Главная (дейлик, лента) → Соло (плейлисты, Топ-32, другие игры) → Онлайн (рейтинговая игра, настройки подбора, гонка недели, кастомные лобби) → Профиль (карточка, рейтинг) → Магазин (примерка, соглы).
- Отдельно показывается окно «Знакомы с обновлением?» с предложением короткого тура.

### 4.3. Привязки и объединение аккаунтов
- Привязать Яндекс: `GET /api/auth/yandex_ya/link`. Возможные ошибки: «уже привязан к другому аккаунту», «к аккаунту уже привязан другой Яндекс ID».
- Привязать Twitch: `/api/auth/twitch/link` и `/link-info`. Если у этого Twitch уже есть отдельный аккаунт, запускается слияние (`/api/auth/twitch/merge`).
- Слияние с Telegram:
  1. В Mini App вызывается `POST /api/auth/telegram/merge-init`, сервер возвращает `url`.
  2. В браузере открывается `/merge`.
  3. Вызывается `POST /api/auth/telegram/merge-claim {token}`.
  4. Вызывается `POST /api/user/telegram-link/merge {useStats}`.
- **Правила слияния** [UI]:
  - пользователь выбирает, чья статистика останется (очки, игры, угаданные треки, рейтинг дуэлей, победы и поражения);
  - история игр, плейлисты, достижения, друзья и всё купленное переносятся с обоих аккаунтов;
  - ник и аватар остаются с выбранного аккаунта;
  - заработанные соглы второго аккаунта сгорают, купленные сохраняются;
  - отменить слияние нельзя.
- Источник ника и аватара выбирается через `GET/PUT /api/user/identity-source`. Ник подтягивается от провайдера при каждом входе, если не куплен свой.

### 4.4. Выход и удаление
- `POST /api/auth/logout` и `POST /api/auth/logout-all` (выход везде: телефон, компьютер, Telegram).
- `POST /api/user/delete {initData?, confirmPaidLoss?}`:
  - стираются ник, аватар, статус, контакты и все привязки;
  - войти снова тем же способом нельзя;
  - если на счету есть купленные соглы, нужно отдельное подтверждение их потери (`paidBalance`);
  - перед удалением нужно заново войти (re-auth);
  - из Telegram удаление делается через бота.

### 5.3. Главная (`/`)
1. **Ежедневный**: большая карточка, ссылка на `/play?mode=daily`.
2. **Лента дейлика**: последние сыгравшие (аватар и счёт от 0 до 30), обновление в реальном времени. `GET /api/daily/feed` возвращает `items[{userId, username, photoUrl, avatarFrame, score}]`.
3. **Популярные плейлисты**: карусель и ссылка «Все плейлисты».
4. **Новые релизы**: что добавили в каталог игроки (`GET /api/home/catalog-releases`). Карточка релиза содержит обложку, название, артистов, «добавил {ник}», число треков в игре, ссылку на Яндекс Музыку и кнопку «В плейлист».
5. **Новости проекта**: статичная карусель в коде.

### 5.4. Хаб «Соло» (`/single`)
- Карточки: Ежедневный (таймер до следующего, архив за 29 дней), Плейлисты (топ-3 по играм за сутки), Топ-32 (таймер до конца недели), «Другие одиночные игры» (Марафон, Больше/Меньше, Случайный), заглушка «Дальше / больше».
- Блок «Топ по количеству игр за сутки» показывает популярных артистов.

### 5.5. Хаб «Онлайн» (`/battle`)
- Кнопки «Классика» и «Лайт» запускают рейтинговый подбор. На кнопках виден счётчик игроков в очереди (`/api/duel/matchmaking/pool`).
- Шестерёнка открывает настройки подбора (язык, жанр, эпоха).
- Блок «Сезон N · осталось X д.»: текущее звание, прогресс до следующего, калибровка.
- «Топ недели» / «Топ сезона» (12 строк).
- «Лента игр» (`/api/battle/recent`).
- Ссылки на «Кастомные лобби» и «Со стримом» (последний на ремонте).

## 6. Игровой движок (соло)

### 6.1. Форматы ответа

| Формат | Флаг в URL | Аудио | Ввод | Подсчёт очков |
|---|---|---|---|---|
| Классика | — | Отрывок с начала трека, длина растёт по уровням | Текст с автокомплитом | По уровню |
| Лайт | `light=1` | Отрывок | 4 варианта, 1 клик | По скорости [сервер] |
| Реверс | `reverse=1` | Отрывок задом наперёд | Текст | По уровню (свои уровни) |
| Эмодзи | плейлист `kind=emoji` | Без звука | Текст | По номеру попытки |
| Картинки | плейлист `kind=picture` | 15 с | 4 картинки (аниме или игры) | По скорости [UI] |

### 6.2. Уровни и очки [код `LEVELS`, `getLevels(isReverse, isEmoji)`]

**Классика и Лайт:**

| Уровень | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| Отрывок, с | 0,5 | 1 | 2 | 4 | 8 | 15 |
| Очки | 6 | 5 | 4 | 3 | 2 | 1 |

**Реверс:**

| Уровень | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| Отрывок, с | 8 | 8 | 8 | 15 | 15 | 15 |
| Очки | 5 | 5 | 5 | 3 | 3 | 3 |

Пропуск в Реверсе с уровней 1–3 сразу ведёт на уровень 4 (`nextSkipLevel`).

**Эмодзи:**

| Попытка | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| Очки | 2 | 1 | 1 | 1 | 1 | 1 |

**Прочие правила:**
- Константы: `MAX_SCORE_PER_TRACK=6`, `MAX_TOTAL_SCORE=30`, `TRACKS_PER_DAY=5`.
- **Частичный ответ:** если угадан только исполнитель, начисляется часть очков (`artistMatch`, `artistScoreAwarded`, «Исполнитель угадан (+N)»), но трек не считается угаданным.
- **Как засчитывается ответ** [UI]: достаточно точного названия песни, даже без исполнителя. Подсказки берутся из `/api/autocomplete` (debounce 200 мс). Строка нормализуется: убираются знаки препинания, `ё` → `е`, схлопываются пробелы, `&` выравнивается.
- В коде есть словарь алиасов артистов: «оксимирон» → Мирон Фёдоров, «нойз мс» → Иван Алексеев, «монеточка» → Елизавета Гырдымова, «фейс», «би 2», «литл биг», «ногу свело», «аквариум»/«борис гребенщиков», «машина времени»/«андрей макаревич», «текиладжаззз», «илья прусикин» и другие.
- Если в плейлисте ограничен набор артистов, автокомплит подсказывает только их (`allowedArtists`).

### 6.3. Жизненный цикл соло-игры

```
POST /api/game/start   {mode, genre, language, yearFrom, yearTo, playlistId, allowedArtistIds,
                        matchToken?, isLight?, isReverse?, trackCount, seriesId, date?}
   → {matchToken, tracks[], LEVELS, score, … }  (если передан старый matchToken, игра возобновляется)
loop по трекам (expectedIndex = индекс текущего трека):
   POST /api/game/audio         {matchToken}                       → {trackIndex, level, initUrl, segUrls, packUrl, trackId}
   Классика/Реверс/Эмодзи:
     POST /api/game/guess       {matchToken, guess, expectedIndex}  → {correct, artistMatch, score, currentLevel, track?, stats?}
     POST /api/game/skip-level  {matchToken, expectedIndex, toLevel} → {currentLevel, audio, guessHistory, skipped}
     POST /api/game/skip        {matchToken, expectedIndex}         → сдаться на треке
   Лайт/Картинки:
     POST /api/game/light-options {matchToken, expectedIndex}       → {options[], scoreStartedAt, revealedAt, serverNow}
     POST /api/game/light-play    {matchToken, expectedIndex}       → старт таймера очков на сервере
     POST /api/game/guess         {matchToken, chosenToken, expectedIndex} → {correct, correctToken, chosenTrackId, score}
   GET/POST /api/game/next      {matchToken, expectedIndex}         → {index, tracks}  (для Марафона)
POST /api/game/finish  {matchToken} → {soglyAwarded, date, genre, isEmoji, isPicture, emojiSeries, trackLimit}
POST /api/game/share-card {mode, playlistId, artistName, predictions[]} → PNG (blob)
```

**Подробности:**
- `matchToken` хранится в `localStorage` под ключом `match_token_{хэш параметров}`, поэтому после перезагрузки игра продолжается.
- У каждого трека есть статус: `playing`, `correct`, `skipped` или `failed` [вывод]. Хранится и `guessedAtLevel`, то есть на какой попытке угадан трек.
- **Обработка ошибок** [код]:

| Код | Сообщение | Действие клиента |
|---|---|---|
| 429 | «Слишком быстро» | Rate-limit, ничего не делать |
| 409 | «Игра рассинхронизировалась» | Подтянуть снапшот с сервера |
| 404 / 403 | «Сессия истекла — игра начата заново» | Сбросить токен, начать заново |
| сеть | «Связь прервалась — состояние игры обновлено» | Ресинк |

- Если звук не загрузился: «Этот трек сейчас недоступен — пропустите его». Есть подсказки про AdBlock и VPN («Видите 404? Попробуйте отключить VPN»).
- **Экран результатов** показывает:
  - очки;
  - результат по каждому треку (на какой попытке и за сколько секунд, пропуск, «угадан исполнитель»);
  - заработанные соглы;
  - лайк или дизлайк плейлиста;
  - «Следующий раунд» (для эмодзи-серий);
  - «Поделиться карточкой»: собрать картинку и скопировать, скачать или отправить в чат;
  - для гостя предложение войти: «результат и соглы за него останутся в профиле».
- При показе ответа можно открыть карточку трека: послушать, открыть в Яндекс Музыке, увидеть, кто его предложил (для дейлика).
- В конце каждого трека выводится случайный мем: в коде 74 картинки, `MEME_COUNT=74`.
- Перед игрой встречаются предупреждения: «Среди песен встречаются материалы исполнителей, признанных иноагентами, и треки с возрастным ограничением 18+».

## 7. Одиночные режимы

### 7.1. Ежедневный (`mode=daily`)

| Параметр | Значение |
|---|---|
| Треков | 5 |
| Формат | Классика |
| Обновление | 00:00 МСК (Europe/Moscow) |
| Попыток в сутки | 1 |
| Максимум очков | 30 |
| Подборка | Автоматическая, плюс треки, предложенные победителем прогноза (поле «Предложил: {ник}») |

- **Статус дня** хранится отдельно для жанра и языка: `GET /api/user/daily-status?genre&lang` возвращает `matchToken, date, tracks[{guessedAtLevel, score, artistScoreAwarded}], predictions, predictionSubmitted` [вывод: в интерфейсе используются жанр по умолчанию и язык ru].
- **Лента дейлика:** `GET /api/daily/feed`, затем realtime-событие `daily_feed_row` с полями `{userId, username, score, …}`.
- **Серия:**
  - каждый день с пройденным дейликом добавляет +1;
  - если сегодня ещё не играл, видно «Серия сгорит сегодня» или «Сегодняшний дейлик не пройден — серия заморожена»;
  - есть лидерборд «Серии»; пустое состояние: «Серия начинается с одного угаданного дейли».
- **Прогноз:**
  - после игры под каждым треком есть ползунок от 0 до 100 %: «сколько игроков его отгадали»;
  - `POST /api/daily/prediction {date, genre, language, predictions:number[5]}`;
  - пока игрок не вошёл, прогноз хранится в localStorage (`daily_prediction_{date}_{genre}_{lang}` и флаг `_submitted`) и отправляется автоматически после входа;
  - победитель дня (самый точный прогноз) получает уведомление «Соглы на балансе, выберите 3 трека» или «предложи трек дня»;
  - [сервер]: метрика точности, вероятно, сумма |прогноз − факт|.
- **Предложение треков дня** (приз победителю прогноза):
  - `POST /api/user/prizes/check {track}` возвращает вердикт: «угадают многие», «угадают не все — можно оставить», «угадают немногие — лучше заменить» или «почти никто не узнает»;
  - подходят только русские треки из каталога;
  - `POST /api/user/prizes/submit {tracks:[3]}`, затем «Принято»;
  - `GET /api/notifications` в ответе содержит флаг `prizeAvailable`.
- **Архив (`mode=archive&date=YYYY-MM-DD`):**
  - доступны последние 29 дней;
  - `GET /api/daily-archive/stats?date=` возвращает `{stats:[{trackIndex, percent}]}`, то есть процент угадавших по каждому треку;
  - если день вне диапазона: «Этот день уже недоступен в архиве».
  - [вывод] Архивные игры влияют на опыт, но не на серию и не на ленту.

### 7.2. Плейлисты (`mode=playlist&id=…`)
- Длина партии (`trackCount`): 5 («Быстрая разминка»), 10 («Средняя партия»), 25 («Большая игра») или все треки. Если треков в плейлисте меньше, вариант отключается с подсказкой «В плейлисте всего N».
- Формат: Классика, Лайт или Реверс. Для музыкальных плейлистов есть ещё «Битва онлайн» (создаёт лобби с этим плейлистом).
- Эмодзи-плейлисты идут сериями: после партии можно продолжить «Следующий раунд» (`series`, `emojiSeries`).
- Треки выбираются случайно из плейлиста [вывод]. Сервер помнит, какие треки уже сыграны (`playlists/unique-tracks`).
- Если плейлист пройден, на нём появляется отметка «Пройден» (`isCompleted`).

### 7.3. Марафон (`mode=infinite`)
- Старт: `/artists` (выбор от 1 до 10 артистов) или страница артиста.
- Параметры: `artists=` (нормализованные имена через запятую), `lang=ru|en|mixed`, формат.
- По FAQ это 20 самых популярных треков артиста (на `/single`: «Угадай 20 треков любимого исполнителя»).
- Треки подгружаются по одному через `/api/game/next`. Пул ограничен `totalPoolSize`. Когда треки закончились, срабатывает `hasNoMoreTracks`.

### 7.4. Случайный (`mode=random`)
- 5 треков из выбранного жанра.

| Жанр (`genre`) | Описание | Языки |
|---|---|---|
| `mixed` | Все жанры, микс | ru, en |
| `hiphop` | Рэп, хип-хоп, R&B | ru, en |
| `pop` | Популярные хиты | ru, en |
| `rock` | Рок и альтернатива | ru, en |
| `indie` | Независимая сцена | ru, en |
| `electronic` | Электроника | ru, en |
| `shanson` | Шансон | только ru |

- Для русского хип-хопа есть выбор эпохи:

| Эпоха | Ключ | Годы |
|---|---|---|
| Все | `all` | — |
| Олдскул | `oldschool` | 1990–2012 |
| Золотая эра | `golden` | 2013–2018 |
| Новая школа | `newschool` | 2019–2026 |

- В URL передаются `yearFrom` и `yearTo`. Последний выбор жанра запоминается в localStorage.

### 7.5. Больше / Меньше (`/higher-lower`)
- Показываются два артиста с фото, нужно нажать на того, у кого **больше слушателей в месяц** (данные Яндекс Музыки).
- Категории: «Русские», «Зарубежные», «Микс».
- `POST /api/higher-lower/start {lang}` возвращает `{token, pair}`.
- `POST /api/higher-lower/guess {token, direction}` возвращает `{correct, rightListeners, gameOver, pair, score, personalBest, isNewRecord, percentile}`.
- Игра длится до первой ошибки. Показываются счёт, рекорд и процентиль «Лучше X % игроков».
- Недельное задание: набрать 10 очков.

### 7.6. Топ-32 (`/comparison`)
- Каждую неделю: с понедельника 00:00 МСК по воскресенье 23:59:59 МСК.
- `GET /api/comparison/active` возвращает `{comparison:{id, type:"curated", artistYandexId, startsAt, endsAt, artist{yandexId, name, avatarUrl}}}`.
- Сетка из 32 треков одного артиста. Стадии: 1/16 → 1/8 → 1/4 → полуфинал → финал.
- `GET /api/comparison/bracket` (нужен вход, иначе 401) возвращает `{comparisonId, bracket, next{roundIdx, pairIdx}, progress}`.
- `POST /api/comparison/vote {roundIdx, pairIdx, winnerTrackId}` записывает выбор в паре.
- Перед выбором можно послушать 15 секунд каждого трека (`/api/comparison/audio-token`). Есть «Альтернативный плеер», если встроенный не грузится.
- После выбора видно «Согласны с вашим выбором: X %» по голосам.
- `GET /api/comparison/bracket/full-stats` даёт полную статистику сетки, `GET /api/comparison/bracket/winner-share` собирает карточку победителя для шаринга.
- Пустое состояние: «Сейчас нет активного топа. Загляните позже».
- Недельное задание: пройти Топ-32 (+50 согл).

## 8. Мультиплеер

### 8.1. Общие константы [код]

| Константа | Значение |
|---|---|
| `BATTLE_MAX_ATTEMPTS` | 3 попытки на уровень |
| `BATTLE_TRACK_COUNT_OPTIONS` | 6 / 12 / 24 (по умолчанию 6) |
| `BATTLE_ROUND_TIMER_OPTIONS` | 15 / 25 / 40 с (по умолчанию 25) |
| `BATTLE_PRE_MATCH_COUNTDOWN_SEC` | 3 |
| `BATTLE_ELO_CALIBRATION_MATCHES` | 10 |
| `BATTLE_DUEL_LEVELS` | L1: аудио 4 с, окно 20 с, 12 очков. L2: аудио 15 с, окно 30 с, 6 очков |
| `BATTLE_PARTY_LEVELS` | Аудио 15 с, окно 30 с, максимум 30 очков |
| `BATTLE_LITE_LEVELS` | Аудио 15 с, окно 20 с, максимум 20 очков |
| Мест в лобби | 6 (стандарт) или 32 (платная «возможность» или выдаётся вручную) |
| Код комнаты | 8 символов `[A-Z0-9]` (например `6GJ4PMRS`) [API] |

### 8.2. Рейтинговый подбор
- Две очереди: **Рейтинговая классика** (`/api/duel/matchmaking/*`) и **Рейтинговый лайт** (`/api/battle/lite-matchmaking/*`).
- `POST …/enter {language, genre, era}`: встать в очередь. Значения:
  - `language`: `ru`, `en` или `any`;
  - `genre`: `pop`, `hiphop`, `rock`, `indie`, `electronic`, `shanson` или `random`;
  - `era`: `oldschool`, `golden`, `newschool` или любая.
- `POST …/tick`: опрос, возвращает `{waiting, roomCode?, tierThresholds}`. Когда соперник найден:
  1. звучит сигнал;
  2. если вкладка скрыта, мигает заголовок;
  3. клиент переходит в `/battle/room/{roomCode}`.
- `POST …/leave`: выйти из очереди. `POST /api/duel/heartbeat`: подтверждение присутствия.
- `GET /api/duel/matchmaking/pool?…` показывает размер очередей: `{classic, lite, isBanned}`.
- **Ошибки:**
  - «Все арены заняты! Попробуйте позже»;
  - «Сначала закончите текущую игру» (`isActiveRoomConflict`);
  - «Рейтинговые игры временно закрыты» (санкция за поведение).
- Рейтинговая классика на практике идёт **1 на 1** (Дуэль), рейтинговый лайт на 2–6 игроков [API: в ленте лайт-матчи на 4 игроков].

### 8.3. Дуэль (Классика 1 на 1)
- На каждый трек два уровня:
  - **уровень 1:** отрывок 4 с, на ответ 20 с, 12 очков;
  - **уровень 2:** отрывок 15 с, на ответ 30 с, 6 очков.
- На уровень даётся 3 попытки, уровень можно пропустить.
- **Опережение:** если соперник угадал на уровне 1 раньше тебя, уровень 1 закрывается для обоих. Уровень 2 остаётся открытым.
- **Только исполнитель:** утешительные очки, трек не засчитывается.
- **Отключение соперника:** пауза «Ждём, пока он вернётся», затем через N секунд «Техническая победа». Есть и «Техническое поражение».
- **Сдаться:** «Соперник получит победу, рейтинг будет пересчитан».
- **Итоги:** победа, поражение, ничья; «Вы сдались» или «Соперник сдался»; изменение Эло (`hostDelta`/`guestDelta`, `hostNewRating`/`guestNewRating`); кнопки «Реванш» и «Продолжить».
- `GET /api/duel/history?userId=` и `GET /api/duel/history/{id}` дают историю и детали: `outcome, reason, opp, genre, answerFormat, mode` и результат по каждому треку и уровню. Если матч устарел: «Детали матча уже не доступны». Есть «Приватный матч».

### 8.4. Битва Классика (3 и более игроков)
- Один уровень: отрывок 15 с и окно на ответ (по умолчанию 25 с в лобби, 30 с в константе), до 3 попыток.
- **Очки за скорость:**
  ```
  pointsForPartyGuess(kind, elapsedMs, windowMs = 30000, maxPoints = 30) =
      max(1, round( (kind == "artist" ? maxPoints/2 : maxPoints) × clamp(1 − elapsedMs/windowMs, 0, 1) ))
  ```
- Если угадан только исполнитель, начисляется половина очков, трек не засчитывается.
- Побеждает тот, у кого больше очков за матч.
- **Сдаться и выйти:** битва продолжается без игрока, набранные очки сохраняются.

### 8.5. Битва Лайт
- 3–6 игроков (в рейтинге от 2). Отрывок 15 с, 20 с на выбор из 4 вариантов, максимум 20 очков, очки убывают со временем.
- **Одна попытка.** Выбор окончателен. Верный ответ и очки открываются после окончания трека.
- Для старта нужен минимум ещё 1 игрок: «Лайт — нужен ещё N».

### 8.6. Кастомные лобби
**Создание:** `POST /api/battle/rooms`. Тело запроса:
```
{ playlistId | playlistIds[], trackCount, roundTimerSec, isOpen, answerFormat: "classic"|"lite", allowRoomRepeats }
```
Ответ `{code}`, затем переход в `/battle/room/{code}`.
- Неавторизованный пользователь (401) отправляется на `/profile?redirect=…`.

**Список лобби:** `GET /api/battle/rooms/open` возвращает `lobbies[{code, playlistName, hostUsername, answerFormat, genre, playerCount, maxPlayers, full, state}]`.
- Поиск по названию, хосту или игроку, фильтр «Все / Классика / Лайт».
- Вход по коду: поле «КОД ЛОББИ». Ошибки: «Лобби с таким кодом нет», «В это лобби сейчас не войти».

**Комната** (`GET /api/battle/rooms/{code}`):
- Вход: `POST …/join` возвращает `{youAre, isSpectator, room, settings{playlistId, playlistName, poolTemplateId, poolPlaylistNames}}`.
- Готовность: `POST …/ready {ready}`.
- Настройки (только хост): `PATCH …/settings`. Можно менять `playlistId`/`playlistIds`, `trackCount`, `roundTimerSec`, `isOpen`, `answerFormat`, `allowRoomRepeats` и язык. При смене настроек сбрасывается готовность.
- Управление игроками (только хост): `POST …/kick {userId}`, `POST …/transfer-host {userId}`.
- `POST …/reset-tracks`: «Сбросить память сыгранных треков». Без этого повторы запрещены, и игра может не начаться с причиной «в подборке закончились новые треки».
- Приглашение друзей: `POST …/invite {userId}`. Список друзей показывает статусы «На сайте», «Не в сети», «В лобби», «Не принимает». Приглашение ограничено по времени (`expiresAt`).
- Чат: `POST …/chat {text}` (ограничение 1 сообщение в 10 с при санкции `chatSlow`).
- Эмоции: `POST …/throw {to, item, n}`, `GET …/throws`.
- История треков комнаты: `GET …/tracks?before=` (пагинация `nextBefore`).
- Старт: `POST …/match/start`. Причины отказа: не хватает игроков, не все готовы, в подборке закончились новые треки, в подборке нет треков, начать может только хост, нет связи.
- Автостарт: когда все готовы, идёт отсчёт («Все готовы · старт…»).
- Выход: `POST …/leave`. После кика вернуться можно только по ссылке или коду.
- Реванш: `POST …/rematch`.

**Матч:**

| Эндпоинт | Назначение |
|---|---|
| `POST …/match/tick?reason=` | Синхронизация. Возвращает `{version, phase, players[{userId, slot, totalScore, connected, forfeited, tracks[{trackScore, levels[{outcome, attemptsUsed, pointsAwarded, finishedAt}]}]}], self, opponents[{emote}], revealedTracksMeta, currentTrackIdx, currentLevel, phaseEndsAt, remainingMs, audioToken, liteOptions}` |
| `POST /api/audio/room {audioToken}` | Сегменты аудио `{initUrl, segUrls, seconds, packUrl, levels}` |
| `POST …/match/guess {guess, trackIdx, level}` | Возвращает `{outcome, attemptsLeft, pointsGained, pointsAwarded, guesses}` |
| `POST …/match/away {away}` | Пометка «отошёл» (вкладка скрыта) |
| `POST …/match/rejoin` | Возврат в матч |
| `POST …/match/forfeit` | Сдаться |
| `POST …/match/nudge` | Поторопить или пнуть [вывод] |
| `POST …/match/spectate/tick?mode=` | Наблюдение (для привилегий от 4) |

- Фазы матча: `countdown → playing → reveal → … → summary` [вывод по строкам «Игра начнётся через», «Следующий трек через», «Второй уровень через», «Итоги через»].
- Статусы игроков в реальном времени: Ответил, Думает, Вышел, Отошёл, Артист, Угадал, Мимо.
- **Итоги:** место, очки, изменение рейтинга, награда в соглах, «Победитель игры», «В вас бросили … — больше всех», список треков игры с кнопкой «Послушать», «Ещё раз».
- **Оценка игроков** после матча: `POST /api/battle/rate {roomCode, targetId, kind}`.
  - Похвала: `commend_friendly` («Приятный собеседник»), `commend_fair` («Честный соперник»), `commend_expert` («Знаток музыки»). Счётчики видны в карточке профиля.
  - Жалоба: `behaviour` («Бросил игру») или `communication` («Оскорблял в чате»).

### 8.7. Эмоции (throws)
- Четыре вида: помидор 🍅, роза, поцелуй, хлопушка.
- Запас тратится (`/api/user/throws` возвращает `stock`). Пак из 100 штук стоит 100 согл. Разовое задание «Сыграть битву» даёт по 100 каждой эмоции.
- Можно «Бросить в себя».
- Если запас кончился: «Закончились — купить в магазине».

### 8.8. Рейтинг Эло, звания, сезоны
- Рейтинг считается по Эло, стартовое значение 1000 [вывод из API: игроки с +201 за неделю имеют 1201].
- Калибровка длится 10 матчей. K-фактор и формула [сервер]. По ленте изменения в дуэли бывают +20/−39, в лайте на 4 игроков +18/+4/−4/−9, то есть многопользовательский Эло.
- **Звания** (`tierForRating`, пороги по умолчанию; сервер может прислать свои `tierThresholds` из 7 чисел):

| Тир | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| Звание | Железо | Медь | Бронза | Сталь | Серебро | Золото | Платина | Алмаз |
| Рейтинг от | 0 | 800 | 950 | 1050 | 1200 | 1400 | 1600 | 1800 |

- **Сезоны:**
  - сейчас «Сезон 1», 40 дней до конца на 06.10.2026;
  - за нулевой сезон выдавались бейджи «Нулевой сезон · ранг B / A / S»;
  - по итогам сезона приходит уведомление «Итоги сезона: N место — +X согл и бейдж» [сервер: таблица наград не видна];
  - в профиле есть вкладка «Сезоны» (Эло и место по каждому сезону).
- **Топ недели** (`GET /api/battle/weekly`):
  - ранжирование по приросту рейтинга с понедельника: `rows[{userId, username, delta, matches, rating}]`;
  - награды в понедельник: 1 место — 2000 согл и бейдж «Чемпион недели», 2 место — 1000, 3 место — 500.
- `GET /api/battle/rating-history` и `/api/users/{id}/rating-history`: история рейтинга (график), `seasonGames`, `duelRating`.
- **Лента игр:** `GET /api/battle/recent` возвращает `matches[{id, roomCode, format: classic|lite, finishedAtIso, players[{userId, username, score, delta, isWinner}]}]`.

### 8.9. Наблюдение (spectate)
- `GET /api/battle/rooms/spectate-list` возвращает живые комнаты и лобби. Фильтры: публичные или закрытые, режим (все, дуэли), рейтинг (рейтинговые или обычные).
- Роли наблюдателя: «Модератор» или «Кастер» (хранится в localStorage).
- Без прав: «Смотреть эту игру нельзя».

## 9. Режимы для стримеров

### 9.1. «Со стримом» / «Онлайн-топ» (`/stream/{code}`, сейчас на ремонте)
- Стример (хост) создаёт комнату-турнир. Настройки:
  - размер сетки: Топ-N, стадии от «1/64 финала»;
  - сколько треков может предложить один зритель;
  - «Участие чата» (голосование в Twitch-чате);
  - разрешать ли внешние ссылки на треки.
- Зрители предлагают треки (`POST /api/stream/{code}/suggest`) через поиск (`/api/stream/search?q=`) или по ссылке. Ограничения:
  - «Вы исчерпали свой лимит»;
  - «Этот трек уже предложен»;
  - «Турнир уже заполнен»;
  - «Приём треков закрыт»;
  - «Ведущий не разрешил ссылки».
- Хост может добить оставшиеся слоты плейлистом (`PATCH /api/stream/{code} {playlistId}`) и модерировать предложения (`/moderate`).
- Для старта нужно минимум 4 трека (`need/have`). Запуск: `/start`.
- Пары играются по очереди (`/play`). Есть «Встроенный плеер» (15 с) и «Альтернативный».
- Голосование чата цифрами 1 и 2 (`/votes`), голос хоста (`/vote {roundIdx, pairIdx, winnerTrackId}`). В каждой паре видно, кто предложил трек (`submitterByTrack`).
- Есть сброс турнира (`/reset`).
- Realtime-канал `stream:{code}`.

### 9.2. «Помощь чата» в соло-играх
- Доступна стримерам с привязанным Twitch («Сначала привяжите Twitch в профиле»).
- `POST /api/chat-help/start {source}` возвращает `{code}`. Дальше `track`, `viewers`, `hint {code, kind}`, `stop`, а состояние берётся из `GET /api/chat-help/state?code=`.
- **Классика:** зрители пишут в чат название или исполнителя. Стример видит, сколько зрителей угадало, кто был первым, сколько назвали только исполнителя. Подсказки: «Буква артиста», «Буква названия», «Открыть ответ».
- **Лайт:** зрители пишут номер варианта, видно распределение голосов.
- Есть «Счёт чата»: таблица лучших зрителей. Панель можно перемещать и менять её размер.

## 10. Музыкальный каталог и пользовательские плейлисты

### 10.1. Каталог артистов и треков
- Источник: Яндекс Музыка. Артистов на ru около 4659 [API `total`].
- **Артист:** `{name, normalized, slug, yandexId, trackCount, monthlyListeners, avatarUrl, genre, language, isForeignAgent}`.
- **Жанры каталога:** pop, hiphop, rock, indie, electronic, shanson, dance, alternative.
- **Метки иноагентов:** на карточке пометка «Исполнитель признан иноагентом».
- `GET /api/artists?langs=ru|en&limit=48&offset=` с сортировкой по слушателям. `?q=` для поиска.
- **Страница артиста** `/artists/{slug}`:
  - `GET /api/artists/card?…` (данные артиста);
  - `/api/artists/{yandexId}/tracks`: треки в игре, с сортировкой по популярности или по дате, у каждого «добавил {ник}» (`addedAt`);
  - `/api/artists/{yandexId}/similar`: похожие артисты и число их треков;
  - `/api/artists/{yandexId}/top-players`: топ игроков по этому артисту;
  - плейлисты с артистом: «Все» или «Один артист» (`/api/playlists/catalog?artistYandexIds=&artistStrict=`).
- **Релизы:** `GET /api/releases/tracks?id=` возвращает `{coverUrl, title, artistName, artists, yandexUrl, format, genre, year, tracks, initiator, creator}`. Формат релиза: Сингл, Макси-сингл, Альбом или Делюкс.

### 10.2. Добавление треков в каталог (UGC)
1. Кнопка «Добавить» (на `/artists` или в конструкторе) → «По внешней ссылке».
2. `POST /api/catalog/import/preview {url}`. Принимаются ссылки Яндекс Музыки на трек, альбом, артиста или плейлист. Ответ: `{source, tracks[{yandexId, title, popularityRank, releaseYear, alreadyInCatalog, available, blocked}]}`.
3. Пользователь выбирает треки чекбоксами, сортирует по популярности или новизне, есть «Выбрать все».
4. Нужно согласие с UGC-условиями: «Добавленные треки будут доступны всем игрокам. Я размещаю их от своего имени и принимаю Пользовательское соглашение» (`POST /api/user/ugc-terms`).
5. `POST /api/catalog/import/submit {trackYandexIds[], acceptTerms}` возвращает `{addedCount, skipped}`. Отправка идёт порциями (сообщение «Успели добавить: N»).

- Статусы треков: «В игре» (уже в каталоге), «Нельзя добавить» (заблокирован, например по жалобе), «Недоступен».
- Добавленное появляется в «Новых релизах» на главной.
- Право добавлять треки может быть отозвано (раздел 14).

### 10.3. Плейлисты: виды и ограничения

| Вид (`kind`) | Треков | Доступен с | Особенности |
|---|---|---|---|
| `music` | 30–250 | любого уровня | Аудио, все форматы, можно запускать битву |
| `emoji` | 5–50 | 20 уровня | Загадка из 2–10 эмодзи (`EMOJI_CLUE_MIN/MAX`) и подпись до 100 символов (`EMOJI_TRANSCRIPT_MAX`) |
| `picture` | 5–50 | 20 уровня | Правильный ответ (аниме или игра) и неверные варианты, источники Shikimori и IGDB |

**Общие ограничения:**
- максимум 30 плейлистов на пользователя (`PLAYLIST_LIMIT`);
- максимум 3 новых черновика (`MAX_NEW_DRAFTS`);
- название до 40 символов (`DRAFT_MAX_NAME`), описание до 300.

### 10.4. Конструктор (`/create-playlist`, `/playlists/{id}/edit`)
1. Выбор вида: «Музыкальный — угадывают на слух», «Эмодзи — угадывают по смайлам», «Картинки — угадывают аниме или игру по отрывку». Эмодзи и Картинки помечены «С 20 уровня».
2. Поиск артиста (`/api/artists?q=&limit=20`), просмотр его треков, «Добавить трек» или «Удалить трек», прослушивание.
3. **Эмодзи:** редактор загадки.
   - Палитра эмодзи из 9 категорий: Смайлы, Люди, Животные и природа, Еда и напитки, Места и транспорт, Занятия, Предметы, Символы, Флаги.
   - Поиск по русским ключевым словам (большой словарь в коде), раздел «Недавние».
   - Смайлы ставятся в слоты и перетаскиваются.
   - Поле «Что зашифровано? Например, строчка из песни».
4. **Картинки:** для каждого трека нужно выбрать правильный ответ («Найдите, откуда эта песня») и неверные варианты.
   - Поиск: `POST /api/titles/search {source: anime|game, q}` возвращает `{hits, degraded}`. Выбор: `POST /api/titles/resolve {source, externalId}`.
   - Если каталог не отвечает: «Каталог сейчас не отвечает — показаны уже добавленные картинки».
5. Сохранение: `POST /api/playlists {name, trackIds[], kind, clues?, draftTarget}`. Изменение: `PUT/PATCH /api/playlists/{id}` [вывод].

**Черновики:**
- Автосохранение: `PUT /api/playlists/draft {target, name, trackIds, kind, clues, baseRev, deviceId, resumed}`.
  - Конфликт между устройствами: «Этот плейлист собирали и на другом устройстве» → «Взять ту» или «Оставить эту».
  - Без сети черновик пишется в localStorage `pl_draft:{userId}:{target}`.
- Если треки из черновика пропали из каталога: «… больше не доступны, их пришлось убрать» (`dropped`).
- `GET /api/playlists/drafts` возвращает список черновиков в профиле, `DELETE /api/playlists/draft?target=` удаляет черновик.

**Прочее:**
- Пока плейлист используется в игре, его нельзя менять или удалять («Нельзя менять во время игры»).
- Удаление: `DELETE /api/playlists/{id}` («пропадёт из каталога, отменить нельзя»).
- Описание: `PATCH /api/playlists/{id}/description {description}`.

### 10.5. Каталог плейлистов (`/playlists`)
`GET /api/playlists/catalog`. Параметры:

| Параметр | Значения |
|---|---|
| `q` | Поиск по названию. Если вставлена ссылка или UUID, используется `id=` |
| `lang` | все, `ru`, `en`, `mixed` |
| `kind` | `music`, `emoji`, `picture` |
| `minTracks`, `maxTracks` | от 1 до 250 |
| `author` | Ник автора |
| `mine=1` | Только мои |
| `artistYandexIds`, `artistStrict` | До 15 артистов, «Только эти артисты» |
| `sort` | Топ за сутки, по популярности, по рейтингу, по новизне, избранное (`favorites`/`liked`) |
| `cursor`, `limit` | Пагинация |

- **Ответ:** `{playlists[], nextCursor, total}`. Плейлист: `{id, name, description, author, authorId, trackCount, language, languageStats, genreStats, difficulty, uniquePlayers, successfulPlays, likeCount, dislikeCount, score, isFeatured, kind, createdAt, covers[4], userVote, vipLikers[], vipLikersTotal}`.
- `GET /api/playlists/catalog/me?ids=` возвращает для текущего пользователя голоса и пройденность (`votes`, `completed`).
- `GET /api/playlists/unique-tracks?ids=` даёт число уникальных треков для набора плейлистов (используется при выборе нескольких плейлистов в лобби).

### 10.6. Страница плейлиста (`/playlists/{id}`)
- Шапка: название, автор, число треков, число игроков, дата создания, вид, распределение жанров в %, рейтинг (лайки минус дизлайки), «Одобрено старожилами · N».
- Блоки: «Описание» (автор может редактировать), «Кто внутри» (`/api/playlists/{id}/artists`), «Ещё от {автора}» (`/from-author`), «Комментарии».
- Действия: «Играть» (выбор формата и длины), «Битва» (создать лобби), избранное (`POST /favorite`), копировать ссылку, лайк или дизлайк (`POST /like {value: 1|-1|0}`). Для автора: изменить состав, удалить.
- Метрики для статистики: `POST /api/stats/card-view {kind, id, place}`.

### 10.7. Комментарии (к плейлистам и в профилях)
- Писать можно с 10 уровня, если комментарии не отключены санкцией или модератором. В профиле владелец может ограничить круг комментирующих.
- Длина до 300 символов. Enter отправляет, Ctrl+Enter переносит строку.
- **Плейлист:**
  - `GET /api/playlists/{id}/comments?limit=20&cursor=&around=` возвращает `{comments, nextCursor, totalCount, canComment, minLevel, commentsBlocked, commentsBlockedMessage}`;
  - `POST {text}` создаёт комментарий;
  - `POST /comments/{cid}/vote {vote}` ставит лайк или дизлайк;
  - `DELETE /comments/{cid}?action=delete|delete_all|ban` (модерация).
- **Профиль:** `GET/POST /api/users/{id}/comments`, `DELETE /api/users/{id}/comments/{cid}?action=`.
- Жалоба: `POST /api/comments/report {category, reason?, subjectType, commentId}`.
- Ответы на комментарии и лайки комментариев порождают уведомления.

### 11.2. Страница профиля (`/profile/id{N}`)
- **Шапка:** аватар с рамкой, ник, титул (по умолчанию «Игрок»), статус (до N символов), уровень и «До N ур. — X опыта», «Сейчас онлайн», активные бейджи.
- **Действия:** «Добавить в друзья», «Отменить заявку», «Принять заявку», «В друзьях», «Пожаловаться», «Заблокировать».
- **Достижения:** `GET /api/users/{id}/achievements` возвращает `{activeBadges, unlocked, definitions, manualBadges, artists(progress)}`. Выбор показываемых бейджей: `POST /api/user/active-badges {ids}`.
- **Рейтинг:** звание, Эло, % побед, количество побед и поражений, калибровка, кнопка «История».
- **Статистика** (плитки): место по уровню, угадано треков, всего игр, текущая серия, средний счёт дейлика, артистов угадано.
- **Расширенная статистика** (`/api/users/{id}/extended-stats`), вкладки:
  - Битвы, Игры, Жанры, Контент, Исполнители (точность, «впервые услышан»), Сезоны;
  - «Опыт по режимам» (`expSplit`: онлайн или соло);
  - «Любимый артист», «Общий ранг», «Матчей сыграно», «Одиночных игр», «Ср. счёт онлайн / соло», «Аккаунт создан».
- **Любимая музыка:** до 3 артистов и до 10 треков, порядок меняется перетаскиванием (`PUT /api/user/favorite-music {artistYandexIds, trackIds}`).
- **Плейлисты:** свои (с черновиками) и «Избранное» (`/api/users/{id}/favorite-playlists`), суммарно игроков и лайков.
- **Друзья:** блок со списком, его можно скрыть настройкой приватности.
- **История игр** (дуэли и битвы) с деталями: по каждому треку видно, кто угадал название или исполнителя и с какой попытки.
- **Комментарии.**
- Приватность влияет на всё: статистику, рейтинг и друзей можно скрыть (`hidden`).

### 11.4. Друзья
- **Лимит:** 32, с 15 уровня 64, с 40 уровня 128.
- **API:**

  - `DELETE /api/friends/{userId}`;
  - блокировки: `GET/POST/PATCH /api/friends/blocks {userId, action}`. Заблокированный не пишет и не шлёт заявки;
  - `GET /api/friends/suggestions`: «С кем вы часто играете» (10 и более совместных матчей);
  - поиск: `GET /api/users/lookup?q=` (по нику, ID профиля или коду добавления);
  - отношение к конкретному игроку: `GET/PATCH /api/users/{id}/relationship`.
- **Код добавления:**
  - выдаётся на сутки (`expiresAt`);
  - перевыпуск гасит старый и отклоняет заявки по нему;
  - режим «Заявки только по коду» (`PUT /api/friends/settings`).
- **«Невидимка»** (`hideOnline`): друзья не видят, что вы на сайте.

### 11.5. Уведомления
- `GET /api/notifications?limit=50&before=` возвращает `{notifications|items[{id, type, isRead, actor, data, count}], unread, nextCursor, hasMore, prizeAvailable}`.
- `PATCH /api/notifications {ids}`: прочитать выбранные. Есть кнопка «Прочитать все».
- **Типы** [код]:
  - соцфункции: ответ на комментарий, оценка комментария, оценка плейлиста, заявка в друзья, принятие заявки, комментарий в профиле;
  - приглашение в битву (с таймером; варианты отказа: истекло, игра уже началась, нет мест, лобби закрыто);
  - деньги и награды: пополнение (пакет), награда за задание, подарок, соглы, итоги недели, итоги сезона, «С возвращением!», «Слон куплен»;
  - новое достижение;
  - приз прогноза («предложи трек дня»);
  - модерация: снято изображение, загрузка изображений закрыта, трек снят (модератором или правообладателем), добавление треков закрыто, картинка снята, ограничение по поведению наложено или снято («Временно закрыто: …» / «Снова доступно: …»), «Спасибо за жалобу» («ваша жалоба учтена»);
  - закреплённое `link_yandex` («привяжите Яндекс ID»).
- **Группировка:** «X и ещё N», «N новых комментариев».
- **Доставка:** realtime через канал `user:notify#{userId}` (событие `notif_new` с `unread` и `kind`). Во время игры (`/play`, `/duel`, `/battle/room`) тосты приглашений не показываются. Резервный опрос раз в 5 минут и при возврате на вкладку.
- **Отключение по типам:** `PUT /api/notifications/mutes {kind}`. Типы: заявки в друзья, приглашения в битвы, комментарии в профиле, «Мои плейлисты» (комментарии и оценки). Звук включается и выключается отдельно.

### 11.7. Настройки профиля (вкладки)
1. **Профиль:**

3. **Приватность** (`GET/PUT /api/user/privacy`), варианты «Все / Друзья / Никто»:

4. **Тема сайта:** акцентный цвет всего сайта (награда за праздничный ивент, `PUT /api/user/bday-theme {theme}`).
5. **Привязки:** Яндекс, Twitch, Telegram (`/api/user/telegram-link`, `/info`, статус «ждём подтверждения в боте», deep-link) и «У меня есть другой аккаунт» (слияние).

## 12. Прогрессия и экономика

### 12.1. Опыт и уровень [код]
```
expForLevel(L) = ceil(0.6 · L³)
levelFromExp(E) = max L : expForLevel(L) ≤ E
progress = { level, inLevel = E − exp(L), toNextLevel = exp(L+1) − E, ratio }
```

| Уровень | 5 | 10 | 15 | 20 | 30 | 40 | 43 | 50 | 100 |
|---|---|---|---|---|---|---|---|---|---|
| Опыт | 75 | 600 | 2025 | 4800 | 16 200 | 38 400 | 47 705 | 75 000 | 600 000 |

- Опыт начисляется за каждую игру в любом режиме, «с самой первой» [UI]. Он делится на онлайн и соло (`expSplit`). Сколько опыта даёт каждый режим, решает [сервер].
- Лидер по уровню сейчас на 112 уровне [API].

### 12.2. Соглы
- **Начисляются:** за игры (соло и онлайн, только авторизованным; итог игры в `soglyAwarded`), за задания, Топ недели, итоги сезона, подарки, промокоды и пакеты.
- **Тратятся:** косметика, «возможности», эмоции.
- **Учёт:** покупные и заработанные соглы считаются раздельно. Это важно при удалении аккаунта и при слиянии: купленные сохраняются, заработанные со второго аккаунта сгорают.

## 14. Модерация, доверие и безопасность, правообладатели

### 14.1. Жалобы
- **На игрока или комментарий:** `POST /api/users/{id}/report` или `/api/comments/report {category, reason?, subjectType?, commentId?}`.

| Категория | Пояснение |
|---|---|
| Оскорбления и травля | Мат, унижение, преследование |
| Ненависть и угрозы | Разжигание вражды, угрозы, экстремизм |
| Запрещённый контент | 18+, наркотики, призывы к суициду |
| Обман и спам | Развод на соглы, реклама, фейковый профиль |
| Нечестная игра | Накрутка статистики, мультиаккаунты |
| Другое | Нужно минимум 5 слов (`OTHER_MIN_WORDS`) |

- **После матча:** похвала или жалоба (`/api/battle/rate`).
- Автор жалобы получает уведомление «Спасибо за жалобу / ваша жалоба учтена».

### 14.2. Действия модератора
- Удалить комментарий, удалить все комментарии автора, забанить автора (`isBanned`).
- Снять аватар, шапку или фон (они остаются в галерее пользователя), запретить загрузку своих изображений.
- Снять добавленный трек, запретить добавление треков.
- Закрыть комментарии («Модератор закрыл вам возможность оставлять комментарии»).

### 14.3. Шкалы поведения [код]
- Две шкалы от 0 до `SCORE_MAX=12000`: **Порядочность** (behaviour: выходы из матчей, нечестная игра) и **Вежливость** (communication: чат и комментарии).
- Правила изменения шкал (сколько снимает жалоба или выход из матча, как идёт восстановление) решает [сервер]. Подсказки в интерфейсе: «Доигрывайте матчи до конца», «Общайтесь без оскорблений».
- Санкции (битовая маска `ranked=1, customContent=2, chatSlow=4, chatMute=8, comments=16`):

| Санкция | Шкала | Включается ниже | Снимается от | Эффект |
|---|---|---|---|---|
| `ranked` | Порядочность | 3000 | 3500 | Нет рейтинговых игр |
| `customContent` | Порядочность | 3000 | 3500 | Свои картинки, статус и звание скрыты (остаются в галерее) |
| `chatSlow` | Вежливость | 6000 | 6500 | Чат: 1 сообщение в 10 с |
| `chatMute` | Вежливость | 3000 | 3500 | Чат в лобби отключён |
| `comments` | Вежливость | 3000 | 3500 | Комментарии отключены |

> В FAQ указаны другие пороги (6000 и 3000 для порядочности, комментарии ниже 6000). Для ТЗ нужно решить, какой вариант правильный.

- Наложение и снятие санкции приходит уведомлением `behaviour_restriction` с полями `added` и `removed`.

### 14.4. Правообладатели
- Страница `/copyright` описывает процедуру. В плеере есть кнопка «Правообладателю».
- Жалоба правообладателя приводит к тому, что трек или картинка снимаются, добавивший получает уведомление. После нескольких обращений по трекам одного пользователя он теряет право добавлять треки.
- Отрывки играются по 15 секунд, полные треки можно открыть только в Яндекс Музыке.
- Пометка иноагентов и предупреждение 18+.

### 14.5. Антифрод и антиспам
- Всё считает сервер (`matchToken`), есть rate-limit (429), защита от рассинхронизации (409, `expectedIndex`), версия состояния в матчах (`version`).
- Идемпотентность покупок и оплат (`opId`).
- Наблюдение за матчами доступно только с привилегий.
- Проверка подлинности Telegram (`initData`, `/api/tg/verify`) и блокировка неофициальных ботов.

## 15. Realtime (Centrifugo)

| Канал | Содержимое |
|---|---|
| `user:notify#{userId}` | Персональные события: `notif_new {unread, kind, data}`, `profile_updated {user}`, приглашения в битву (`battle_invite:{code}`), достижения |
| `room:{code}` | Состояние лобби и матча: игроки, готовность, настройки, фазы, ответы, чат, эмоции |
| `stream:{code}` | Состояние стрим-турнира: предложения, сетка, голоса |
| Публичные showcase-каналы (`PUBLIC_SHOWCASE_TAGS`) | Лента дейлика (`daily_feed_row`), обновление витрин главной |

- Токен: `GET /api/centrifugo/token?t=` возвращает `{token, userId, expiresIn}`. Перед истечением токен обновляется.
- **Устойчивость:** если 20 секунд нет соединения при активной подписке на `room:` или `stream:`, показывается «outage». После переподключения клиент догружает состояние (`retryCatchupOnce`). Событие `RECOVERY_FAILED_EVENT` вызывает перезагрузку данных через REST. Учитывается рассинхронизация часов сервера и клиента (`serverNow`, `skewSec`).
- Ошибка «Сервер перегружен — слишком много подключений» означает, что достигнут лимит соединений.
- Во время матча работает и HTTP-опрос (`match/tick`), то есть стоят двойные гарантии.

## 16. Доставка аудио и защита от читов

- Аудио нарезано на сегменты (fMP4/MSE): `initUrl` (init-сегмент) и `segUrls[]`. Есть `packUrl` (пакет для предзагрузки) и `seconds`.
- Сервер отдаёт столько сегментов, сколько разрешает текущий уровень (`[audio] уровень N: K сегментов (сервер на уровне M)`). Клиент физически не может получить 15 секунд на уровне 0,5 с.
- Доступ по одноразовым токенам: соло использует `matchToken` (`/api/game/audio`), матчи `audioToken` (`/api/audio/room`), Топ-32 и стрим свои токены.
- Реверс разворачивается на сервере [вывод].
- Клиентский плеер: громкость (сохраняется), «Может быть громко», подсказки про блокировку автовоспроизведения (iOS Silent Mode, AdBlock, VPN).
- Если звук не загрузился, клиент шлёт `POST /api/stats/ui {event:"audio_fail", reason, mode}`.
- Прослушивания для статистики: `POST /api/stats/track-click {type:"listen_end", yandexId, seconds, path, mode, format}`.

## 20. Юридическое и соответствие требованиям
- **Документы:** Пользовательское соглашение (`/terms`), Политика конфиденциальности (`/privacy`), Публичная оферта (`/offer`), Политика авторских прав (`/copyright`), сводная страница `/legal`. Контакты: contact@songless.ru, Telegram @ex_app.
- **Согласия:**
  - условия, политика и 18+ при входе и перед первой игрой;
  - cookie: необходимые или с внешней аналитикой (можно отозвать в настройках);
  - UGC-условия при добавлении треков;
  - оферта и 18+ при оплате.
- **Возрастная маркировка:** 18+ в подвале и при входе.
- **Иноагенты:** метка на артистах и предупреждение в плеере.
- **Права на музыку:** короткие отрывки, ссылка на Яндекс Музыку, процедура снятия по обращению, санкции к нарушителям.
- **Персональные данные:** удаление аккаунта стирает данные. Поведение аккаунта при удалении через Telegram описано отдельно.
- **Деньги:** соглы нельзя вывести или вернуть (купленные сгорают при удалении), чек приходит на e-mail, есть лимиты пополнений.

- **Звуки:** сигнал найденного соперника, звук достижения, звук приглашения; мигание заголовка неактивной вкладки.
- **Доступность:** aria-метки на кнопках, `aria-live` для таймеров.
- **Мониторинг:** перехват ошибок, события падения аудио, UI-события магазина (`shop_try`, `shop_short`, `shop_topup_open`), клики (`data-track-click`).

## 22. Что не удалось узнать и вопросы для ТЗ

Это решает сервер и из клиента не видно. В ТЗ нужно описать самостоятельно:
1. Сколько опыта и согл даёт каждый режим (соло, дейлик, битва, победа или поражение) и есть ли суточные лимиты.
2. Формула Эло: K-фактор, калибровочный K, многопользовательский Эло в лайте, затухание, мягкий сброс между сезонами, длина сезона, награды по местам.
3. Как именно в Лайте и Картинках очки зависят от скорости в соло.
4. Алгоритм сравнения ответов: нечёткое совпадение, допуск опечаток, версии и ремиксы, алиасы.
5. Алгоритм отбора треков для дейлика, Случайного и рейтинговых пулов (популярность, сложность, язык, эпоха), сколько треков предложенных игроками попадает в дейлик.
6. Метрика точности прогноза и правило ничьих.
7. Формулы шкал Порядочность и Вежливость: сколько снимают жалобы и ливы, как идёт восстановление со временем.
8. Как вычисляется `difficulty` плейлиста и его рейтинг `score`, кто такие «старожилы».
9. Как работает рейтинговый подбор: диапазон Эло, расширение диапазона со временем, тайм-ауты.
10. Цена «32 места в лобби» и таблица наград за сезон.
11. Расхождение порогов санкций между FAQ и кодом.
12. Как устроен режим «Со стримом» после ремонта и интеграция с Twitch-чатом (IRC/EventSub).
