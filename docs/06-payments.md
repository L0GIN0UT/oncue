# Платежи и подписки

> Статус: принято (v1). Решение: [ADR 0007](adr/0007-billing-disabled-by-flag.md). Сервис: [architecture/services.md](architecture/services.md) §11.

## 1. Модель

- **Основная модель — подписка** (тарифы: например, `free`, `plus`). Разовые покупки (пакеты валюты, косметика за деньги) — опционально, той же инфраструктурой.
- Остальные сервисы **ничего не знают о деньгах и тарифах**. Они знают только **entitlements** — права на возможности:
  - `lobby.max_players:32`, `collections.limit:100`, `cosmetics.premium`, `stats.extended`, `ads.disabled`;
  - entitlement — это ключ и, при необходимости, значение.
- Тариф = набор entitlements. Набор задаётся конфигом в payments и меняется без релиза.
- Внутренняя валюта и магазин косметики живут в progression и работают независимо от биллинга.

## 2. Режим на старте: биллинг выключен

- Флаг `billing.enabled = false` (Unleash).
- Все пользователи получают план **`free_all`**, в котором выданы **все** entitlements. Функционально весь продукт бесплатен.
- Платёжные ручки возвращают `403 billing.disabled`, кнопки оплаты на фронте скрыты по тому же флагу.
- Код сервиса payments **полностью разработан и покрыт тестами**: интеграция с провайдером идёт через порт `PaymentGateway`, в тестах и на staging используется `FakePaymentGateway`.
- **Включение монетизации** — это смена конфигурации, а не разработка:
  1. настроить тарифы и набор entitlements у `free`;
  2. подключить реальный адаптер провайдера;
  3. включить флаг (сначала для части пользователей);
  4. пользователям `free_all` выдать grace-период согласно продуктовому решению.

## 3. Как сервисы проверяют возможности

```python
# libs/entitlements
if not await entitlements.has(user_id, "lobby.max_players", at_least=32):
    raise FeatureNotAvailable("lobby.max_players")
```

- Источник — claim `ent` в access JWT (компактный хэш плана и версии) плюс локальный кэш, обновляемый по событиям `EntitlementGranted/Revoked`.
- Если payments недоступен, используется последний известный набор. Если его нет — план по умолчанию из конфига (на старте `free_all`).

## 4. Подписка: жизненный цикл

```
none → pending (создан платёж) → active → past_due (неуспешное продление, grace N дней) → canceled/expired
                                     ↘ canceled (пользователь отменил, доступ до конца периода)
```

- Источник истины по статусу платежа — **вебхук провайдера** с проверкой подписи. Редирект пользователя информационный.
- Обработка вебхуков идемпотентна (`provider_event_id` в inbox).
- Продление делает провайдер (рекуррентные платежи) или наш планировщик — зависит от провайдера (выберем при включении).
- Чеки (54-ФЗ) — через провайдера или онлайн-кассу.

## 5. Порты

| Порт | Назначение | Реализации |
|---|---|---|
| `PaymentGateway` | Создать платёж или подписку, отменить, вернуть, проверить вебхук | `FakePaymentGateway` (сейчас), адаптер провайдера (при включении) |
| `ReceiptService` | Фискальные чеки | Fake / провайдер |
| `EntitlementPublisher` | Публикация изменений прав | Outbox → Redpanda |

## 6. Юридическое (к моменту включения)

Оферта, правила подписки и автопродления, политика возвратов, 18+ (если сохраняется), хранение платёжных данных только у провайдера (у нас — токены и статусы, никаких номеров карт).
