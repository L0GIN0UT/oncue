# Защита от накрутки через пользовательские сборники: применение на стенде

Ветка `feat/progression-ugc-abuse-guard`. Зона повышенной проверки (progression, ledger):
**требуется ручная проверка владельцем**.

## Правила (всё в конфиге, секция `ugc_guard`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `own_collection_rewards` | `false` | за прохождение своего сборника ни опыта, ни Версов |
| `repeat_window_hours` | `24` | повтор того же сборника тем же игроком в окне наград не даёт; `0` выключает проверку |
| `repeat_scope` | `ugc` | окно повтора для пользовательских сборников; `all` добавляет кураторские |
| `ugc_daily_xp_cap` | нет | суточный потолок опыта с пользовательских сборников |

**Как включить «никогда не начислять повторно»:** `repeat_window_hours: 87600` (10 лет).

Секции в действующем конфиге стенда нет, поэтому после выката действуют значения по умолчанию
(защита включена, потолка UGC нет). Чтобы задать потолок (в сиде 500) или поменять окно,
опубликуйте новую версию конфига через админку progression (черновик → публикация).

## Применение на стенде (после слияния)

1. Обновить образ progression, выполнить `progression migrate` (миграция 0013: две таблицы
   и колонка `daily_counters.ugc_xp` с нулём по умолчанию; данные не меняются).
2. Запустить процессы. Новые публикации сборников сами попадают в проекцию авторов.
3. Один раз догрузить авторов уже созданных сборников (90 на стенде):
   `gv dev progression-backfill-authors` (или `service-entry backfill-collection-authors
   --collections-url http://collections:8000` в контейнере progression). Повтор безопасен.
4. (По желанию) опубликовать версию конфига с `ugc_guard.ugc_daily_xp_cap`.

Пока автор сборника неизвестен, награда начисляется как раньше; такие случаи пишутся в лог
`progression.ugc_guard_owner_unknown`.

## Что проверить вручную

- Владелец проходит свой сборник: опыт и Версы не растут.
- Другой аккаунт проходит чужой сборник: награда есть; повтор в течение 24 ч: нет.
- Матч по сборнику в лобби: у автора нет награды, у остальных есть.
- После `gv dev progression-backfill-authors`: старые сборники ведут себя так же.
- Известные границы: второй аккаунт самого автора не отличим от обычного игрока; от него
  защищают окно повтора и суточный потолок UGC-опыта.
