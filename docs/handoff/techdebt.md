### Группа B — решения без владельца
- Disconnect делает **match**, не identity: ключ server API Centrifugo остаётся только у публикующих сервисов (D9). Бан `ACCOUNT` — по событию `UserSanctionsChanged.account_banned`, код 3500 (без переподключения); кик из комнаты — код 3000. Остаточный риск (Centrifugo OSS не отзывает токены, окно ≤ `token_ttl_s`) — ADR 0059 и строка бэклога; закрывает только connect/subscribe proxy.
- Провал `disconnect` при бане не бросает исключение: иначе событие откатит проекцию санкций и бан `ONLINE` не применится. Вместо этого метрика `gv_match_disconnect_failed_total` (завести алерт в группе C вместе с лагом consumer social).
- Иерархия: допустимо, если права цели ⊆ прав актёра (как `RoleMatrix.can_grant`); равный модератор допустим, admin — нет. Проекция `staff_perms_proj` из `UserRolesChanged`; бэкфилл — `GV_REANNOUNCE_STAFF_PERMS=true` на одну выкладку identity `migrate`.
- Роль БД: рантайм `progression_app` без прав на изменение журналов; журналы определяются по триггеру `progression_ledger_forbid_mutation` (новый журнал закрывается сам). Выдача прав — каждый `migrate`, нет роли — ошибка. Локально на старом томе: `gv dev db-roles`.
- `p/*`: предпросмотр только для `pending`; у одобренной картинки в карточке admin превью нет (метаданные). Если нужно — отдавать `approved` потоком из `u/`.
- trivy: SARIF сохраняется артефактом job, не выгружается в Code Scanning (не нужен GitHub Advanced Security); блокировка только по CRITICAL (`ignore-unfixed`), HIGH остаётся отчётным (ADR 0057).
- Кик: повторы `unsubscribe`/`disconnect` с паузой остаются в цикле владельца комнаты (как у `unsubscribe` раньше); при недоступном Centrifugo это замедляет комнату — вынос в фон в группе C.
- Preflight секретов Centrifugo не проверяется внутри сервисов (identity и match видят только свой секрет): `gv dev up` и `gv preflight` для конвейера выкладки.
- Падения тестов match (2) при параллельной нагрузке прошли повторным прогоном (258 passed).

### Группа C — решения без владельца
- Партиционирование журналов progression **не делалось**: `UNIQUE(op_id)` (идемпотентность денег) в партиционированной таблице обязан включать ключ партиции; ADR 0062 — варианты, пороги, путь миграции. Вместо него — инкрементальная сверка (контрольная точка `reconcile_checkpoints`, полный проход раз в сутки) и ретенция.
- Ретенция: по умолчанию 180 дней (минимум 14) для `metric_marks` и дневных/недельных `quest_progress`; разовые задания не удаляются (защита от двойной награды). Срок — предположение (срок хранения топика Redpanda в репозитории не найден).
- Общий `XREAD` — многоключевой, не работает в Redis Cluster (ADR 0063). Ридер команд перезапускается при любом сбое с backoff, а не роняет процесс.
- Закрытие пустого лобби — локальное, без события в outbox: для лобби событий в шине нет (закрытие лежит в снимке комнаты).
- Бан-отзыв Centrifugo — синхронно в consumer (мимо фоновой очереди); кик/выход — фоновая очередь, переполнение считается метрикой и алертом.
- Типы уведомлений: системные (`user_mutable: false`) выключать нельзя (`admin_switchable`); кэш флагов 15 с — для аварийного стопа держать ≤ 30 с.
- Inbox Django: оставлен свой (ADR 0065).
- Падения 2 тестов match / `admin test_runtime` на Windows — известные/нагрузочные.

### `party_speed` на поздних уровнях — предложение (код не менялся, решает владелец)
Причина: время `t` и окно `T` берутся внутри уровня ответа, поэтому ответ через 1 с после открытия 6-го уровня (кадр уже почти раскрыт) даёт 95 очков — как на 1-м. Расчёт для `max_points: 100`, `partial_ratio: 0.5`, шести уровней по 20 с (точный ответ; столбцы — ответ через 1 / 5 / 10 / 19 с после открытия уровня):

| Вариант | L1 | L3 | L6 |
|---|---|---|---|
| A. Как сейчас: `100·(1 − t/T)` | 95 / 75 / 50 / 5 | 95 / 75 / 50 / 5 | 95 / 75 / 50 / 5 |
| B. Вес уровня `f = [1, 0.85, 0.7, 0.55, 0.4, 0.25]` | 95 / 75 / 50 / 5 | 67 / 53 / 35 / 4 | 24 / 19 / 13 / 1 |
| C. Время от старта раунда: `1 − (смещение уровня + t) / ΣT` | 99 / 96 / 92 / 84 | 66 / 63 / 58 / 51 | 16 / 13 / 8 / 1 |

Рекомендация — **B**: сохраняет стимул отвечать быстро внутри уровня, управляется данными (`level_weights` в `params` режима, схема `scorer.party_speed.v1.json` — необязательный массив, по умолчанию все 1, поэтому существующие режимы не меняются), не требует нового поля в `RoundOutcome`. Для одноуровневых режимов (duel.lite) ничего не меняется. C проще объяснить игроку («чем раньше от начала кадра, тем больше»), но резко обесценивает 1-й уровень при медленной игре (84 против 5 у B на 19-й секунде) и меняет семантику `elapsed_ms`. Внедрение B — отдельная задача (контракт, плагин, тесты, сид-режим `film.party.frame`).
