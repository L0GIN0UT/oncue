# Данные и хранилища

> Статус: принято (v1).

## 1. Владение данными

- У каждого сервиса **своя БД** (на VPS — отдельная database и отдельный пользователь в общем кластере Postgres; в k8s — отдельный кластер для сервисов с большим объёмом данных).
- Права пользователя БД — только на свою базу. Это проверяется инфраструктурным тестом.
- Единственное исключение — сервис admin: он **только читает** read-only реплики через пользователя с правом SELECT ([ADR 0006](../adr/0006-django-admin-panel.md)).
- Чужие данные — через **локальные проекции**, которые строятся по событиям (например, game держит `catalog_projection`). Проекция read-only и может быть полностью перестроена из лога Redpanda.

## 2. Хранилища

| Хранилище | Кто использует | Что хранит |
|---|---|---|
| PostgreSQL 16 | Все доменные сервисы | Источник истины, outbox/inbox |
| Redis 7 | game, match, rating, gateway, catalog | Горячие сессии (TTL), комнаты и lease, лидерборды (ZSET), rate-limit, кэш |
| OpenSearch | catalog | Поиск, автокомплит (edge n-gram, морфология ru/en) |
| S3 (SeaweedFS на VPS) | media-pipeline, progression (UGC-изображения) | Ассеты загадок по уровням, аватары, баннеры |
| CDN | Клиенты | Раздача ассетов по подписанным ссылкам |
| Redpanda | Все | Лог доменных событий (retention: 30 дней; compacted-топики для проекций) |
| ClickHouse (позже) | analytics | Продуктовая аналитика |

## 3. Соглашения по схемам

- Первичные ключи: **UUID v7** (упорядочен по времени: дружит с B-tree, не раскрывает количество записей). Для публичных коротких кодов (комнаты, коды друзей) — отдельное поле.
- Время — `timestamptz` в UTC. Таймзона продукта (Europe/Moscow для дейлика) — параметр конфига.
- Деньги — целые копейки (`bigint`), валюта — отдельное поле.
- Soft delete только там, где нужно продукту (комментарии). Удаление аккаунта — анонимизация по `UserDeleted`.
- Миграции — Alembic. **Только обратно совместимые** (expand → migrate → contract), чтобы rolling deploy не ломался.
- Enum-ы, которые могут расшириться (тип загадки, домен, режим), хранятся строками со справочником в конфиге, а не как Postgres ENUM.

## 4. Большие таблицы

| Таблица | Сервис | Стратегия |
|---|---|---|
| game_results, guesses | game | Партиционирование по месяцу (`pg_partman`), горячие 3 месяца, старые → архив/ClickHouse |
| match_results | match | Партиционирование по месяцу |
| ledger | progression | Партиционирование по месяцу, append-only, баланс — материализованная проекция |
| rating_history | rating | Партиционирование по сезону |
| notifications | notifications | По месяцу, TTL 180 дней |
| outbox / inbox | все | Очистка отправленных и обработанных старше 7 дней |

## 5. Кэширование

| Что | Где | Инвалидация |
|---|---|---|
| Карточка медиа-единицы | Redis, catalog | По событию `MediaItemUpdated` |
| Конфиги режимов | In-process (TTL 60 с) + Redis | По событию `ModeConfigPublished` |
| Entitlements пользователя | In-process/Redis у потребителей | По событию `EntitlementGranted/Revoked`, TTL 5 мин |
| Публичные страницы (каталоги, профиль) | bff-web + CDN | Короткий TTL + stale-while-revalidate |
| Лидерборды | Redis ZSET — это и есть хранилище чтения | Обновляются rating по событиям |

Правило: кэш **никогда не единственный источник истины**. Его потеря приводит только к деградации скорости.

## 6. Бэкапы и восстановление

- Postgres: WAL-G, непрерывная архивация WAL в S3, ежедневный base backup. **PITR** с целевыми RPO ≤ 5 мин, RTO ≤ 1 ч.
- Еженедельный автоматический тест восстановления в отдельное окружение (CI job).
- Redis: AOF для match (снапшоты комнат). Для остального Redis считается кэшем.
- S3: версионирование бакетов, репликация в отдельное хранилище.
- Redpanda: не бэкапим — источник истины в Postgres. Лог можно восстановить из outbox-архива при необходимости.
