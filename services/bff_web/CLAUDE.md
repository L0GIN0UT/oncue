# bff_web

Backend-for-frontend: агрегация данных под экраны веб-клиента.

- Пакет: `bff_web_service`; запуск: `bff_web api`
- Карточка сервиса (данные, события, деградация): `docs/architecture/services.md`
- Публичный API: `/api/web/v1/...` на gateway (только GET)
- Зависимости: Redis (кэш); вызывает game, identity, catalog, collections, library, match, rating, progression, notifications, social по HTTP
- Статус: этап 2 — экраны session, home, solo, results (`docs/plans/stage-2.md` §6); этап 3a — витрина режимов, недельная сетка, рекорды, итог по `presentation` (`docs/plans/stage-3a.md` §7); этап 3b — каталог и страница сборника, медиатека (`docs/plans/stage-3b.md` §9); этап 4a — хаб онлайна и итог матча, этап 4b — очереди, рейтинг, сезоны, топ недели и лидерборды (`docs/plans/stage-4.md` §8)
- Граф зависимостей собирает `wiring.py` (вне слоёв); `api/deps.py` — что получают роутеры.

## Особенности
- Только чтение (D4): мутаций нет, CSRF и идемпотентность не нужны; команды игры браузер шлёт прямо в game.
- Схемы экранов — `api/public/schemas.py`; блок упавшего источника — `{"status": "unavailable"}`, страница всё равно 200.
- Токен — из cookie `gv_access` или Bearer, дальше передаётся как Bearer; недействительный токен в `/v1/session` — `subject: null`, не 500.
- Публичные ответы — `public, max-age=30`, личные — `private, no-store`; личные блоки не кэшируются.
- Токен проверяется локально (JWKS identity, `GV_JWKS_URL`): недействительный → аноним (блок дейликов `unavailable`, game не вызывается); JWKS недоступен → токен уходит источникам непроверенным. Вид субъекта — по claim `gst`, имя — из identity `/v1/me` (гостю он отвечает 403).
- Источники: `GV_UPSTREAMS__{GAME,CATALOG,IDENTITY,COLLECTIONS,LIBRARY,MATCH,RATING}_URL` (по умолчанию — DNS compose), общий таймаут `timeout_s` (1,5 с), лимит параллельных вызовов на запрос, circuit breaker на сервис (`breaker_failures`/`breaker_reset_s`); 5xx/429/таймаут/ответ вне контракта → блок `unavailable`, 4xx → решает use-case. Редиректам не следуем (Bearer не уходит по чужому адресу).
- Кэш Redis (`GV_PAGE_CACHE__*`): только публичные `game /v1/modes` (и `?session=online` под своим ключом) и `/v1/collections/{id}/modes` (30 с), витрины каталога сборников без `q`/курсора (30 с) и карточки catalog (5 мин); в кэш попадает тело, прошедшее разбор; ошибки Redis — промах. Всем страницам — `Vary: Authorization, Cookie`.
- Раскладка по блокам — по данным game, без ключей режимов (`PageLayout`, `GV_PAGES__*`): `random_source_types` → блок `random`; `scheduled_source_types` (`daily`, `bracket`) не попадают в витрину `modes`, `collection_source_types` (`collection`) — ни в одну витрину (game их в `/v1/modes` и так не отдаёт); статусы `/v1/daily` режимов `weekly_source_types` (`bracket`) идут в блок `weekly`, остальные — в дейлики (на главной и в хабе). Витрина `modes` — группы `(source_type, presentation)` в порядке ответа game.
- `records` (хаб) — личный блок из `game /v1/me/records`, только пользователю: гостю и анониму `records: null`, game не вызывается. Рекорды и карточки периода без опубликованного режима пропускаются; без `/v1/modes` такие блоки `unavailable`.
- Каталог сборников (`/v1/pages/collections`): collections зовётся без токена; без `q` и `cursor` — витрины `featured`/`popular`/`new` (сортировка = имя блока, общие фильтры, `next_cursor` на «показать все»), иначе только `results`; с `q` — `private, no-store`. Отказ collections 4xx (чужой курсор) — ответ экрана.
- Страница сборника: карточка с токеном (состав и `me` решает collections, D6), режимы game — без токена; 404 collections — 404 экрана, game недоступен или ещё не спроецировал — `modes: unavailable`. `me` — только пользователю.
- Медиатека: аноним — 401, гость — 403 `auth.guest_forbidden` без вызова library; всегда `private, no-store`; 404 library (`library.shelf_not_found`) — 404 экрана.
- Онлайн только с аккаунтом (D13, ADR 0036): `/v1/pages/online` гостю и анониму — `{status: "auth_required", blocks: null}` без вызовов (403 гостя от match по непроверенному токену — тоже); токен не прошёл локальную проверку или match ответил 401 — `session_expired` (фронт делает refresh и повторяет). Блоки `open_rooms`, `my_matches` (match, лимиты `GV_PAGES__ONLINE_*_LIMIT`) и `modes` (game `?session=online`: карточка + правила комнаты `online`; режим без `online` — нарушение контракта, блок `unavailable`) гаснут независимо. `/v1/pages/match/{id}` — как медиатека (401/403 без вызова match); 404 match — 404 экрана, прочие неописанные 4xx и недоступность — все блоки `unavailable`; карточки catalog (`/v1/items?ids=`, без токена) и флаги «в медиатеке» (library `/v1/items/shelves?ids=`) — пачками по `GV_PAGES__MATCH_ITEMS_BATCH_SIZE` (50, предел источников; без N+1: матч из 8 раундов — по одному вызову на источник), дубли схлопнуты, порядок — по раундам; пропавшая в ответе единица: карточка пропускается, флаг пустой; сбой любой пачки гасит свой блок; пачки карточек в Redis не кэшируются; блоки — под общим сроком `GV_PAGES__MATCH_ITEMS_DEADLINE_S`. Всё онлайн — `private, no-store`.
- 5a, прогрессия (`GV_UPSTREAMS__PROGRESSION_URL`): `/v1/pages/profile` — аноним 401, гость 403 `auth.guest_forbidden` без вызова progression, всегда `private, no-store`; блоки `progress`, `wallet`, `quests`, `badges`, `wheel` (`can_spin` = включено и `today` пусто; секторы и `today` приходят в блоке — отдельного чтения фронту не нужно) гаснут независимо, 401/403 источника — ответ экрана. Тексты заданий, бейджей и секторов — из progression. Блок `progress` главной — свёртка `me/progress` + `me/quests` + `wheel` под общим сроком `GV_PAGES__HOME_PROGRESS_DEADLINE_S`; гостю и анониму `null` без вызовов, любой сбой — `unavailable`, остальная главная цела. Спин колеса браузер шлёт прямо в progression.
- 5b (ADR 0049): тема — только ключ (в 5b настройка `default_theme_key`, в 5d от сезонного события), значений токенов в API нет: наборы лежат во фронтенде. Покупка, промокод, оформление, аватарка и «прочитано» — прямые вызовы браузера в progression и notifications. Сбой, 401 и 403 notifications гасят только колокольчик.
- 5b, косметика (`GV_UPSTREAMS__NOTIFICATIONS_URL`): `/v1/pages/shop` — как профиль (аноним 401, гость 403 без вызовов, `private, no-store`); `catalog` (progression `/shop/items`, `slots` — слоты в порядке появления в ответе) и `packs` гаснут независимо, 404 `progression.billing_disabled` → `packs: null`. Профиль получил `appearance` (слоты + `custom_avatar_url` из `/me/avatar`; без аватара блок гаснет), `inventory`, `avatar`; игрок — `appearance` (`/v1/appearance?user_ids=`); итог матча — `appearance` пачками по `GV_PAGES__APPEARANCE_BATCH_SIZE` (12), дубли схлопнуты, под общим сроком блоков матча.
- `/v1/pages/shell`: `theme.key` — только ключ (`GV_PAGES__DEFAULT_THEME_KEY`, ADR 0049); `bell` — notifications `/unread-count` только пользователю (гость и аноним — `null` без вызова, сбой — `unavailable`). С токеном `private, no-store`, без токена — публичный кэш.
- 5c, social (`GV_UPSTREAMS__SOCIAL_URL`): необязательные блоки только пользователю с аккаунтом (гость и аноним — `null`, social не вызывается; личные ответы `private, no-store`), каждый гаснет независимо: `players/{id}` — `social` (social `/v1/players/{id}/relation`) и `restricted`; `online` — `friends` (`/v1/me/friends` + число входящих из `/v1/me/friend-requests`, любая половина упала — `unavailable`; 401 social не даёт `session_expired`); `collections/{id}` — `comments` (первая страница, `GV_PAGES__COMMENTS_LIMIT`=30; token пользователя уходит ради `can_edit`/`can_delete`, анонимам и гостям — без токена); `shell` — `sanctions` (`/v1/me/sanctions`).
- Приватность профиля (5c): `profile_visible=false` (скрытый профиль, блокировка, неизвестный игрок — неразличимы) → `restricted=true`, `progress` `unavailable` без вызова progression, оформление остаётся; `stats_visible=false` → только `progress` `unavailable`. Social недоступен/отверг токен — статистику чужого игрока не отдаём (fail-closed), `social` `unavailable`. Свой профиль — social не вызывается. `Viewer.user_id` — `sub` проверенного токена (при непроверенном токене `None`).
- `match/{id}`: `players[].can_report` решает bff (зритель — участник матча с ≥2 игроками, игрок — не он); social вызывается только за `can_add_friend` (см. ADR 0069).
- Ответ экрана из отказа источника (`screen_error`) — только 401/403/404/409/422; прочие 4xx — блок `unavailable`, а не 404.
- 4b, хаб онлайна: к блокам 4a добавлены `queues` (match `/v1/queue/pool`), `ratings` (rating `/v1/me/ratings`; в калибровке `rating`/`tier` = null, «осталось N» — `calibration_left`), `seasons` (из rating `/v1/ladders`; ladder без сезона пропускается), `weekly` (топ недели каждого ladder-а, `GV_PAGES__ONLINE_WEEKLY_LIMIT` строк, с токеном — строка `me`; сбой любого ladder-а гасит блок). Все четыре гаснут независимо; 401 rating — `session_expired`, 403 гостя — `auth_required`.
- `/v1/pages/leaderboards?ladder&cursor&around=me`: публичная, токен в rating не уходит; ladders, общий лидерборд (по ключу ladder+cursor) и топ недели кэшируются в Redis на `GV_PAGE_CACHE__LEADERBOARD_TTL_S` (10 с), `Cache-Control: public, max-age=10` (`GV_HTTP_CACHE__LEADERBOARDS_MAX_AGE_S`). `around=me` только пользователю (аноним и гость — 401): токен уходит в rating, страница `private, no-store` с `me`; в калибровке (404 `rating.not_ranked`) — обычная первая страница. Без `ladder` берётся первый из списка rating; неизвестный — 404 `rating.ladder_not_found`; чужой курсор — 422.
- 5d, события (ADR 0054): активное событие — progression `/v1/events/active` (анонимно, Redis-кэш `GV_PAGE_CACHE__ACTIVE_EVENT_TTL_S` ≤ 30 с); `shell.theme.key` = `theme_key` запуска (пустой/неверного вида → `default_theme_key`), блок `event` (баннер; `found`/`total` — только пользователю, из `/v1/events/{key}`) в shell и home; progression недоступен — тема по умолчанию и `event: null`. `/pages/events/{key}` — как профиль (401/403 без вызовов), 404 → 404, недоступность → 503; `profile.events` — `/v1/me/events`, сбой → `[]`. Засчёт находки браузер шлёт прямо в progression.
- ADR 0069: `PlayerPage.nickname` (из social `relation`, при видимом профиле); `AppearanceCard.custom_avatar_asset_id` (объект жалобы `avatar`, необязателен); `MatchPlayerCard.can_add_friend` — social `/v1/players/relations` пачками `GV_PAGES__RELATIONS_BATCH_SIZE` только для игроков с `can_report`, сбой — `false`; `MyMatchCard.participants` в хабе — итог match на каждый из первых `GV_PAGES__ONLINE_MATCH_PLAYERS_LIMIT` матчей, сбой — `[]`.
- Онлайн, счётчик и комнаты: `OnlineBlocks.online_count` — social `/v1/presence/online-count` (публичный, без токена, общий кэш `GV_PAGE_CACHE__ONLINE_COUNT_TTL_S`, сбой — `unavailable`). Открытые лобби получили `title` (введённое хостом `settings.name` или шаблон `GV_PAGES__ROOM_NAME_TEMPLATE`, по умолчанию «Комната {host}»), `host_id` и `host_level`. `/v1/pages/rooms/{code}` (аккаунт; гость 403, аноним 401; 404 `match.room_not_found`) — match `GET /v1/rooms/{code}` и затем уровни игроков пачками `GV_PAGES__LEVELS_BATCH_SIZE` из progression `/internal/v1/levels` под сервисным токеном bff_web (область `levels.read`, `GV_SERVICE_AUTH__*`, `wiring._progression_tokens`); уровни нужны id игроков из match, поэтому идут после него, сбой progression или отсутствие токена — `level: null`. Токен зрителя в progression не уходит.
- ADR 0071: адрес своей аватарки профиль берёт из progression `/v1/me/appearance` (`custom_avatar_url`), `current_url` из `/v1/me/avatar` не читается (deprecated); блоки `appearance` и `avatar` профиля гаснут независимо.
