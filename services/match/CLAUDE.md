# match

Онлайн: лобби, комнаты, матчмейкинг, конечный автомат матча, таймеры, реконнект, наблюдение.

- Пакет: `match_service`; запуск: `match api|relay|consumer|rooms|all|migrate`
- Карточка сервиса (данные, события, деградация): `docs/architecture/services.md`
- Публичный API: `/api/match/v1/...` на gateway; admin — `/admin/v1/rooms|matches`
- Зависимости: PostgreSQL, Redis, Redpanda, Centrifugo; game (`round-plans`), media-pipeline (`asset-links`)
- Статус: этап 4a — комнаты, кастомные лобби, дуэль, party, realtime, реконнект (`docs/plans/stage-4.md` §5, ADR 0032–0036); 4b — очереди и рейтинговый подбор, наблюдение (ADR 0038)

## Особенности
- Комнаты живут в Redis, владелец — процесс `rooms` (ADR 0034): `api` кладёт команду в `{room:CODE}:cmd` и ждёт ответ в `{room:CODE}:reply:{user}:{op}` ≤ `GV_MATCH__REPLY_TIMEOUT_MS`, иначе 202. Права (участник, хост) проверяет владелец — `application/owner.py`.
- Lease `{room:CODE}:owner = instance|epoch`; снимок пишется только Lua-CAS `Lease.write` с токеном эпохи. Курсор потока хранится в снимке — это и есть подтверждение команд (`XDEL` и ответы — после снимка): команды без снимка новый владелец применит заново.
- Снимок — `infrastructure/rooms/codec.py` со `schema_version`; новое поле — только со значением по умолчанию при чтении, смена смысла — `SCHEMA_VERSION + 1` и шаг `_UPGRADES`; тест читает сохранённый `tests/unit/data/room_snapshot.v1.json`.
- Правила раунда — только фасад ядра `ModeEngine.contest_*` (`application/rules.py`), без `if kind == ...`. Единственное правило по составу — пауза при отключении в матче на двоих (D10). Число раундов не пишется в тело конфига: его задаёт план game.
- Версия комнаты растёт на каждое сообщение канала (без пропусков — фронт ресинкается по пропуску); `phase_version` — версия начала текущей фазы/уровня: `expected_version` старше неё — 409 `match.phase_mismatch`.
- Античит: виды строятся в `application/views.py` из снимка без ядра; план и ключи ответа — только в снимке; `reveal` — только в фазе `reveal`; личное (`me`) — только в ответе команды и `GET /state`. Сценарии обходят JSON рекурсивно (`tests/component/test_scenarios.py`).
- Ссылка уровня — одна на (комната, раунд, уровень): субъект `room:{code}:{round}`, ревил — `…:reveal`; недоступный ассет — раунд `void`.
- Итог — `matches` + `match_players` + `match_rounds` + outbox одной транзакцией, `ON CONFLICT` по `match_id`; флаги `started_written`/`finished_written` в снимке — повтор после handoff безопасен. `match_rounds` партиционирована по месяцу (задача `match.partitions.ensure` в relay).
- Итог пишет runner **после** успешного CAS снимка (`RoomOwner.persist`); пока итог не записан, закрытая комната не отпускается (повтор с паузой, `gv_match_persist_failures_total`). Матч, прерванный до конца отсчёта (`MatchStarted` не было), в Postgres не пишется и `MatchFinished` не публикует. Удалённые аккаунты (`users_proj.deleted` и `Room.forgotten`) в итоге — `00000000-…` без `user_id`.
- Seed плана — `secrets.token_hex(32)` через порт `seeds`, только в снимке. Окно `op_id` — компактное (статус, код, вердикт), только для занятых мест (и добровольного выхода — повтор `leave` даёт тот же ответ), не больше `GV_MATCH__OP_USERS_MAX` игроков; чистится при кике и удалении аккаунта.
- Сбой обработчика не `AppError` откатывает комнату (копия до команды) и пробрасывается: runner перечитывает снимок и повторяет запись. Redis/сеть — повтор без счёта; та же запись упала `GV_MATCH__POISON_LIMIT` раз — 503 `match.unavailable`, команда пропущена. Столько же сбойных тиков подряд — комната прерывается (`internal_error`).
- `player:{id}:room = code|ms` с TTL снимка: занят, если комната по указателю не закрыта и игрок не вышел (или места ещё нет), либо комнаты нет, а указатель свежее `GV_MATCH__PENDING_ROOM_MS`; замена — Lua-CAS (`claim_room`). Итог и `UserDeleted` сериализуются advisory-замком пользователя.
- Свободный чат — только в `lobby`/`reveal`/`summary`; у эмоций свой лимит и `CHAT_SLOW`. Кик/выход/удаление отзывают подписку Centrifugo (`unsubscribe`, сбой — только лог). Админский abort пишется в `admin_actions` (без БД — 503; ключ на другую комнату — 409 `idempotency.key_reused`); в событии — код `admin`. Параллельные `POST /rooms` одного игрока — замок `player:{id}:creating` с токеном (`GV_MATCH__CREATE_LOCK_MS`), до лимита; тот же ключ во время создания — 409 `idempotency.in_progress`.
- Текущая версия шаблона для `POST /rooms` — проекция `mode_heads` из `game.mode_config.v1`, тело — `GET /internal/v1/modes/{key}/versions/{v}` game (кэш без срока).
- Сдача (`forfeit`) — исход матча, не выход: место остаётся, игрок не активен в матче, голосует за реванш. LEFT — только `leave`, выбывание по grace, кик, удаление аккаунта.
- Реванш дуэли/party — новая комната, старая закрывается с `closed {reason: rematch, rematch_code}`; кастомное лобби возвращается в `lobby` с памятью сыгранного. `state`/`tick` читают закрытую комнату, пока жив снимок (`GV_MATCH__CLOSED_TTL_S`).
- Тесты: двойники портов match и сборка сервиса — `tests/support/` (`match_doubles`, `match_harness`, `match_app`, `match_fixtures`); фейки game/media/Centrifugo — `gv_testkit.match`; шаблоны — сиды `seeds/game/modes`.
- Очередь = `(ladder, format)`: Redis `{mmq}:q:<ladder>:<format>` (ZSET по рейтингу) + HASH записи игрока с TTL `GV_MATCH__QUEUE_TTL_S` (heartbeat — `POST /queue/tick`); состояния `searching → reserved → matched` (ZSET по рейтингу, по времени входа — батч берёт старейших первыми, и резервов — зачистка после падения матчера через `GV_MATCH__QUEUE_RESERVED_STALE_S`) (`reserved` клиенту виден как `searching`, пока создаётся комната). Рейтинг, окна и интервалы — только проекция `rating.rating.v1` (`ladders_proj`, `ratings_proj`; порядок по `version`, мягкий сброс по `SeasonStarted.soft_reset` применяет match); новичок — `soft_reset.target`, иначе `GV_MATCH__DEFAULT_START_RATING` (события не несут `elo.start`).
- Матчер (`infrastructure/matchmaker.py`) — runner процесса `rooms` под lease очереди с fencing: пара резервируется Lua-скриптом, проверяющим токен lease (дважды и после потери lease пара не создаётся). Комната рейтинговой дуэли создаётся в `lobby` с обоими игроками (второй готов) и системной командой `start` хоста; шаблон — опубликованная дуэль `session.ranked` + `ladder` с `answer.format` из `domain/queue.FORMAT_ANSWER`.
- Срыв отсчёта рейтинговой комнаты (выход, сдача, отключение до `MatchStarted`, отказ плана game): `RoomOwner._ranked_abort` закрывает комнату, `QueueHooks.aborted` возвращает оставшегося в поиск с прежним `entered_at`; штрафа и записи матча нет. Реванш рейтинговой комнаты запрещён (403 `match.ranked_forbidden`). `queue_format` в `MatchStarted/MatchFinished` — из `answer.format` комнаты.
- Проекция сезона — отдельная `seasons_proj` (SeasonStarted до LadderPublished не теряет `soft_reset`); `LadderPublished` с форматами вне `FORMAT_ANSWER` обрабатывается, но пишет лог/метрику `gv_match_ladder_unknown_formats_total`, а такая очередь отвечает 422; `ladder`/`formats` проверяются по `^[a-z][a-z0-9_]*$` до попадания в ключи Redis; рейтинг удалённого аккаунта игнорируется (общий advisory-замок пользователя), `UserDeleted` снимает запись из очереди.
- Откат подбора: код комнаты хранится в `_Attempt` (меняется при коллизии), созданная, но не запущенная комната убирается `RoomStore.discard`; `leave` в `reserved` — 409 `match.queue_matching`; срыв отсчёта считается логом `match.ranked_countdown_dropped` (для детектора этапа 5).
- Санкции (ADR 0052, миграция `0004`): проекция `sanctions_proj` из `social.UserSanctionsChanged`; эффективная маска — проекция, если запись есть, иначе claim (`application/sanctions.py`, `effective_actor`/`require_online`). `ONLINE` → 403 `match.online_banned` на `POST /rooms`, `join`, `rematch`, очередь `enter/tick`, `realtime-token` (продление токена перепроверяет). По событию игрок снимается с очереди и покидает комнату системной командой `evict` (без забвения, в отличие от `remove`); `unsubscribe` Centrifugo — до `GV_MATCH__UNSUBSCRIBE_ATTEMPTS` попыток, метрика `gv_match_unsubscribe_failed_total`.
- Наблюдение (`match.spectate`): список идущих матчей, `state` и `realtime-token` без участия в комнате — только чтение, `me` пуст, лобби и итоги не показываются; лимит `GV_MATCH__SPECTATE_PER_USER_PER_MIN` (список, `state` и токен наблюдателя); подписки наблюдателей отзываются владельцем при `summary`/`closed` (`RedisSpectators`).
- Disconnect Centrifugo (ADR 0059): `account_banned` в `social.UserSanctionsChanged` → `disconnect` без переподключения (код 3500) + `evict`; кик → `disconnect` с переподключением (3000). Бан-отзыв идёт синхронно через `DirectRevoker`, мимо очереди (потерять нельзя, повтор события невозможен). Ключ server API только у match, не у identity; метрика `gv_match_disconnect_failed_total`, сбой — только лог. Остаточный риск: выданные токены живут до TTL.
- Чтение команд — один общий `XREAD` на инстанс (`infrastructure/rooms/reader.py`, ADR 0063): курсоры в памяти, откат курсора актёра очищает ящик; многоключевой `XREAD` — только Redis без кластера. Сбой цикла читателя (не только Redis) — ERROR, `gv_match_command_reader_errors_total`, повтор с паузой до `GV_MATCH__COMMAND_READER_BACKOFF_MAX_S`. Лобби, где никто не онлайн дольше `GV_MATCH__EMPTY_LOBBY_CLOSE_S`, закрывает владелец локально (`empty_timeout`, шина не нужна).
- Отзыв Centrifugo при кике/выходе (`unsubscribe`/`disconnect`) идёт через `RevocationQueue` (воркеры `GV_MATCH__REVOCATION_*`, переполнение — `gv_match_revocation_dropped_total`, SIGTERM — слив с таймаутом). Лаг проекции санкций — `gv_match_sanctions_projection_*_lag_seconds`; алерты — `infra/observability/prometheus/rules/match.yml`, runbook — `docs/07-infrastructure.md` §6.1.
- Название комнаты: `RoomSettings.name` (необязательное, `POST /rooms` → `name`; нет в `SettingsOverride`, после создания не меняется, реванш копирует настройки). Проверка — `gv_text.ugc` (без ссылок, denylist) в `RoomService._room_name`, предел длины `GV_MATCH__ROOM_NAME_MAX_LENGTH` (40, схема ≤ 100), отказ — 422 `match.room_name_rejected` (`details.reason`). В снимке — `settings.name`, читается `s.get("name")` без bump `SCHEMA_VERSION` (тест `test_codec.py`, сохранённый `room_snapshot.v1.json` не менялся). Фразу «Комната <ник хоста>» собирает bff. `OpenRoomCard.host_id` — для уровня хоста в bff; уровни игроков match не хранит. Realtime-схема не менялась: дельты несут только игроков и фазу, не настройки.
- `clue_type`/`answer_format` лобби (ADR 0070): `apply_settings` — только из `template.options`, отличия от шаблона уходят в `round-plans.overrides`; отказ game → 422 `match.setting_not_allowed` (`reason` `not_allowed|incompatible`), комната остаётся в лобби.
- Картинка ответа в ревиле (ADR 0073): `PlannedRound.artwork_asset_set_id` (необязательно; старый game без поля — `None`) → при переходе в `reveal` `_resolve` выдаёт вторую ссылку (субъект `room:{code}:{round}:reveal`, уровень 1) в `MatchState.artwork`; сбой любого рода — `null`, ревил цел. До `reveal` картинка нигде не выдаётся. Ссылка короткая, поэтому владелец на тике перевыдаёт её за `GV_MATCH__ARTWORK_REFRESH_MARGIN_S` до истечения (`_refresh_artwork`); читающий путь в media не ходит. Поле в снимке — с дефолтом `None`, `SCHEMA_VERSION` не менялся.
- Позиция прослушивания (`POST /rooms/{code}/listen`, команда `listen`): `Seat.listen_s` (целые секунды, зажато в `meta.seconds` уровня или окно уровня), сообщение `player` и `players[].listen_s`; сбрасывается в `Room.set_phase`. Эфемерна, ответа не раскрывает; пишется в снимок с дефолтом `None` (без bump `SCHEMA_VERSION`). Свой лимит `GV_MATCH__LISTEN_PER_PLAYER_PER_MIN` (429), `op_id` команды не занимает окно (`UNREMEMBERED_KINDS`), повтор значения и устаревший `level` — 200 без сообщения, не в `level_open` — 409 `match.phase_mismatch`.
