# social

Друзья, комментарии, жалобы, модерация, шкалы поведения и санкции, приватность.

- Пакет: `social_service`; запуск: `social api|relay|consumer|worker|all|migrate`
- Карточка сервиса (данные, события, деградация): `docs/architecture/services.md`
- Публичный API: `/api/social/v1/...` на gateway; admin — `/admin/v1/cases|users|sanctions`
- Зависимости: PostgreSQL, Redis (presence, лимиты), Redpanda
- Статус: этап 5c, шаг 0a — контракты и заглушки 501 (`docs/plans/stage-5.md` §10.1, ADR 0050–0053); домен — потоки F1–F4

## Особенности
- События `social.social.v1` — `contracts/events/social/`; конфиг (лимиты, причины жалоб, пределы санкций) — в БД версиями (`config_versions`, ADR 0053; схема тела `contracts/social/social_config.v1.json`; bootstrap local/ci из `seeds/social/config.yaml`), значений в коде нет.
- Схемы API — `api/schemas.py`; ручки друзей — `api/public/friends.py` (F1), комментарии/жалобы/свои санкции — `api/public/discussion.py` (F2, F3), админка — `api/admin/__init__.py` (F3, F4).
- Настройка приватности `friend_requests = all|none` — «кто может звать в друзья»; скрытый профиль, блокировка и неизвестный игрок отвечают одинаково (нет перечисления).
- Текст жалоб и комментариев в события не попадает; жалоба идемпотентна по `(автор, объект)`; порог за сутки открывает кейс ровно один раз.
- Санкции: `UserSanctionsChanged` несёт полное активное состояние и `version`; `ACCOUNT` — флаг `account_banned`, не бит claim. Модератор не санкционирует себя. Права: `social.moderate`, `social.comments.delete_any`, `social.sanctions.manage`, `social.sanctions.account`, `social.config.manage`, `social.config.publish`.
- F1 (друзья, миграция `0002`): пара `user_a < user_b`; операции пары идут под `pg_advisory_xact_lock` (сначала игроки по возрастанию, затем пара) — гонки accept и встречных заявок дают одну дружбу. Идемпотентность — `idempotency_keys` (`gv_db`), ответ в той же транзакции. Один 404 `social.player_not_found` для неизвестного/скрывшего заявки/заблокировавшего. Присутствие и лимиты — Redis (`social:presence:*`, `social:limit:*`, fail-closed 503). Ник отправителя берётся из `users_proj`; нет проекции — 503 `social.profile_not_ready`.
- Конфиг: `config_versions` (черновик/действующая), `DbConfigProvider` с кэшем `GV_SOCIAL__CONFIG_CACHE_TTL_S`; нет версии/БД — 503 `social.config_unavailable`. Копия схемы — `config/social_config.schema.json` (равенство сверяет contract-тест). Bootstrap — `GV_SOCIAL__BOOTSTRAP_CONFIG_DIR` (только local/ci). Use-cases версий для admin-API — `application/config_admin.py` (`on_change` — хук аудита в той же транзакции).
- События F1 публикуются с `aggregate_type = "social"` (топик `social.social.v1`). `UserDeleted`/`MatchFinished` слушают и друзья, и модерация: `register_friends_handlers(..., include_shared=False)` + `SharedHandlers`.
- F4 (кейсы, миграция `0005`): `domain/cases.py` — переходы `open → in_work → escalated → resolved` и оптимистичная блокировка по `version` (409 `case_version_conflict`); «старший» (решает эскалированные) — обладатель `social.sanctions.account`. `application/cases.py`: claim/escalate/resolve — одна транзакция (кейс `FOR UPDATE`, контент, `SanctionGranter` через `GranterFactory(uow)`, аудит в `moderation_audit`, outbox `ContentModerated` + `ReportResolved` по жалобе, без текстов). Реализацию санкций/читателя подставляет `Adapters.sanctions|granter_factory` (по умолчанию заглушки `infrastructure/sanction_stubs.py`). Аватарки: проекция `avatar_proj` из `media_pipeline.AssetModerated` (жалоба на неизвестный/отклонённый ассет — 404 `report_target_not_found`). Комментарии: блокировка закрывает POST/PATCH в обе стороны (403 `social.blocked`), `CHAT` — по `claim | SanctionReader.active_mask`. Админ-ручки конфига пишут аудит через `on_change` (`moderation_audit`, `config:<версия>`), публикация сбрасывает кэш провайдера в процессе.
- Шкала порядочности — только счётчики для модератора (из `MatchFinished.players[].finish`, `PlayerRated`), автосанкций нет.
- Санкции (F3, миграция `0004`): `sanctions` (история; одна не снятая запись на `(игрок, вид)` — новая выдача закрывает прежнюю как `replaced`, истёкшую — `expired`) и `sanction_state.version` (инкремент под блокировкой строки в транзакции изменения → монотонность при гонках). `SanctionService` (`application/sanctions.py`) реализует `SanctionGranter`/`SanctionReader`; `container.sanctions(session=None)` в чужой транзакции работает через SAVEPOINT. Событие `UserSanctionsChanged` — в той же транзакции; задача relay `social.sanctions.expire` (`GV_SOCIAL__SANCTION_EXPIRY_INTERVAL_S`) закрывает истёкшие (`changed_by = null`). Ручки — `api/admin/sanctions.py`; `account` — только с `social.sanctions.account`; приглашение при ONLINE — claim | таблица `sanctions`.
