# game

Соло-движок: сессии, раунды, ответы, очки; реестр плагинов загадок; конфиги режимов (соло и онлайн); дейлик, больше/меньше, топ-32; план раундов матча для match.

- Пакет: `game_service`; запуск: `game api|relay|consumer|worker|all|migrate`
- Карточка сервиса (данные, события, деградация): `docs/architecture/services.md`
- Публичный API: `/api/game/v1/...` на gateway; admin — `/admin/v1/mode-configs|daily-sets|projection`
- Зависимости: PostgreSQL, Redis, Redpanda; `gv_game_kernel` (правила), `gv_text` (нормализация)
- Статус: этап 4a — онлайн-конфиги и план раундов матча (`docs/plans/stage-4.md` §6, ADR 0032, 0033); этап 3b — игра по сборнику (`docs/plans/stage-3b.md` §7, ADR 0028, 0029); этап 3a — марафон, «больше/меньше», сетка топ-32, ревил другим типом, рекорды, запрос ассетов (`docs/plans/stage-3a.md` §5); этап 2 — конфиги, дейлик, соло-сессии, проекции

## Особенности
- Картинка ответа (ADR 0073): `Reveal.artwork {url, expires_at, mime}` или `null`. Профиль `artwork` по домену — `GV_GAME__ARTWORK_PROFILES` (по умолчанию как в `asset_profiles.yaml` media; `tests/contract/test_artwork_profiles.py` сверяет с golden); `ArtworkProfiles` даёт `params_hash` домена, при материализации раунда набор ищется в проекции `clue_assets` (каталожный, без `scope`), ref кладётся в `Round.artwork_asset` (необязательное поле JSON раунда, у старых снимков `None`, DDL нет). Ссылку на ревиле выдаёт `SessionPresenter.artwork` через `AssetPort.link` (уровень 1, кэш с тегом `artwork`); `GoneError`/`DependencyUnavailableError`/`RateLimitedError` → `artwork: null`, ревил цел. До завершения раунда картинка не выдаётся. Онлайн-ревил (match) пока без artwork (`docs/backlog.md`).
- Контракт API зафиксирован в 0a (§2.6 плана): схемы — `api/public/schemas.py`, `api/admin/schemas.py`; правка схемы = правка `contracts/openapi/game.json` (`gv contracts export`).
- Правила игры — только в `libs/game_kernel` (плагины, `ModeEngine`); game оркестрирует, без `if type == ...`.
- Конфиг режима: контракт `contracts/modes/mode_config.v1.json`, модели — `gv_game_kernel.spec` (меняет только шаг 0); сиды — `seeds/game/modes/*.yaml`.
- Ассеты ищутся по `(media_item_id, clue_type, params_hash(clue.params))` из `AssetsReady` (D7); очки уровней — в `scoring.params.points`.
- Античит (D11): до ревила в ответах нет `media_item_id`, названия, `asset_set_id`; ассет — только уровня ≤ текущего; чужая сессия — 404.
- Сессии — в Postgres (D12): ход = строка под `FOR UPDATE` + `expected_version` + `Idempotency-Key` + outbox в одной транзакции; вызов media-pipeline — вне транзакции.
- Возможности режима — у ядра (`application/rules.py`): протоколы источника (`RoundSource`, `ProgressiveSource`, `SubjectSource`, `PeriodSource`), `presentation`, `reveal_playable_for`; из параметров — только общие поля периода (`timezone`, `schedule_ahead_*`, `exclude_recent_days`, `period`). Слой api получает use-cases через `ApiServices` (сборка — `main.py`).
- Раунды выдаются лениво (D4): план — в `state.plan` (скрыт), после каждого раунда `_settle` спрашивает `should_end`/`followups` и выдаёт следующий; в снимке невыданные раунды — пустые `pending`. `state_schema` 2, без поля — v1 этапа 2 (`tests/unit/test_state_schema.py`).
- Набор дня = набор периода (`daily_sets.period`, `day` — начало периода по `period_start` ядра, тема сетки — `subject_id`); одна попытка на период. Сетка публикует `BracketCompleted` вместо `GameFinished`.
- Рекорды/гистограмма (`features.records`) и статистика выбора сетки — в транзакции хода, только пользователи. Ревил другим типом: единица играбельна при обоих наборах (`uow.candidates_for(reveal)`).
- Кэш конфигов: в процессе (TTL) + поколение `game:modes:gen` в Redis; версии неизменяемы. Ссылки ревила кэшируются в процессе до истечения.
- Тесты идут на реальных плагинах ядра (`build_registry()` → `register_builtin`); фильтры SQL-адаптера `CandidatePort` обязаны совпадать с `gv_testkit.game.FakeCandidatePort.matches` (`tests/integration/test_candidates.py`).
- 409 `game.desync`: `details = {"session": SessionSnapshot}`; после 401 от media-pipeline кэш сервисного токена сбрасывается (`TokenProvider.invalidate`).
- Параметр пути admin-ручек — `{mode_key}`: имя `key` конфликтует с параметром зависимости `Idempotency-Key`.
- Периодические задачи (наборы дня, брошенные сессии) — `ServiceDefinition.build_periodic_jobs`, выполняются в relay под advisory lock; должны быть идемпотентными.
- Сборники (3b): проекция `collection_proj`/`collection_items_proj` из `collections.collection.v1` (снимок по общей `version`, удалённый — надгробие); адаптер `SqlCollectionPort` обязан совпадать с `FakeCollectionPort.matches` (`tests/integration/test_collections.py`). Сессия фиксирует `collection_id` и `content_version` в `state.collection` и доигрывается после скрытия. Наборы со `scope_id` (свои эмодзи) — только в сессии своего сборника и первыми; удаляет их game сам по снимку (событий удаления от media нет). Шаблоны `*.collection.*` не входят в `GET /v1/modes` (по умолчанию `kind=play`); их отдаёт `GET /v1/modes?kind=collection` (с `round_options`/`min_items` конфига), играбельность сборника — `GET /v1/collections/{id}/modes`.
- Онлайн-режимы (4a, ADR 0032): конфиги `duel|party|lobby` game проверяет (`RulesFactory`, `SUPPORTED_SESSIONS`) и публикует тем же путём, что соло, но не играет: старт соло-сессии — 422 `game.mode_not_solo` до лимитов и транзакции. `ModeCatalog.published()` по умолчанию — только соло (каталог, дейлики, режимы сборника); онлайн — `published(online=True)` и `GET /v1/modes?session=online` (блок `online`).
- Internal API для match (ADR 0033, `api/internal`, `application/queries/round_plans.py`): только сервисный токен со scope `rounds.plan`. `POST /internal/v1/round-plans` — `draw_rounds` с `seed` (детерминизм), `exclude_ids`, `collection_ids` (проекция `collection_proj`, как соло), ключи ответа, `asset_set_id` по уровням и ревилу, `options`; только онлайн-режимам (`game.mode_not_online`). Ключи ответа, `media_item_id` и названия не пишутся в логи и ошибки.
- Формат `lite` (4b, ADR 0040): `answer.params.distractors` — варианты `pick` строит ядро (`ModeEngine.draw_rounds`), `round-plans` отдаёт их в `options`; недостаток кандидатов — 422 `game.pool_too_small`. Валидация конфига: только с `pick`, `min_pool ≥ count + 1`; `min_playable` публикации не меньше `count + 1`.
- Ladder-ы (4b, ADR 0037): проекция ключей `ladders_proj` из `rating.LadderPublished` (inbox, порядок по `version`, миграция `0006`); `ValidateModeConfig` сверяет `session.ladder` с ней (`config.ladder_unknown`, `config.ladder_domain_mismatch`). Bootstrap сидов проверяет ladder мягко (предупреждение): событие rating может прийти позже старта game. Шаблоны очередей — сиды `*.ranked.{classic,lite}`, `*.duel.lite`.
- Поиск `title ILIKE` админки проекции (`/admin/v1/projection/items`) обслуживает GIN `gin_trgm_ops` `ix_catalog_items_title_trgm` (миграция `0007`, `CONCURRENTLY`; нет расширения `pg_trgm` — индекс пропускается, поиск медленнее). Поиск персон по имени (`subjects`) индексом не покрыт, лимит ≤ 20.
- Теги сборника (ADR 0067): `collection_proj.tags` (миграция `0008`) из необязательного `tags` событий collections; сессия фиксирует их на старте (`state.collection.tags`), `GameFinished.collection_tags` — необязательный массив.
- Переопределения лобби в плане (ADR 0070): `round-plans.overrides {clue_type, answer_format}` — допустимость из `session.lobby.overridable` (`gv_game_kernel.apply_lobby_overrides`), эффективный конфиг проходит `RulesFactory.check`, пул — под переопределённую загадку; отказ 422 `game.override_not_allowed` / `game.override_invalid`.
- Ссылка ревила/`final-clue` (ADR 0012): срок — `expires_at` ответа, TTL задаёт media-pipeline (`GV_MEDIA__LINK_TTL_S`, по умолчанию 60 с, ≤ 3600); кэш ссылок в game — до `expires_at` минус `GV_GAME__REVEAL_LINK_MARGIN_S`. Фронтенд обновляет ссылку по `expires_at` (один `final-clue` за показ), константы 60 с в клиенте нет.
- Результаты дейлика игроков (PR-A «дейлик и итоги»): `GET /v1/daily/results?user_ids=&domain=` — завершённые попытки ТЕКУЩЕГО периода режимов с Source из `GV_GAME__DAILY_RESULTS_SOURCE_TYPES` (по умолчанию `daily`), только `score`/`max_score`, из своей `game_sessions` одним запросом по индексу попытки дня (без проекции и N+1). Авторизация: пользовательский токен (гость — 403), потолок игроков `GV_GAME__DAILY_RESULTS_MAX_USERS` (50; 422 `game.too_many_users`; схема — 100), лимит `GV_GAME_LIMITS__DAILY_RESULTS_PER_MIN` (60). game дружбы и приватности не знает: кому показывать чужие очки, решает bff по данным social — остаточный риск: известный `user_id` даёт очки сегодняшнего дейлика (решение владельца: при необходимости перейти на сервисный токен bff, см. описание PR). `SessionResult` получил необязательные `mode_key`, `domain`, `day`, `daily`.
